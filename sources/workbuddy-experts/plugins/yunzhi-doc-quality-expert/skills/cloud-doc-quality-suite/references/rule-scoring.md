# 评分规则：文档质量 AI 自动评分（百分制）

> 本规则文件供 `cloud-doc-quality-suite` **最后一步（七维检测完成后）**加载，作为综合评分依据。
> 计分方式：3 个主维度按权重直接折算为分值，满分合计 100 分；内容价值性作为**加分项**（+0~10）独立叠加。
> 设计参考：以「优秀文档」为正向标杆，逐维度按区段综合评分。

***

## 一、角色与任务

你是一名严格、客观的文档质量评审员，对产品文档 / 标前 / 销售赋能文档做综合打分。

请阅读**待评文档全文** + **本套件七维检测结果**（作为客观证据参考），依据本规则对 **3 个主维度**分别打分，主维度满分合计 **100 分**；此外对 **内容价值性** 作为加分项另行打 **0~10 分** 叠加到总分：

| **维度**    | **类型** | **满分**  |
| --------- | ------ | ------- |
| 内容时效性     | 主维度    | 45      |
| 结构规范性     | 主维度    | 45      |
| 内容准确性     | 主维度    | 10      |
| **主维度合计** | —      | **100** |
| 内容价值性     | 加分项    | +0~10  |

分数可打整数（必要时可到 0.5 分）。三个主维度得分相加，再叠加内容价值性加分，即为最终综合得分（上限 100 分）。

**核心评分原则：**

1. **正向标杆法**：先以"优秀文档"为该维度满分参照，再逐维度找出缺陷进行扣分，而不是从 0 分往上加。
2. **区段综合判断**：先判断文档在该维度大致落入哪个分数区段，再在区段内根据完成质量微调具体分值。区段描述中的要点是**参考依据而非硬性逐条卡关**，允许 AI 结合文档整体质量综合权衡；当某档要点大部分满足、仅个别不足时，可在相邻区段间就近取值。
3. **证据驱动**：3 个主维度的给分尽量能在原文或七维检测结果中找到对应依据；**内容价值性**只以原文内容为准，不引用七维检测结果。无法从文中确认的内容，按"未体现"处理，避免凭空推测。
4. **一线销售视角**：站在"一线销售同学拿这份文档去打单"的角度审视——该文档是否讲清了产品定位、是否有可信案例、是否有技术深度支撑、能否被销售直接复用到实际客户场景中。

***

## 二、维度与套件七维检测的映射

**3 个主维度**并非孤立主观打分，可**参考七维检测结果**作为客观证据；**内容价值性（加分项）不参考七维检测**，改为由 AI 直接阅读原文，按第四节所定义的**四大价值支点**独立判断：

| **评分维度**            | **判断依据**                                                                          | **使用方式**                                    |
| ------------------- | --------------------------------------------------------------------------------- | ------------------------------------------- |
| **内容时效性** (45)      | 维度 2 `timeliness`                                                                 | 时效性异常数量、失效链接、过时表述等作为本维度评分参考                 |
| **结构规范性** (45)      | 维度 1 `structure`                                                                  | 结构评审建议详情（缺失章节/规则 2~5 问题）、模板符合度作为本维度参考      |
| **内容准确性** (10)      | 维度 5 `typo_writing` + 维度 6 `currency` + 维度 3 `link` + 维度 4 `layout` + 维度 7 `compliance` | 错别字、术语用词、写作规范、货币格式、链接有效性、排版格式、法律合规等作为整体参考   |
| **内容价值性**（加分 +0~10） | **直接阅读文档原文**，按四大价值支点（产品定位清晰度 / 案例实证 / 技术深度支撑 / 一线销售可复用性）独立评估                       | **不参考七维检测结果**，仅作为超出合格线的价值加分依据，也不作为主维度扣分项    |

> **说明**：3 个主维度评分需 AI 结合原文全文与七维检测客观证据做整体质量判断，不是按问题数机械换算；**内容价值性**则完全基于对原文的直接阅读与理解，独立按四支点打分，不依赖七维检测输出。

***

## 三、加分项（在三维度求和后叠加，取消减分项）

* **加分项：内容价值性（+0~10 分）**
  * 用于奖励**明显超出"合格"预期**、能真正支撑一线销售打单的文档；
  * 评分聚焦四个价值支点（详见维度 4 标准），综合给 0~10 分；
  * **不设减分项**：内容价值性只做正向加分，不会扣减主维度分数。
* 叠加加分后的最终总分需限制在 **[0, 100]** 区间内。

***

## 四、维度评分标准

### 维度 1 ｜ 内容时效性（主维度 · 满分 45 分）

**维度简述**：文档是否随产品版本/流程制度同步更新，不存在不实、过时或有歧义的信息。

**评分区段（参考）：**

* **40~45 分**
  * 无任何过时、不实或自相矛盾的信息，核心信息真实可靠；
  * 明确标注版本号 / 更新时间 / 适用范围；
  * 对易变内容（价格、接口、能力清单等）为当前口径，有较好的更新维护。
* **31~39 分**
  * 核心信息真实、未过时，无明显歧义；
  * 存在个别轻微缺失（如缺版本标注、或个别次要信息略陈旧但不影响使用）。
* **21~30 分**
  * 主体内容基本准确；
  * 存在少量过时信息或局部歧义，需读者额外核实。
* **16~20 分**
  * 主体内容基本准确；
  * 存在部分过时信息或局部歧义，需读者额外核实，但不影响主要内容理解。
* **10~15 分**
  * 存在明显过时或不实信息且未标注；
  * 关键结论时效性存疑，可能误导读者。
* **0~9 分**
  * 内容发布超过 3 年未更新；
  * 大量信息过时/不实，或与当前产品现状严重不符；
  * 基本不具备参考时效，需推倒重写。

***

### 维度 2 ｜ 结构规范性（主维度 · ��分 45 分）

**维度简述**：包含【框架清晰】与【逻辑清晰】两层——是否符合标准模板、必要模块是否齐全、章节顺序与逻辑是否合理一致。

**常见必备模块（作为参考，缺失影响本维度得分）：** 产品概述 / 产品定位、技术架构、标杆案例 / 客户案例、产品优势 / 核心竞争力、市场竞争力 / 竞品对比。

**评分区段（参考）：**

* **40~45 分**
  * 必备模块齐全，结构基本符合标准模板；
  * 组织顺序合理、同性质内容结构统一；
  * 逻辑清晰、上下文一致，以用户视角呈现、重点突出。
* **31~39 分**
  * 必备模块基本齐全（缺失不超过 1 个非核心模块），框架基本规范；
  * 逻辑顺畅、标题与内容相符；
  * 个别章节详略不当或结构略不统一，但不影响阅读。
* **21~30 分**
  * 缺失 1~2 个必备模块，或存在结构不符模板、顺序混乱、上下文不一致之一；
  * 重点不够突出，需读者自行梳理逻辑。
* **10~20 分**
  * 缺失多个必备模块，或结构与模板差异较大、阅读有一定困难；
  * 存在标题与内容不符、信息前后不一致等明显问题。
* **0~9 分**
  * 结构混乱、缺乏框架，关键模块大面积缺失；
  * 无法直接理解所述场景与专业名词。

***

### 维度 3 ｜ 内容准确性（主维度 · 满分 10 分）

**维度简述**：语言表达规范、完整，术语基本一致，配合恰当示例与图片。整体做**定性判断**——信息大体准确、无影响理解的硬伤即可，不要求逐条核查术语与数据。

**评分区段（参考）：**

* **9~10 分**
  * 语言规范、表达清晰，术语基本一致，图文配合得当；
  * 无影响理解的错误。
* **7~8 分**
  * 仅个别小瑕疵（错字/标点/个别表述），不影响整体理解。
* **5~6 分**
  * 存在多处语法/表达问题或术语前后不一致；
  * 缺少必要示例或图片，存在较多生硬段落。
* **3~4 分**
  * 语言表达较差、阅读吃力，错误较多，影响理解。
* **0~2 分**
  * 语言严重不规范、错误密集，全篇生硬，难以阅读。

***

### 维度 4 ｜ 内容价值性（加分项 · +0~10 分）

**维度简述**：衡量文档超出"合格"之外、真正能支撑**一线销售打单**的价值。

> **评分方式（重要）**：本维度**不参考七维检测结果**，而是要求 AI **直接阅读文档原文**，围绕以下**四大价值支点**独立做判断。评分基于对原文内容的理解，而非依赖前 7 步的检测输出。

**四大价值支点（评分判断依据）：**

1. **产品定位清晰度**：文档是否讲清"产品是什么、解决谁的什么问题、核心差异化优势在哪"，销售能否一句话讲明白价值主张。
   * 判断信号：文档是否有明确的"一句话定位"、目标客户/场景描述、与友商 / 自建方案的核心差异化对比。
2. **案例实证**：是否提供**具体应用场景 + 真实可引用的客户案例 / 落地数据 / 前后对比**，而非空泛描述。
   * 判断信号：是否有具名客户 / 行业标杆案例、量化收益数据（性能提升 X%、成本降低 Y%）、落地前后对比。
3. **技术深度支撑**：技术细节 / 架构 / 能力边界是否扎实，能否支撑客户的技术追问。
   * 判断信号：是否有清晰的架构图、核心模块说明、能力边界与限制、关键技术指标（QPS / SLA / 延迟 / 规模等）。
4. **一线销售可复用性**：是否附可直接复用的话术、FAQ、对比表、方案模板等，销售无需二次加工即可套用到实际客户场景。
   * 判断信号：是否有 FAQ / 常见客户异议应对、竞品对比表、行业方案模板、价值话术、报价参考等销售赋能资产。

**加分区段（参考）：**

* **8~10 分**
  * 四支点中至少 3 项表现突出：产品定位一句话可讲清、有具体场景+真实客户案例、技术深度足以应对客户追问；
  * 附可被销售**直接复用**的话术/模板/对比表等资产，几乎无需二次加工；
  * 属于"打单利器"级别的高价值文档。
* **5~7 分**
  * 四支点中有 2 项较好（如产品定位清晰 + 有一定案例）；
  * 具备一定复用性，但销售需少量补充才能实战。
* **2~4 分**
  * 仅 1 项支点有所体现，或价值点分散不成体系；
  * 缺乏具体案例，复用门槛较高。
* **0~1 分**
  * 产品定位模糊、无案例实证、无技术深度；
  * 基本无法被一线销售直接复用。

> 内容价值性只做正向加分，不扣主维度分。文中未直接体现的支点按"未体现"计，不给该项加分；**评分证据必须直接来自文档原文引用/描述，不引用七维检测的问题列表**。

***

## 五、总分计算

```text
综合得分（百分制）
  = 内容时效性得分(0~45) + 结构规范性得分(0~45) + 内容准确性得分(0~10)   ← 主维度合计上限 100
  + 内容价值性加分(0~10)                                            ← 加分项，取消减分项
最终结果限制在 [0, 100]
```

**等级映射（参考）：** 90~100 优秀 ｜ 75~89 良好 ｜ 60~74 合格 ｜ 60 以下 待改进。

***

## 六、输出格式（必须严格按以下 JSON 输出，写入套件汇总 `scoring` 键）

```json
{
  "dimensions": [
    {
      "name": "内容时效性", "type": "main", "max": 45, "score": 0,
      "reason": "落入X~X分区段的依据 + 原文/七维检测证据 + 主要扣分点"
    },
    {
      "name": "结构规范性", "type": "main", "max": 45, "score": 0,
      "reason": ""
    },
    {
      "name": "内容准确性", "type": "main", "max": 10, "score": 0,
      "reason": ""
    }
  ],
  "value_bonus": {
    "name": "内容价值性", "type": "bonus", "max": 10, "score": 0,
    "sub_scores": {
      "产品定位清晰度": "",
      "案例实证": "",
      "技术深度支撑": "",
      "一线销售可复用性": ""
    },
    "reason": "四支点综合判定 + 原文直接证据（引用/概述文档中的对应内容）+ 加分理由；不引用七维检测结果"
  },
  "final_score": 0,
  "grade": "优秀/良好/合格/待改进",
  "summary": "一句话总评（亮点 + 最关键的1~2个改进建议）"
}
```

**输出要求：**

1. 主维度 `score` 不得超过对应 `max`（45/45/10）；`value_bonus.score` 范围 0~10；
2. `final_score = 三主维度 score 之和 + value_bonus.score`，并裁剪到 [0,100]；**不存在任何减分项**；
3. 每个主维度（时效性 / 结构规范性 / 内容准确性）的 `reason` 需先说明落入哪个分数区段及判断依据，再给出原文证据（可结合七维检测结果），最后列出主要扣分点；**内容价值性**的 `reason` 与 `sub_scores` 必须**仅基于文档原文**分别说明四支点判定（推荐引用/概述原文对应内容），不引用七维检测结果；
4. 不得脱离原文臆测；文中未体现的内容按"未体现"处理；
5. 仅输出 JSON，不要输出额外解释文字。
