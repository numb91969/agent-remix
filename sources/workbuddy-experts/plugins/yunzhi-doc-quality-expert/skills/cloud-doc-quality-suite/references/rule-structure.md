# 规则 1：文档结构质量评审

## 目的

基于预定义的文档模板和范本，严格评估目标文档在**结构完整性、产品定位清晰度、场景化价值传递、案例实证充分性、技术细节深度**等维度的质量：结构不完整时具体说明缺失部分及修改建议，结构完整时不再输出建议详情。

## 适用文档类型

> 全部模板均为腾讯云售前弹药库官方模板，统一存放于 `assets/templates/` 目录，
> 格式涵盖 `.docx` / `.pptx` / `.xlsx`，AI 应使用对应的文档解析能力读取模板的章节/页面标题。

| 类型 | 模板文件 | 格式 | 适用场景 |
|------|----------|------|----------|
| 产品白皮书 | `assets/templates/产品白皮书_模板.docx` | DOCX | 产品/技术白皮书 |
| 案例集 | `assets/templates/案例集_模板.pptx` | PPTX | 客户成功案例集、行业案例汇编 |
| 产品解决方案 | `assets/templates/产品解决方案_模板.pptx` | PPTX | 行业/场景化解决方案 |
| 产品介绍 | `assets/templates/产品介绍_模板.pptx` | PPTX | 产品介绍、产品手册（PPT 版） |
| 产品彩页 | `assets/templates/产品彩页_模板.pptx` | PPTX | 产品彩页、单页营销物料 |
| 竞品分析 | `assets/templates/竞品分析_模板.pptx` | PPTX | 竞品对比分析、市场竞争态势 |
| 快速入门 | `assets/templates/快速入门_模板.docx` | DOCX | 产品快速上手指南、Getting Started |
| 销售一指禅 | `assets/templates/销售一指禅_模板.docx` | DOCX | 销售一指禅、销售话术手册 |
| 交付标准流程 | `assets/templates/交付标准流程_模板.docx` | DOCX | 产品交付流程、实施 SOP |
| POC 测试申请指引 | `assets/templates/POC测试申请指引_模板.docx` | DOCX | POC 测试申请、技术验证指引 |
| 产品报价指引 | `assets/templates/产品报价指引.xlsx` | XLSX | 产品报价表、商务报价模板 |

> **注**：本维度仅覆盖上述 11 种官方模板类型，不设置默认兜底模板。若目标文档无法归入任一类型，则跳过本维度检测（详见下文「类型不明时的处理」）。

### 文档类型自动识别

AI 应按以下优先级识别目标文档类型并匹配模板：

1. **文件名关键词匹配**：从用户文件名提取「白皮书 / 案例集 / 解决方案 / 产品介绍 / 彩页 / 竞品分析 / 快速入门 / 销售一指禅 / 交付 / POC / 报价」等关键词
2. **扩展名辅助**：`.xlsx` → 产品报价指引；`.pptx` → 优先匹配 PPT 类模板；`.docx` → 优先匹配 Word 类模板
3. **正文/封面标题语义匹配**：从目标文档的封面、首页或一级标题提取关键词再行匹配
4. **类型不明时**：以上均无法判定时，**跳过本维度检测**，不做兜底处理，不强行套用任何模板

### 类型不明时的处理

- **不做兜底**：不再回退到「产品白皮书_模板.docx」或任何默认模板
- **跳过维度**：`Step 2 加载模板` 与 `Step 3 执行五项评审规则` 全部跳过，不产生结构对比结果
- **输出规范**：
  - `综合建议` 说明「目标文档类型无法归入 11 种官方模板类型，已跳过结构质量评审维度」
  - `建议详情` 返回 `[]`
- **不影响其他维度**：其余七个维度（时效性 / 超链接 / 排版 / 文本低错 / 货币 / 法律合规 / 写作规范）不受影响，正常执行

## 工作流程

### Step 1：识别文档属性

- **文档类型**：产品白皮书 / 案例集 / 产品解决方案 / 产品介绍 / 产品彩页 / 竞品分析 / 快速入门 / 销售一指禅 / 交付标准流程 / POC 测试申请指引 / 产品报价指引（**若无法归入以上任一类型 → 跳过本维度检测**，不做兜底）
- **语言版本**：国内（中文） / 海外（英文）
- **产品类型**：SaaS 类（腾讯乐享、腾讯会议、腾讯电子签、腾讯问卷等） / 非 SaaS 类

### Step 2：加载模板

根据文档类型从 `assets/templates/` 加载对应模板文件（`.docx` / `.pptx` / `.xlsx`），并使用对应解析能力提取核心章节/页面标题，用于后续逐章节对比：

- `.docx`：使用 `python-docx` 或同类工具提取段落样式为 Heading 1/Heading 2 的标题层级
- `.pptx`：使用 `python-pptx` 提取每页幻灯片的标题占位符文本
- `.xlsx`：使用 `openpyxl` 提取首行表头/分 Sheet 标签作为结构骨架

### Step 3：执行五项评审规则

> **核心原则：必须从原文出发，不要联想和推理，不要夸大问题**

#### 规则 1：结构不完整检测

将目标文档与对应模板进行**逐章节对比**：
- 逐一检查模板中要求的**核心章节（必选）**是否存在于目标文档
- 记录缺失的章节名称
- 章节名称不需要完全一致，语义等价即可（如"产品简介" ≈ "产品概述"）
- **判定标准**：模板中标记为必选的核心章节有任一缺失 → 结构不完整

#### 规则 2：产品定位分析

- 是否有一句话产品简介或产品定位描述
- 是否明确了核心功能和能力
- 是否突出了差异化优势（与竞品的区别点）
- 仅记录缺失项，存在的内容无需标注问题

#### 规则 3：文档场景分析

- 是否有明确的目标客户群体描述
- 是否包含场景化的需求分析或痛点描述
- 是否有功能与场景的对应关系（功能如何解决具体场景问题）
- 是否有清晰的销售指引或价值传递路径

#### 规则 4：文档案例分析

- 是否包含客户案例
- 案例是否包含具体的实施效果数据（效率提升 %、成本降低等量化指标）
- 案例是否有时效性（建议 2 年内的案例）
- 案例是否有客户授权或来源标注

#### 规则 5：技术细节分析

- 是否包含技术架构说明或架构图
- 是否有技术指标或性能数据
- 是否具备技术可验证性

> **特殊规则**：SaaS 类产品可不对技术架构深度进行检测，此规则对 SaaS 类产品降级为可选检查项。

### Step 4：结果输出

按结构完整性决定 `建议详情` 是否为空：

| 场景 | `综合建议` | `建议详情` |
|------|-----------|-----------|
| 文档类型无法归入 11 种官方模板类型 | 说明已跳过本维度及原因 | `[]` |
| 文档结构不完整（规则1判定缺失核心章节） | 简要概述结构问题与整体质量 | **具体说明缺失部分及修改建议**（含规则 2~5 的改进建议） |
| 文档结构完整 | 简要概述整体质量，认可已具备的内容 | `[]`（返回空值） |

> - 结构完整性由规则 1 判定；规则 2~5 的问题仅在「结构不完整」场景下随 `建议详情` 一并输出，作为改进建议，不再单独承载等级。
> - **类型不明时不做兜底**：不强行套用默认模板；`综合建议` 中显式声明「已跳过」以便下游区分。

## 输出格式

```json
[{
  "综合建议": "基于全文的综合审核建议，结合文档结构、产品定位、场景、案例、技术细节简要概述；类型不明时说明跳过原因",
  "建议详情": "若结构不完整则具体说明缺失部分及修改建议（含规则 2~5 的改进建议）；若结构完整或类型不明则返回空值 []"
}]
```

**结构完整输出示例**：

```json
[{
  "综合建议": "文档结构完整，覆盖模板要求的全部核心章节，产品定位清晰，案例与技术细节具备实证性，整体质量良好",
  "建议详情": []
}]
```

**结构不完整输出示例**：

```json
[{
  "综合建议": "文档缺失多个核心章节，产品定位与技术细节部分描述不足，需按模板补齐",
  "建议详情": [
    {"问题": "缺失核心章节「产品架构」", "修改建议": "参照模板补充产品架构章节，说明整体架构与关键组件"},
    {"问题": "无量化实施效果数据", "修改建议": "在客户案例中补充效率提升 %、成本降低等量化指标"}
  ]
}]
```

**类型不明输出示例**：

```json
[{
  "综合建议": "目标文档类型无法归入 11 种官方模板类型（产品白皮书 / 案例集 / 产品解决方案 / 产品介绍 / 产品彩页 / 竞品分析 / 快速入门 / 销售一指禅 / 交付标准流程 / POC 测试申请指引 / 产品报价指引），已跳过结构质量评审维度",
  "建议详情": []
}]
```

### 输出要求

1. 纯 JSON 格式，不含 Markdown 代码块符号
2. **不再输出「等级」字段**，仅保留 `综合建议` 与 `建议详情`
3. 无需额外解释或注释
4. `综合建议` 基于文档原文事实，简洁客观
5. `建议详情` 仅在结构不完整时详细列出各规则的具体问题和修改建议；结构完整或类型不明时返回空数组 `[]`
6. 多轮校验结果完全一致

## 注意事项

- **严格基于原文**：所有分析必须基于目标文档实际内容
- **不夸大问题**：如实反映文档质量，存在的内容要予以认可
- **语义等价判断**：章节名称可以不同但语义相同即视为匹配
- **SaaS 产品豁免**：SaaS 类产品的技术架构深度为可选检查项
- **类型不明跳过**：目标文档若无法归入 11 种官方模板类型，**跳过本维度检测**，不做兜底、不套用默认模板，避免误判
