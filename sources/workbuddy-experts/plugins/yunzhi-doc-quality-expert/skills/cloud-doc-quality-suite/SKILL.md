# 云计算产品文档综合质量检测套件

## 目的

作为文档质量检测的**统一编排调度中心**，对云计算产品文档（白皮书、案例集、解决方案、产品介绍等）进行 **8 维度全量质量检测 + 百分制综合评分**：AI 先产出标准化的结构化检测结果（JSON），再统一由 `scripts/check.py` 渲染为**最新版可视化 HTML 报告**交付用户（JSON 为中间产物，不作为最终交付）。

## 适用场景

- 售前弹药库文档发布前的全面质量把关
- 文档版本迭代后的回归检测
- 批量文档质量评估与分级
- 海外/国际版文档的货币单位合规性审核

## 七维检测矩阵

| 序号 | 维度 | 规则文件 | 核心能力 | 输出字段 |
|------|------|----------|----------|----------|
| 1 | 文档结构质量评审 | `rule-structure.md` | 基于模板对比的结构完整性、产品定位、场景分析、案例实证、技术深度 | 综合建议、建议详情（结构不完整时列出缺失章节与修改建议；结构完整或类型不明时 `[]`） |
| 2 | 时效性检测 | `rule-timeliness.md` | 检测标题/Roadmap/版本/封面中超过6个月的过期时间 | 过期时间片段及修改建议 |
| 3 | 超链接异常检测 | `rule-link.md` | HTTP状态码/DNS/锚点/平台文档链接可用性验证 | 链接地址、异常类型、修复建议 |
| 4 | 排版格式检测 | `rule-layout.md` | 标题层级跳跃、空段落、列表格式、表格结构、标记闭合 | 问题类型枚举、原文片段、修复示例 |
| 5 | 产品写作规范检测 | `rule-writing-standard.md` | 一体化输出：① 用词规范（错别字/形近/音近/成语/英文拼写/大小写/口语/程度词/负面情绪/一致性/宗教政治/法律禁词/的地得/人称/账号/举例）② 数字及数量规范（阿拉伯/汉字/范围/百分数/日期时间/千分位 15 条）③ 词汇表规范（一致性/定义）（**链接规范由维度 3 承担、货币规范由维度 6 承担、空格与标点规范已移除**） | 规则编号（W-*）、类别、原文片段、建议修改（**本维度不做严重等级分级**） |
| 6 | 货币规范检测 | `rule-currency.md` | 非美元货币单位（CNY/EUR/GBP 等）检测与上下文分析；货币符号格式规范（符号置于金额前、无空格、不重复附加中文单位） | 货币单位不匹配片段及换算建议；符号格式违规原文及修复建议 |
| 7 | 法律合规检测 | `rule-compliance.md` | 五大核心红线：① 国家相关元素（政府案例/领导人形象/党史/军旗军服/共青团红十字会等机构标志/英烈/国家秘密/国家机关名义 9 项）② 公序良俗（恐怖主义/民族分裂/宗教极端/歧视/淫秽色情/暴力赌博/软色情/炫富/低俗庸俗）③ 赛事元素（未授权奥运/亚运/国家队/运动员）④ 虚假宣传（完全解决/绝对保证/彻底消除/100% 承诺/未提示效果差异）⑤ 控标字眼（控标/控标项/控标点/控标参数） | 类别、命中规则、原文、章节定位、修复建议、依据 |

### 综合评分（七维检测完成后执行）

| 序号 | 阶段 | 规则文件 | 核心能力 | 输出字段 |
|------|------|----------|----------|----------|
| 8 | 百分制综合评分 | `rule-scoring.md` | 结合原文全文与七维检测结果，主维度按区段综合评分（时效 45 + 结构 45 + 准确 10 = 100），内容价值性作为加分项额外 +0~10 | 主维度得分与依据、`value_bonus`（四支点）、`final_score`、`grade`（优秀/良好/合格/待改进）、`summary` |

## 执行流程

### 第零步：获取目标文档 + 元数据识别

1. 接收用户上传的目标文档内容（支持 .md / .docx / .pptx / .xlsx / .pdf / 纯文本）
2. 读取并缓存文档全文，后续所有维度均基于同一份文档内容进行检测
3. 若用户同时提供了文档标题，一并记录（时效性检测需要）
4. **文档元数据识别（用于后续维度门控 gating）**：
   - **文件类型**：依据扩展名判定 `docx / pptx / xlsx / md / pdf / txt` 之一，写入 `文档类型.file_ext`
   - **语种识别**：抽样文档正文（标题 + 首页 + 中段各 500 字），按中文/英文字符占比判定
     - 中文字符占比 ≥ 50%  → `language = "zh"`（中文文档）
     - 英文字符占比 ≥ 80% → `language = "en"`（英文/海外文档）
     - 其他 → `language = "mixed"`（双语文档，按最严检测）
5. **将 `file_ext` 与 `language` 作为跳过条件传递给下游各维度**（详见各步骤"跳过条件"）

### 第一步：执行文档结构质量评审

**加载规则** → 读取 `references/rule-structure.md`

**执行要点**：
- 识别文档类型，覆盖 **11 种官方模板类型**：产品白皮书 / 案例集 / 产品解决方案 / 产品介绍 / 产品彩页 / 竞品分析 / 快速入门 / 销售一指禅 / 交付标准流程 / POC 测试申请指引 / 产品报价指引
- 识别语言版本（国内中文 / 海外英文）及产品类型（SaaS / 非 SaaS）
- 从 `assets/templates/` 加载对应类型的文档模板（`.docx` / `.pptx` / `.xlsx`），使用对应解析工具（`python-docx` / `python-pptx` / `openpyxl`）提取章节/页面标题进行逐项对比
- 文档类型识别优先级：①文件名关键词 → ②扩展名辅助 → ③封面/首页标题语义 → ④**类型不明时跳过本维度**（不做兜底、不套用默认模板；`综合建议` 显式声明「已跳过」，`建议详情` 返回 `[]`；其他 6 个维度正常执行）
- **⚠️ 类型不明的联动效果**：一旦本维度因「文档类型不明」被跳过，则**第八步综合评分同样跳过**，汇总 JSON **不输出 `scoring` 字段**（缺少结构规范性依据，无法给出可信总分）。对应 HTML 报告中**不渲染综合评分模块**。此时报告仅呈现已执行的检测明细维度。
- 执行 5 项评审规则：结构完整性 → 产品定位 → 场景分析 → 案例分析 → 技术细节
- **不再输出「等级」字段**：结构不完整时在 `建议详情` 中具体列出缺失部分及修改建议（含规则 2~5 的改进建议）；结构完整时 `建议详情` 返回 `[]`

### 第二步：执行时效性检测

**加载规则** → 读取 `references/rule-timeliness.md`

**执行要点**：
- 以当前日期往前推 **6 个月**为过期阈值
- 仅检测 4 类时间：文档标题时间、Roadmap 时间、最新版本时间、封面时间
- 跳过 5 类不需要检测的时间：历史版本时间、产品功能时间、客户案例客观陈述时间、未来预测时间、未来规划时间

### 第三步：执行超链接异常检测

**加载规则** → 读取 `references/rule-link.md`

**执行要点**：
- 提取所有超链接（显式/内联/锚点/引用式）
- 分类后逐一检测：请求异常（HTTP/DNS/超时）→ 锚点异常 → 平台链接异常 → 特殊链接处理
- 区分认证需求与真实失效：内部平台返回 401/403 标注"需认证访问"而非"失效"
- 跳过占位链接（example.com / localhost 等）

### 第四步：执行排版格式检测

**加载规则** → 读取 `references/rule-layout.md`

**跳过条件（v1.7.0 新增）**：
- 若 `file_ext ∈ { pptx, xlsx }`，则**整体跳过本维度**：
  - PPT 采用页面式版式编辑，其"标题层级 / 空段落 / 列表格式 / 表格结构"由 PowerPoint 版式与占位符约束，不适用本规则
  - Excel 是纯表格数据文件，排版规则不适用
  - 输出：`"检测状态": "已跳过（PPT/Excel 文件类型不适用排版规则）"`，`异常数量: 0`，`问题列表: []`
- 其余 `docx / md / pdf / txt` 正常执行

**执行要点**：
- 获取文档原始标记格式信息（Markdown # 层级 / HTML 标签 / 富文本结构）
- 逐项检测 5 大类：标题层级 → 空段落/空白 → 列表格式 → 表格结构 → 格式一致性
- 每项问题按 P0~P3 分级报告
- 代码块内部内容不纳入排版检测范围

### 第五步：执行产品写作规范检测

**加载规则** → 读取 `references/rule-writing-standard.md`

**执行依据**：《腾讯云产品写作规范》三大类别规则（用词 / 数字与数量 / 词汇表），规则编号 `W-WORD-*` / `W-NUM-*` / `W-GLOSSARY-*`。

> **v1.7.0 调整**：本维度已**移除"空格与标点规范（W-SPACE）"整个类别**（含 W-SPACE-01~15 共 15 条规则），不再检测中英文空格、全角/半角标点、括号引号规范等格式化细节。相关问题由维度 4 排版格式或后续独立版式工具承担。

**执行要点**：

- 按三大类别顺序对全文逐项扫描：
  1. **用词规范（W-WORD）**：中文错别字（形近/音近/成语/重复用词）/ 英文拼写与专有名词大小写 / 口语化词语 / 程度词与转折词 / 负面情绪词 / 用词前后一致性 / 短语词性结构一致性 / 宗教政治导向词 / 广告法严禁词 / 「的/地/得」/ 第一人称 / 用户称呼 / 账号账户 / 举例用词
  2. **数字及数量规范（W-NUM）**：阿拉伯数字 vs 汉字数字 / 千分位 / 数值范围 / 百分数 / 增减表述（禁用「降低 N 倍」）/ 日期时间格式 / 物理量 / 编号阿拉伯化
  3. **词汇表规范（W-GLOSSARY）**：定义遵守语法 / 业界标准 / 四象限词汇定义策略 / 一概念一词汇
- **链接规范相关规则已迁移至维度 3（`rule-link.md`）**：外网链接必须绝对链接、禁止内部预览链接等由维度 3 统一执行，本维度不再重复输出
- **货币规范相关规则已迁移至维度 6（`rule-currency.md`）**：货币符号置于金额前、无空格、不加中文单位等由维度 6 统一执行，本维度不再重复输出
- **空格与标点规范（W-SPACE）已完整移除**：不再检测该类别下任何规则
- **本维度不做严重等级分级**：不输出问题的严重等级（P0~P3），不输出 `问题分布`（P0~P3 计数），仅输出 `类别统计`（用词 / 数字及数量 / 词汇表三类）
- 严格遵守跳过规则：代码块、URL 原文、版本号、SKU、参数名、员工 ID、正式法律引用块**豁免**
- 每条问题必须输出**规则编号 + 原文片段 + 建议修改**三要素

### 第六步：执行货币规范检测

**加载规则** → 读取 `references/rule-currency.md`

**跳过条件（v1.7.0 新增）**：
- 若 `language == "zh"`（中文文档），则**整体跳过本维度**：
  - 货币规范检测的核心目的是识别**海外/国际版文档**中不应出现的非美元货币；中文文档面向国内客户，使用人民币（¥/￥/RMB/CNY/元）是合规且必需的默认单位，不构成异常
  - 输出：`"检测状态": "已跳过（中文文档不适用货币规范）"`，`异常数量: 0`，`问题列表: []`
- `language == "en"`（英文/海外）或 `mixed`（双语）文档正常执行

**执行要点**：
- 扫描所有货币/金额相关内容：产品报价、案例金额、预算构成、竞品对比、消耗预估
- 检测非美元货币单位：人民币（¥/￥/RMB/CNY/元）、其他（€/£/¥日元 等）
- 按场景优先级报告：P0 产品报价/竞品对比 → P1 预算/消耗预估 → P2 标杆案例
- 不检测非金额语境中的"元"字（如元素、元数据、元组等技术术语）
- 不做汇率换算，仅在建议中提示"按当前汇率进行换算"

### 第七步：执行法律合规检测

**加载规则** → 读取 `references/rule-compliance.md`

**执行依据**：《广告法》《消费者权益保护法》《反不正当竞争法》《招标投标法》《国旗法》《国徽法》《国歌法》《英雄烈士保护法》《奥林匹克标志保护条例》。

**执行要点**：
- 按 5 大类别顺序检测，命中即视为违规必须修改：
  1. **不得使用国家相关元素**：① 政府客户合作项目做宣传案例 ② 党和国家领导人形象/名义/题词/特型演员做商业广告 ③ 利用党和国家重大活动/决议/领导人讲话作商业炒作 ④ 使用或变相使用国旗/国歌/国徽/军旗/军服/"军"字号（军用/军工/军品/军需）⑤ 使用共青团/少先队/妇联/工会/残联/红十字会等机构标志 ⑥ 使用英雄烈士姓名/形象/事迹 ⑦ 涉党和国家历史时歪曲党史或宣扬历史虚无主义 ⑧ 损害国家尊严/利益、泄露国家秘密 ⑨ 变相使用国家机关及工作人员名义/形象
  2. **不得妨碍社会公共秩序、违背良好风尚**：宣扬恐怖主义/民族分裂主义/宗教极端思想；含民族/种族/宗教/性别/地域/职业歧视；含淫秽/色情/暴力/赌博/迷信/软色情；炫富/恶搞经典/低俗庸俗媚俗/无底线内容
  3. **避免使用未经授权的赛事元素**：奥运会/冬奥会/残奥会及其徽标、"奥运版"/"亚运版"标注、国家队/运动员/教练员形象名义、借赛事报道或体育明星生活变相发布商业广告；已获奥委会等官方授权且原文注明的除外
  4. **禁止虚假宣传**：禁用"完全解决/绝对保证/彻底消除行业痛点/100% 保证/永不宕机/绝对安全/无懈可击"等百分百承诺；必须明确说明产品功能效果因具体使用场景或条件而异，并提示用户合理预期
  5. **不得含有"控标"、"控标项"字眼**：含"控标/控标项/控标点/控标参数/控标条款/控标要求"等表述均违规
- 输出不含等级字段，命中即视为必须修改
- 每条问题必须附带**法律依据**（《广告法》《招标投标法》《英烈保护法》等具体条款）
- 客观陈述（如"国家高新技术企业认定"）、已获官方授权且原文注明的赛事引用、代码块/API 字段表**豁免**
- 中英文双语文档需同步检测英文绝对化表述（the best、world's first、No.1、ultimate、perfect、unrivaled）

### 第八步：执行综合评分（百分制）

**加载规则** → 读取 `references/rule-scoring.md`

**跳过条件（gating）**：
- 若第一步因「**文档类型不明**」被跳过（structure 维度未执行），则**本步整体跳过**：汇总 JSON **不输出 `scoring` 字段**，HTML 报告中综合评分模块不渲染。原因：结构规范性（占 45 分）缺乏评分依据，强行给分会误导用户。
- 其余情况正常执行评分。

**执行依据**：以「优秀文档」为正向标杆，对 3 个主维度分别打分（内容时效性 45 + 结构规范性 45 + 内容准确性 10 = 100），并对内容价值性作为加分项额外打 0~10 分叠加。

**执行要点**：

- 输入：**原文全文** + **前 7 步已完成的七维检测结果**（作为客观证据参考）
- 评分维度与七维检测的映射（详见规则文件第二节）：
  - **内容时效性**（主维度 45）← 主要参考 `timeliness`
  - **结构规范性**（主维度 45）← 主要参考 `structure`
  - **内容准确性**（主维度 10）← 主要参考 `typo_writing` + `currency` + `link` + `layout` + `compliance`
  - **内容价值性**（加分项 +0~10）← **不参考七维检测结果**，AI 直接阅读文档原文，按四大价值支点（产品定位清晰度 / 案例实证 / 技术深度支撑 / 一线销售可复用性）独立打分
- **区段综合判断**：先判断落入哪个分数区段，再在区段内根据完成质量微调；区段描述为参考而非硬性逐条卡关
- **证据驱动**：3 个主维度的给分尽量能在原文或七维检测结果中找到依据；**内容价值性**证据须直接来自文档原文；文中未体现的内容按"未体现"处理
- **不设减分项**：只对内容价值性做正向加分（0~10）；`final_score = 主维度合计（≤100）+ 内容价值性加分`，并裁剪到 [0, 100]
- 等级映射：**90~100 优秀 ｜ 75~89 良好 ｜ 60~74 合格 ｜ 60 以下 待改进**
- 输出写入汇总 JSON 的 `scoring` 字段

### HTML 报告生成规范（v1.7 · 最新版 · 强制遵守）

> ⚠️ **本节为强制要求，任何模型执行本 Skill 生成 HTML 报告时都必须严格遵守，不得凭记忆生成旧版格式。**

#### 唯一生成方式：调用 `scripts/check.py`

**HTML 报告只能由 `scripts/check.py` 渲染生成，禁止 AI 自行手写 HTML。** 流程如下：

1. 将七维检测结果 + 评分（如有）按标准 schema 写入一个 JSON 文件（如 `_ai_result.json`）
2. 执行：`python scripts/check.py --result <该JSON> --output <输出目录> --doc-name "<文档名>"`
3. 脚本输出 `<文档名>_quality_report.html`
4. 删除中间的 `_ai_result.json`（仅保留最终 HTML 给用户）

> **为什么强制用脚本**：脚本内置了最新版的所有格式规则（隐藏未执行/跳过维度、无评分模块联动、无 footer、无状态徽章、仅输出 HTML 等）。AI 手写 HTML 极易残留已废弃的旧版元素，导致报告不符合最新要求。

#### 最新版报告的强制特征（务必核对）

生成后的 HTML **必须**符合以下最新规范，**以下列出的旧元素一律不得出现**：

| 项目 | 最新要求 | ❌ 不得出现的旧内容 |
|------|----------|--------------------|
| 报告主标题 | `📋 AI 检测报告` | ~~《文档名》AI 检测报告~~、~~文档综合质量检测报告~~ |
| 模块 1 字段 | 仅 **文档名称 / 文档类型 / 检测时间** 3 项 | ~~文档链接~~、~~检测基线日~~、~~文档来源~~、~~文档负责人~~ 等 |
| 综合评分模块 | 有 `scoring` 时渲染；**文档类型不明/无 scoring 时整块不渲染** | ~~"未评分""暂无评分明细"占位块~~ |
| 各维度模块 | **未执行 / 已跳过 的维度整块不展示** | ~~"该维度未执行""⏭ 该维度已跳过"提示块~~ |
| 维度标题栏 | 仅 图标 + 维度名称 | ~~右上角"已完成 · x 项"状态徽章~~ |
| 页面底部 | 无页脚 | ~~"由 cloud-doc-quality-suite v1.7 生成"~~ |
| 输出文件 | **仅 HTML** | ~~JSON 检测结果副本~~ |

#### 模块 1：文档基本信息（`.doc-info`）

主标题固定为 `📋 AI 检测报告`；下方仅 3 项元数据（横向网格布局）：

| 字段 | JSON 取值来源（按优先级） | 缺省显示 |
|------|--------------------------|----------|
| 文档名称 | `文档名称` → `meta.document_name` → 文件名 | 未知文档 |
| 文档类型 | `文档类型` → `meta.document_type` | — |
| 检测时间 | `检测时间` → `meta.check_date`（ISO 自动格式化为 `YYYY-MM-DD HH:MM:SS`） | 当前时间 |

#### 模块 2：综合评分（`.section` 内含 `.score-hero` + `.score-dims`）

> **可选模块**：当 `scoring` 字段缺失（文档类型不明、评分已跳过）时，**整个综合评分模块不渲染**（不显示任何"未评分"占位），报告直接从模块 1 跳到模块 3（检测明细）。

- **英雄条（`.score-hero`）**：`scoring.final_score` / 100（大字号）+ `scoring.grade`（🏆 徽章）+ `scoring.summary`（一句话总结）；背景色按等级：优秀绿、良好蓝、合格黄、待改进红
- **评分明细卡片区（`.score-dims`）**：**4 张卡片**（严格按此顺序）
  1. 📊 **内容时效性** — `scoring.dimensions[0]`（`score` / `max` + 进度条 + `reason`）
  2. 📊 **结构规范性** — `scoring.dimensions[1]`
  3. 📊 **内容准确性** — `scoring.dimensions[2]`
  4. ✨ **内容价值性（加分项）** — `scoring.value_bonus`（金黄色卡片；显示 `+score` / `max` + 四支点 `sub_scores` 子项）

#### 模块 3：检测明细（`.detail-section`，按维度顺序，仅展示已执行维度）

**维度展示顺序（不可更改）**：

1. 🏗️ 文档结构质量评审（`structure`）
2. ⏰ 时效性检测（`timeliness`）
3. 🔗 超链接异常检测（`link`）
4. 📐 排版格式检测（`layout`）
5. 📝 产品写作规范检测（`typo_writing`）
6. 💰 货币规范检测（`currency`）
7. ⚖️ 法律合规检测（`compliance`）

> **重要**：上述顺序中，**检测状态为「未执行」或「已跳过」的维度整块不渲染**（例如中文文档的货币规范检测、类型不明时的结构质量评审）。报告中只出现实际执行了的维度。

**每个维度 section 展示要素**：

- 标题栏：仅 **图标 + 维度名称**（**不展示右上角"已完成 · x 项"状态徽章**）
- 可选类别统计条（`.cat-stats`）：`问题分布`（layout/compliance 的 P0~P3 计数）与 `类别统计`（typo_writing 三类、compliance 五类）。**产品写作规范检测（typo_writing）不做严重分级，不展示 P0~P3 问题分布**
- 问题卡片列表（`.issue-list`）：每条问题一张卡片，左侧色条按严重等级（P0 红 / P1 黄 / P2 蓝 / P3 灰）。**产品写作规范检测（typo_writing）不渲染严重等级标签与左侧色条**
- 无异常：显示 `✅ 未检测到异常`

**每条问题明细必须包含且仅包含以下 5 个固定字段**（顺序不变；缺失字段显示 `—`）：

| 序号 | 字段名 | 内容含义 | 各维度对应的原始 JSON 字段（脚本自动映射） |
|------|--------|---------|-----------------------------------------|
| 1 | **问题类型** | 该问题所属的类型/规则/类别 | `问题类型` / `类型` / `规则编号+类别` / `异常类型` / `命中规则` |
| 2 | **问题描述** | 该问题的具体说明 | `问题描述` / `问题说明` / `异常详情` / `综合建议` |
| 3 | **问题位置** | 问题所在的章节/段落/坐标 | `问题位置` / `位置` / `所在位置` / `章节` / `loc` |
| 4 | **原文片段** | 出问题的原文摘录（等宽字体、代码块样式） | `原文片段` / `问题片段` / `片段` / `snippet` |
| 5 | **修改建议** | 可直接采纳的修改方案 | `修改建议` / `建议修改` / `修复建议` / `建议详情` / `suggestion` |

> **规则约束**：
> - **不得新增、删除、重命名**上述 5 个字段
> - 若某条问题 JSON 中某字段确实缺失，HTML 显示 `—`（`.empty-val` 灰色样式），**不得跳过整条**
> - **原文片段**必须用等宽字体样式（`.mono`）展示，保留原始换行
> - **修改建议**用绿色样式（`.fix`）以强化"可执行"视觉暗示
> - **严重等级**（P0/P1/P2/P3）在卡片顶部以彩色标签展示，不占用 5 字段之一；**产品写作规范检测（typo_writing）例外——该维度不做严重分级，卡片无等级标签、无左侧色条**

## 执行约束

### 必须遵守的原则

| 原则 | 说明 |
|------|------|
| **顺序执行** | 严格按步骤 1→7 依次执行七维检测，最后执行第 8 步综合评分，不跳过任何步骤 |
| **独立检测** | 每个维度独立执行，前一步结果不影响后一步 |
| **规则遵从** | 严格遵循各规则文件中的所有规则、流程和输出格式 |
| **基于原文** | 所有检测必须基于实际文档内容，不联想、不推理、不夸大 |
| **完整执行** | 已执行的维度即使无异常也需体现（显示"✅ 未检测到异常"）；未执行/已跳过的维度在 HTML 报告中整块不展示 |
| **一致性保证** | 相同输入多次检测产生完全一致的输出 |
| **HTML 用脚本渲染** | 最终 HTML 报告必须由 `scripts/check.py` 生成，禁止 AI 手写 HTML，防止残留旧版格式 |

### 异常处理

| 场景 | 处理方式 |
|------|----------|
| 规则文件不可用 | 该维度标注 `"检测状态": "跳过（规则文件不可用）"`，继续后续 |
| 文档内容为空 | 终止检测并返回错误提示 |
| 某维度检测异常 | 记录异常信息，继续执行后续维度，不中断整体流程 |

## 使用方式

### 标准流程：AI 检测 + 脚本渲染

用户上传文档 → AI 加载本 SKILL.md → 按顺序读取规则文件 → 逐维度检测 + 综合评分 → 将结果写入 JSON → **调用 `scripts/check.py` 渲染为最新版 HTML 报告** → 删除中间 JSON，交付 HTML。

```bash
# 由 AI 输出的检测结果 JSON 渲染为最新版 HTML 报告（唯一权威方式）
python scripts/check.py --result <检测结果.json> --output <输出目录> --doc-name "<文档名>"
# 批量渲染目录内所有 *.json

```

> 脚本仅输出 `<文档名>_quality_report.html`（不再生成 JSON 副本）。**不要手写 HTML**，以保证报告始终为最新格式。
