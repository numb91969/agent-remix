# 学习看板模板（动态页）

## 1. 定位

看板是卡片库的呈现层，不是专家的稳定核心。数据必须实时来自卡片库，不做静态快照。模板文件 `templates/learning-board.html` 是首次创建与明确重建看板时的母本，通过平台 database SDK 动态读取「课程概念卡片库」，数字可回表复算。

## 2. 架构来源（只吸收架构，不复制模板）

- 按课程掌握度进度条：来自 RemNote 的 Mastery Tracking 思路；
- 到期复习队列（分组卡片 + 到期日期）：来自开源 Obsidian University Workflow 的全库复习看板思路；
- 状态机三段分布（新卡片 / 复习中 / 已掌握）与进度条：来自 Notion 学习看板模板的掌握状态机思路；
- 反模式纪律（不写排名、不写预计提分、看板不是装饰品、数据不足不硬生成）：来自调研中深度用户失败反思。

## 3. 数据契约

模板按卡片库固定字段名匹配（见 `library-integration.md` 第 4 节）：

| 模板用途 | 字段 |
|---|---|
| 卡片主题 | 概念 |
| 分组 | 课程、章节 |
| 可信门禁 | 核验状态、复习资格（候选 / 可复习） |
| 掌握统计 | 只统计可复习卡的掌握状态（新卡片 / 复习中 / 已掌握） |
| 复习调度展示 | 复习阶段、复习次数、最近自评 |
| 到期判断 | 复习资格 = 可复习 且 下次复习 ≤ 今天 且 掌握状态 ≠ 已掌握 |
| 队列内容 | 卡面问题、来源锚点 |

模板通过 `db.getSchema()` 动态读取字段，字段缺失时对应区块降级显示，不报错、不改动卡片库结构。

## 4. 生成流程（专家执行）

1. 满足触发条件（卡片库 ≥10 条记录且用户明确要求看板；不足 10 条时给文字摘要，不生成 HTML）。
2. 加载平台原生 `资料库` Skill，读取 `templates/learning-board.html`。
3. 把 `{{DATABASE_ID}}` 替换为实际卡片库 ID（来自建库回执，禁止留空上传），把 `{{TEMPLATE_VERSION}}` 替换为当前专家版本号。
4. 读取服务端真实 Database schema；按平台当前 Data Page 契约校验字段引用、SDK 调用、`data-sp-bindable` / `data-sp-database-id` 标记和第三方图片外链。lint 未通过禁止上传。
5. 按平台原生 Page 导入流程上传，显式关联卡片 Database，并挂到课程知识库目录页或用户指定位置。
6. 回执在线页面链接；没有取得成功回执和链接时明说未创建成功，不伪造链接。
7. 页面只读呈现数据，不提供页内编辑回写（改数据走对话/资料库 Database 操作）。

## 5. 内容纪律

- 所有数字来自卡片库查询，可回表复算；
- 不写“超越多少同学”“预计提分”“必考”等无依据结论；
- 到期判断口径固定（复习资格＝可复习、下次复习 ≤ 今天且未掌握），不临时改口径；
- 候选卡单独计数，不计入掌握度和到期队列；
- 掌握状态由用户四档自评决定，看板不自行判定“掌握”；
- 页面标题固定「课程学习看板」，副标题注明数据来源与可复算；
- 不写过程性说明（如“资料库检索未命中”“基于本地数据生成”“知识库边界”等运行时状态与待办）；检索结果、异常、边界情况一律在会话内用文字向用户说明，不固化进页面。

## 6. 页面生命周期与模板演进

- 包内模板是首次创建和用户明确要求“重建看板”时的母本。模板改动跟随专家包版本升级，通用结构改进必须回写 `templates/learning-board.html`。
- 数据变化只更新 Database；动态 Page 下次加载即读取新数据，不重新生成或上传页面。
- 用户要求调整已有在线 Page 的布局、样式或区块时，先把可复用的通用改进同步回包内母本，再按平台原生 `资料库` Skill 的 Page 增量编辑流程更新在线页面，保留未涉及内容。
- 只有用户明确要求重建，或现有 Page 已无法增量修复时，才整包重新导入；重建前说明会替换页面结构。
- 数据与结构分离：结构可演进，数据始终实时读取卡片库并可回表复算。
