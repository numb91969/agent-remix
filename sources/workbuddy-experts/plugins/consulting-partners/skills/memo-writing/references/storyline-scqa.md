# 故事线：SCQA / SCR / RSC + 金字塔结构

> 决定 deck/报告"有没有麦肯锡的骨头"。丁笃行组织任何多页材料前，先定故事线，再填内容。
> 对应用户采访要求："整体叙事结构需要总分总，要分 CHAPTER"。

## 一、SCQA（叙事展开的标准骨架）

- **S 情境 Situation**：读者已知、无争议的背景与基线。给共识，建立"我们在说同一件事"。
- **C 冲突 Complication**：发生了什么变化 / 出现了什么风险 / 为什么"现在"必须处理。制造紧迫感（配数字）。
- **Q 问题 Question**：由冲突自然引出的那个核心问题（通常隐含："那我们该怎么办？"）。
- **A 答案 Answer**：你的建议/结论。这就是金字塔的塔尖。

SCQA 是"提出问题"的部分（S+C+Q），A 引出后面整份材料的主体论证。

## 二、SCR / RSC（何时把结论前置）

- **SCR = Situation → Complication → Resolution**：常规顺序，适合读者需要被带入背景的场合。
- **RSC = Resolution → Situation → Complication**：**结论前置**，适合：
  - 读者是高管、时间紧、已熟悉背景；
  - 决策备忘录、执行摘要、汇报开场。
  麦肯锡默认偏好"结论先行"（top-down）：**先给答案，再给理由**。书面汇报尤其如此。

**丁笃行默认**：对高管/决策场景用 RSC（结论先行）；对需要教育读者的复杂议题用 SCR。

## 三、金字塔结构（纵向问答 + 横向 MECE）

```
            塔尖：一句话核心结论（= deck 的 A / memo 的 Bottom Line）
           /        |        \
      支撑论点1   支撑论点2   支撑论点3     ← 横向：MECE，互斥穷尽，最多3条
       /  \        /  \        /  \
    数据 事实   数据 事实   数据 事实       ← 底层：事实/数据/访谈/推导
```

- **纵向问答**：上一层的每个论点，都在回答"为什么这么说？"，下一层给答案；读者读任一层都不悬空。
- **横向逻辑**：同层论点之间是**归纳**（三个论点共同支撑上层同一结论）或**演绎**（大前提→小前提→结论）之一，二选一，不混用。
- **结论先行**：先抛结论，再展开支撑；读者不必读到最后才 get 重点。

## 四、总分总 + 分 CHAPTER（deck 级结构，对应采访）

一份完整 deck 的宏观结构：

1. **封面**
2. **执行摘要**（整份 deck 的 SCQA 浓缩在一页：现状→矛盾→建议，或直接 RSC 结论先行）
3. **目录**（列出各 CHAPTER）
4. **CHAPTER 1**：章节分隔页 + 该章 leading 引导页（highlight 本章将展开哪几节）→ 内容页若干
5. **CHAPTER 2**：同上（每章前都要有目录/分隔 + tracker 标识当前位置）
6. ……
7. **结论/下一步**（回扣执行摘要，给明确行动+负责人+时间）
8. **附录 Appendix**（详细分析放这，不堆在正文）

**每章前必有目录 + 页面上有 tracker**（显示当前在第几章第几节）——这是帮读者结构化的关键，非常重要。

## 五、趋势分析先定方法论（对应采访）

做趋势/格局分析前，先选**拆解维度**，不要上来就画图：
- 按**时间轴**拆（阶段演进：过去→现在→未来），或
- 按**major players**拆（主要玩家/阵营对比）。
选定后，为每个阶段/玩家**选好统一的可对比维度**（如：规模、增速、壁垒、盈利模式），保证横向可比。

## 六、故事线自检（做完对照）

- [ ] 执行摘要能否用 SCQA/RSC 一页讲清？
- [ ] 抽出所有页的行动标题连读，是否自成完整论证？（见 action-titles.md）
- [ ] 每章前有目录/分隔页 + 页面有 tracker？
- [ ] 同层论点是否 MECE（不交叉、不遗漏）？
- [ ] 是归纳还是演绎，全篇统一？
- [ ] 结论章是否回扣了执行摘要，且不引入新论据？
