# 贴图头条 - 输出规格

## 输入状态

接受 `content-state.v1/v2`。结构校验与出图门禁分层：v1/v2 的报头、日期、标题和有图主图必须确认；低于 0.85 却标为 confirmed=true 的关键字段拒绝，confirmed=false 可保留工作草案但不能出图。v2 另外要求 layout_analysis.confirmed=true、review.passed=true、非空 checks 且每项 ok=true。不要为过门禁虚增置信度；先重新核对来源、纠正识别再继续。

所有新生成的布局由同一门禁检查。旧状态的查看和历史 PNG 回放不执行迁移或重绘。整期编辑状态 `tietu-edition.v1` 另存来源、关系和方案，不原地覆盖旧 content-state。

## 画布规格

| 项目 | 默认值 | 说明 |
|------|--------|------|
| 宽度 | 1080 px | 竖版宽度，适合手机信息流 |
| 高度 | 1920 px | 竖版高度，适合手机信息流 |
| 背景色 | #FFFFFF | 纯白，保持正式媒体感 |
| 边距 | 40 px | 左右边距，保证文字不被裁切 |

固定模板以 1080×1920 为设计基准；当前版本不接受随意改变画布尺寸。若未来支持多尺寸，必须整体同比缩放并增加独立测试。

## 字体层级

| 层级 | 字号 | 用途 |
|------|------|------|
| 报头 | 72 px | 媒体名称或报头 |
| 主标题 | 64–72 px | 核心新闻标题 |
| 辅助标题 | 36–40 px | 次要信息或副标题 |
| 日期/期号 | 28–32 px | 日期、期号等元信息 |
| 标签 | 28 px | “今日关注”等标签文字 |

字体必须从系统中文字体文件路径加载，例如 Windows 的 `C:\Windows\Fonts\simhei.ttf`、`msyh.ttc` 或 `simsun.ttc`。找不到可用中文字体时必须失败，不得静默回退到 Pillow 默认字体。

## 图片处理

- `primary_photo.crop` 为 `primary_photo.path` 指向的实际位图中的 x/y/width/height 像素坐标，图片左上角为原点；不采用 source_image 或其他 PDF 渲染尺寸的坐标；
- 顺序固定为：校验实际图片边界 → 裁出 crop → cover-fit 等比缩放 → 在裁出区域内按 focal_point 取窗；
- `focal_point` 保持 0–1 的既有取窗语义，作用于裁切后的区域；
- 拒绝负数、零面积、NaN、Infinity、布尔值和越界 crop。小数坐标向内取整，未包含完整像素时拒绝；不补黑边、不扩到 crop 之外；
- 原文件不修改。已另存的独立照片应使用该照片自身坐标，完整使用时 crop 为 0/0/图宽/图高；
- 新 layout 的 image 层携带 crop 与 crop_space=source_pixels。旧 layout 无 crop 时仅按历史图层回放；要应用修复须从旧 state 重建，不猜丢失的信息；
- 禁止直接把原图 resize 到目标框造成拉伸；
- 缺少未确认图片时使用带文字的占位区；正式交付前必须补齐并确认核心图片。

## 输出格式

- 文件格式：PNG
- 色彩模式：RGB
- 透明度：不透明（背景为纯色）
- 文件命名：`cover_<type>_<revision_id>.png`

## 版本管理

- 每次用户确认或生成新版本时，保存 `state.json`、`layout.json` 和 `cover.png`；
- 版本目录：`<workspace>/.tietu_versions/`；
- 版本记录只保存相对路径、内容哈希、修订 ID、父版本和修改摘要；
- 版本名禁止包含路径分隔符，任何输出必须位于当前会话工作目录内。
