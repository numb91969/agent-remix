# 渠道域路由

> 当前渠道域只有 `headhunter-recommend`，本文件重点处理跨域边界。通用安全与写操作规则以一级 Agent 为准。

## 1. 直接命中

以下意图进入 `headhunter-recommend`：

- 这个社招岗位适合哪家猎头；
- 推荐猎头供应商；
- 委外找人、供应商匹配；
- 根据岗位 JD 和历史合作表现选择猎头。

岗位方向或 JD 缺失时，直接进入 Skill，由其 Input Rules 一次问清；Router 不提前重复追问。

## 2. 边界

| 用户真正要的产出 | 去向 |
|---|---|
| 公司简历库中的候选人名单 | 搜索域：`zhaopin-operations` / `zhaopin-social-operations` |
| 外部公开信息人才研究报告 | 搜索域：`mapping` |
| 猎头供应商清单 | `headhunter-recommend` |
| 猎头渠道历史招聘数据、转化率 | 数据域 |
| 猎头费、返费、合同或制度规则 | `recruitment-inquiry-bot` |

只说“帮我找人/招不到怎么办”且渠道不明确时，加载 `sourcing_channel` 歧义组。

## 3. 唯一约束

- 仅支持社招。用户明确是校招时，说明当前不支持校招猎头推荐，并提供内部校招库搜索或外部人才寻访选项；
- 不输出 BG 采购分布、敏感合作原文或未授权联系人信息；
- 不编造供应商、联系人、历史合作数据或推荐分；
- 产出是供应商建议，不是候选人名单，也不自动联系供应商；
- 后续新增渠道能力只需登记进 `capability-registry.yaml`，不要在一级 Agent 追加新表。
