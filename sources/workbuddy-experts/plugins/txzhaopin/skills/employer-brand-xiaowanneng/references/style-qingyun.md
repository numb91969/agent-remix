## 栏目命题

让顶尖技术人才看见：腾讯既有前沿问题、真实场景与技术空间，也允许技术人才作为一个完整的人生长。

不要只写“优秀的人取得优秀成绩”。写清楚一个具体的人如何做技术、面对困难、作出选择、与世界建立联系。

人物稿最核心的机制是：

> 用人物独有的生活语言解释技术方法，再用技术选择反证人物性格。

## 稳定气质

- 技术有深度，但不故作高深；
- 人物有反差，但不刻意造神；
- 专业、真诚、略有杂志感和文学性；
- 年轻但不装年轻，有力量但不喊口号；
- 允许焦虑、试错和复杂性存在；
- 强调真实问题、产业落地、长期积累和同行人；
- 生活侧面承担解除精英距离感的作用，不是硬凑趣味。

## 五种写作引擎

### 1. 人物母题型

适用：

- 有完整采访或口述材料；
- 同时包含技术经历、职业选择和生活细节；
- 人物存在有事实支撑的反差、兴趣或方法。

推荐外层：

> 概念型标题 → 标签金句 → 人物信息 → 导语 → 三段左右主题正文 → 不正经 QA → 技术人开包好物

外层可以调整，但正文只设一个统摄性母题。母题至少能够自然支撑标题、开头、两个章节和结尾；否则将它降级为普通生活细节。

### 2. 人物声音与形式实验

适用：

- 人物语言习惯非常鲜明；
- 连续时间记录能够呈现成长；
- 双人差异适合特殊对话形式。

日记体适合呈现时间、试错、情绪波动与成长。Input/Output 适合呈现技术人的思考方式和双人差异。

形式必须帮助理解人物，不只追求新鲜。包装式“思考中、服务器繁忙”等文字属于编辑创作，使用前需让人物确认，不能伪装成原话。

双人物从开头就通过称谓、头像、颜色或稳定语言特征区分。首屏不要连续堆叠多个长技术答案。

### 3. 议题型答疑

适用：

- 需要解决高潜技术候选人的真实顾虑；
- 有三位以上员工的有效原话；
- 问题涉及选择、导师、氛围、焦虑、成长和加入时机。

推荐顺序：

> 为什么来 → 入职后是否符合预期 → 谁在支持我 → 如何工作 → 如何面对焦虑 → 现在是否适合加入 → 最终建议

每组采用：

> 真实问题 → 一句编辑提炼的判断 → 两到四位人物提供不同证据

不能凭空生成员工证言。同一问题下的人物不要重复“平台好、机会多”。

### 4. 技术与社会议题评论

适用 AI 趋势、技术伦理、产业观察和研究观点。

推荐结构：

1. 文化或现实问题；
2. 技术变化与核心矛盾；
3. 两种或多种相反观点；
4. 建立平衡框架；
5. 分维度论证；
6. 用腾讯实践作为证据；
7. 回到人的主体性与选择。

区分事实、外部观点、腾讯判断和未来推演。腾讯产品不能从证据突然膨胀成产品清单。

### 5. 刊物序言、卷尾与领导寄语

#### 卷首

> 母题问题 → 刊物为何存在 → 技术时代与人的关系 → 青云初心和历史 → 刊物记录什么 → 短句回答母题

#### 卷尾

> 抵达最后一页 → 回望技术与生活 → 承认故事尚未完整 → 邀请读者进入下一程 → 未来式短句

#### 领导/Offer 寄语

> 战略判断 → 腾讯长期选择 → 真实资源与场景 → 文化与人才观 → 平等邀请

只以高管或组织名义写已经授权的观点。没有授权，不模拟高管发言或创造金句。

默认采用中间档语气：不写成过重的企业宣言，也不堆密集网络热词；避免战争化、竞争贬损和过度承诺。

## 人物稿四种子结构

### 日期日记

用于连续成长素材。叙事弧线可为：

> 吐槽/困难 → 试错 → 解决 → 验证 → 回看 → 传递给下一届

保持人物声音，同时控制负面联想。

### 双线互证

用于强烈双重身份，如理性与感性、技术与艺术。

两条线不能只是反差展示。生活身份需要帮助解释技术方法、共情能力、团队方式或职业选择。

### 情绪章节

用于兴奋、焦虑、变化等情绪本身能够解释成长的素材。

每种情绪都要有事件、难题和行动，不能写成情绪散文。控制焦虑篇幅，最后形成主体性的调适，而非企业替人物解决一切。

### 意象编织

用于资深人物，且兴趣确能解释方法与长期积累。

中心意象尽早建立，有节制地回返。若每段都强行套入咖啡、游戏、戏剧等词汇，会显得为了比喻而比喻。

## 技术内容翻译

使用以下顺序：

1. **用户可感知的结果**：它在哪个产品或生活场景出现；
2. **为什么难**：用一个具体限制、问题或失败说明；
3. **核心方法**：只保留理解所需的一层术语；
4. **行动与结果**：人物和团队做了什么，得到什么阶段性反馈；
5. **业务或人的意义**：它如何改变效率、体验、判断或安全。

不要从论文摘要或术语定义起笔。

准确类比示例：

- 用“返回上一级后不能失忆”解释模型记忆性；
- 用输入方式、时间和成本解释两代技术方案差别；
- 用比赛规则和提交现场解释技术竞争；
- 用真实用户场景解释底层技术价值。

比喻不能歪曲方案差异。技术候选人可保留必要术语；广泛读者需要场景化中译中。

业务成绩嵌入故事因果，不集中罗列。指标、排名、论文、覆盖范围、首次/首个等强事实必须有审核来源。

## 标题、导语与结尾

标题优先写人物反差、独有方法或全文形式，不写“优秀人才＋技术成果”。

标题承诺的母题应在首屏兑现。

人物导语至少交代：

- 人物身份；
- 青云届次或入职节点；
- 当前业务角色；
- 全文核心反差或母题。

结尾回扣开头或母题，并从个人经验延伸到同行人、下一届青云或未来探索。默认采用开放邀请，而不是硬接投递。

## 栏目质检

- 是否把人物写成完整的人，而非技术履历；
- 是否只设一个统摄母题；
- 母题是否有至少三个事实支撑；
- 技术是否按“结果—难点—方法—价值”翻译；
- 人物独特性与业务可信度是否平衡；
- 生活侧面是否承担结构功能；
- 是否存在网感段子化或先进事迹化；
- 是否保留未接受修订、备选标题、照片 DDL 或审核说明；
- 真实姓名、化名、图片和正文是否一致；
- 业务数据、论文、外部公司和引用是否获授权并保持最新；
- 结尾是否把未来交还给读者。
