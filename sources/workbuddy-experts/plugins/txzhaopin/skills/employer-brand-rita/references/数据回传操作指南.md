# 数据回传与通知 Kathy

> Rita 每次产出正式交付物后，必须执行数据回传流程，确保 Kathy 能实时掌握团队调研动态。

## 回传机制：腾讯文档共享表直写

**原理**：通过 WorkBuddy 的 `tencent-docs` 连接器，Rita 直接将调研元数据写入腾讯文档在线共享表格。招聘经理无需任何手动操作。

**共享表地址**：https://docs.qq.com/sheet/DRFN2d3hhc1BRbWxV?tab=oum2Tg

## 触发节点

| 事件 | 回传内容 | 写入 Sheet |
|------|----------|-----------|
| 问卷创建成功 | 调研ID、调研名称、委托BG、类型、目标人群、开始日期、执行人 | 项目索引 (BB08J2) |
| 分析报告完成 | 更新样本量、结束日期、备注 | 项目索引 (BB08J2) |
| 数据回收完毕 | 更新样本量 | 项目索引 (BB08J2) |
| 访谈完成 | 访谈ID、所属调研、受访者编号、角色、日期、主题标签、情感倾向、内容预览 | 访谈摘要 (oum2Tg) |
| 维度评分出炉 | 调研ID、维度、题目、均分、回答数、分值范围 | 维度评分汇总 (kaDwzU) |

## 执行流程

```
Rita 完成交付物（问卷/报告/访谈框架）
    ↓
构造回传数据（JSON 格式）
    ↓
┌─────────────────────────────────────────────────┐
│ 路径 A（首选）— tencent-docs 连接器直写          │
│                                                 │
│ 前提：招聘经理的 WorkBuddy 已授权 tencent-docs   │
│ 连接器，且共享表已开放「组织内可编辑」权限        │
│                                                 │
│ 执行：通过 tencent-docs MCP 向共享表追加行       │
│ → 对招聘经理完全无感，自动完成                   │
│                                                 │
│ 路径 B（降级）— 消息提醒                         │
│                                                 │
│ 触发：连接器未授权 / 写入失败 / 网络不可用        │
│ 执行：在交付物末尾附加提示——                     │
│   「📋 数据回传提示：请将本次调研信息同步到       │
│    共享表 或告知 Kathy 手动记录。」               │
└─────────────────────────────────────────────────┘
```

## 技术参数

```
共享表 file_id: DRFN2d3hhc1BRbWxV
Sheet ID 对照：
  - 项目索引 → BB08J2
  - 访谈摘要 → oum2Tg
  - 维度评分汇总 → kaDwzU

写入方式：mcporter call "tencent-docs" "sheet.set_cell_value"（逐cell写入）
  ⚠️ 重要：set_range_value 存在静默失败问题（返回成功但数据不持久化），
  必须使用 set_cell_value 逐cell写入，已实测验证可靠。

  写入步骤：
  1. 先查询当前最大行号（确定追加位置）
  2. 逐cell调用 set_cell_value 写入该行所有字段
  3. 写入后读回验证（可选但建议）

  单cell写入参数格式：
  {
    "file_id": "DRFN2d3hhc1BRbWxV",
    "sheet_id": "BB08J2",
    "row": 2,
    "col": 0,
    "value_type": "string",
    "string_value": "要写入的值"
  }

  项目索引列序（sheet_id: BB08J2）：
    col 0: 调研ID | col 1: 调研名称 | col 2: 委托BG | col 3: 调研类型
    col 4: 目标人群 | col 5: 样本量 | col 6: 开始日期 | col 7: 结束日期
    col 8: 执行人 | col 9: 备注

  访谈摘要列序（sheet_id: oum2Tg）：
    col 0: 访谈ID | col 1: 所属调研 | col 2: 受访者编号 | col 3: 角色
    col 4: 日期 | col 5: 时长(分钟) | col 6: 主题标签 | col 7: 情感倾向
    col 8: 内容预览

  维度评分汇总列序（sheet_id: kaDwzU）：
    col 0: 调研ID | col 1: 委托BG | col 2: 维度 | col 3: 题目
    col 4: 均分 | col 5: 回答数 | col 6: 最低分 | col 7: 最高分

查询已有数据（用于确定追加行号 & 避免重复写入）：
  mcporter call "tencent-docs" "sheet.get_cell_data" --args '{"file_id":"DRFN2d3hhc1BRbWxV","sheet_id":"BB08J2","return_csv":true,"start_row":0,"end_row":50,"start_col":0,"end_col":1}'
  → 找到最后一个非空行的下一行作为写入位置
  → 检查调研ID列是否已存在相同记录（避免重复）
```

## 执行规范

1. **无感执行**：回传对招聘经理透明，不额外增加操作负担
2. **每次必做**：任何正式交付物完成后，立即执行回传，不可遗漏
3. **失败降级**：写入失败时不阻塞主流程，降级为文字提醒
4. **隐私保护**：严格遵循脱敏规则
5. **ID 自增**：调研ID格式 `EB_{年}_{三位序号}`，每次写入前查询表中最大序号+1
6. **招聘经理拒绝权**：如招聘经理明确表示"不用同步"，跳过回传步骤

## 脱敏规则（P0 强制执行）

**绝对禁止回传的信息：**
- 候选人真实姓名
- 手机号、邮箱、微信号等联系方式
- 工号、身份证号
- 具体公司名称（用"Top互联网/外企/国企/创业公司"等类别替代）
- 具体院校名称（用"985/211/海外Top100/双非"等层级替代）
- 问卷开放题的原始作答文本
- 单份问卷的完整个人作答记录

**脱敏转换规则：**

| 原始信息类型 | 脱敏方式 | 示例 |
|------------|---------|------|
| 候选人姓名 | 完全不记录 | 张三 → （不出现） |
| 具体公司 | 替换为行业类别 | 字节跳动 → Top互联网 |
| 具体院校 | 替换为层级标签 | 北京大学 → 985 |
| 访谈画像 | 岗位/学历/年限/公司类别 | AI算法/硕士/3年/前Top互联网 |
| 问卷开放题 | 仅提炼主题标签，不传原文 | → [薪酬竞争力, 技术氛围] |
| 统计数据 | 样本量<5时合并到上级维度 | 3人细分 → 合并展示 |
| 访谈内容 | 仅保留主题+情感+摘要性结论 | → "受访者认为技术氛围好但薪资竞争力不足" |

**回传时附加说明**：每次数据回传成功后，在交付物中告知招聘经理"已同步以下脱敏信息到共享表：[列出字段]"。
