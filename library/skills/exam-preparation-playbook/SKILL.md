# Exam Preparation Playbook

## 使用时机

在用户需要制定、执行、复盘、修复或收口考试复习计划时使用。简单概念解释、单个学习方法问题或不涉及计划状态的局部咨询无需加载完整流程。

## 工作目标

把用户的考试、时间、范围和掌握证据转化为可执行计划，并在每轮反馈后更新同一份状态，而不是重新生成一份互不关联的计划。用户明确启用备考台账后，把同一状态持续写入其资料库；未启用或不可用时回退到对话摘要。

## 标准处理顺序

1. **识别阶段**：规划、执行、复盘、修复、考前收口或续接。
2. **恢复状态**：用户说“继续”“打卡”“复习到期内容”或“看看进度”时，先按 `@references/library-integration.md` 精确查找台账和进行中的计划周期；找不到再请求摘要，不要求用户先证明已启用台账。
3. **判断信息是否足够**：够用就行动；不足时只问当前场景的首要问题。
4. **建立依据**：区分已核验事实、用户提供信息、用户自评、模型暂定和未知项。
5. **计算容量并排序**：先扣除缓冲，再按稳定裁决顺序安排任务；不得让计划超过真实可用时间。
6. **选择输出层级**：只交付用户当前阶段需要的简版、标准版或展开版。
7. **推进验证**：每项重要任务包含完成标准，掌握度优先由答题、复述、真题、自测或错题复做验证。
8. **更新状态**：收到打卡或条件变化后先更新执行与掌握记录；只有任务顺序、容量、范围或优先级发生实质重排时才递增计划版本并列出差异。已启用台账时只更新当前计划周期且与本轮有关的记录。

## 最小充分信息

信息是否必需，由“换一个答案是否会改变当前方案”判断。

- 初次规划：考试名称和日期、科目或模块、每日可用时间、当前基础
- 今日执行：最近考试、今天可用时间；有可用台账时读取原任务，没有时再请用户提供
- 打卡复盘：原任务、完成度、实际耗时、主要卡点；有卡点时再补一句“怎么想通的”，有自测或错题时一并使用
- 计划修复：发生了什么变化、剩余可用容量、仍需保留的硬约束
- 考前收口：准确日期、剩余范围、已验证弱项、考试当天安排

考试范围、分值、真题、自测、错题、固定日程和资料属于推荐信息。用户无法补充时，标记假设后给最低风险的暂定方案，不伪造重点。

## 核心计划规则

- 先根据用户真实可用时间计算净容量，再排任务；缓冲和裁决规则见 `@references/decision-guide.md`。
- 多科排序必须使用同一裁决顺序，不用无依据的伪精确总分。
- 单项任务通常控制在 20—50 分钟；遇到明显疲劳、救急或连续失败时可缩短。
- A 类任务直接影响近期考试或高权重弱项；B 类有明确增益；C 类时间允许再做。
- 每项任务写明动作、知识点或材料、预计时长和完成标准。
- 计划覆盖与掌握进度分开记录；“看完”“抄完”“听懂”不直接视为掌握。
- 容量不足时必须删除、后移或降级，不用压缩睡眠填补缺口。

## 打卡与调整

每次打卡优先读取：

- 完成度：完成、部分完成、未开始、取消或替换
- 掌握度：熟练、模糊、未学或未验证；用户说“不会”时，已尝试但失败归为“模糊”，从未学习归为“未学”
- 实际耗时
- 主要卡点
- 自测、真题、复述或错题证据

出现 A 类任务连续两次未完成、实际耗时明显偏离、新增高权重弱项、考试范围或日程变化、剩余任务超过容量、明显疲劳、连续受挫或断档后积压时，启动重排。

重排不是把未完成任务原样挪到明天。先判断失败原因，再决定保留、拆分、降级、替换、后移或删除；断档积压按“保高权重和临考内容、暂停低权重复习、保护每日习惯”处理。完整状态迁移规则见 `@references/state-schema.md`。

已生成看板后，数据更新只写台账表（看板绑定表实时读数据），不重新导入看板页面；用户要求改看板布局或区块时走平台页面增量编辑，整包重建仅在用户明确要求时进行。

## 资料按需路由

| 触发场景 | 必读资料 |
|---|---|
| 首问、模式选择、多科排序、容量冲突、延期、疲劳或超载 | `@references/decision-guide.md` |
| 用户需要今日清单、七天计划、复盘或修复结果 | `@references/output-templates.md` |
| 询问日期、报名、准考证、考纲、题型、分值、政策或高频考点 | `@references/source-policy.md` |
| 用户提交上轮计划、打卡或要求持续调整 | `@references/state-schema.md`；需要计算下一复习日期时调用 `scripts/review_schedule.py`，不心算日期 |
| 用户要启用/续接备考台账、复习到期内容、保存打卡、看进展或生成看板 | `@references/library-integration.md`；执行前先按该文件「一点五」加载平台内置「资料库」技能并验证连通（与外部连接器状态无关）；看板使用包内 `templates/dashboard-template.html` 动态模板并按当前计划周期过滤；未拿到资料库节点链接不视为完成 |
| CET、计算机等级或教师资格考试专项入口 | `@references/common-exam-routes.md` |
| 修改规则后做质量复核 | `@references/regression-cases.md` |

只读取当前任务需要的资料，不在开场加载全部 references。

## 输出选择

- **简版**：信息不足、用户焦虑、只需立即行动或处于救急入口时使用。输出结论、一个立即任务、一个待确认问题。
- **标准版**：信息基本充分的初次规划或日常执行。输出风险、阶段安排、未来七天或今日任务。
- **展开版**：用户明确要求完整方案，或多科、多阶段任务确实需要覆盖清单和状态表时使用。

模板见 `@references/output-templates.md`。不要同时输出用户当前用不到的所有层级。

## 事实、停止与降级

- 暂定信息统一标记为“待确认”，来源冲突时不擅自选一个当事实。
- 具体考试事实无法核实时，说明缺口并引导到官方渠道，不用模型记忆补位。
- 拒绝泄题、代考、实时考试作答、作弊和规避纪律，改为提供合规训练。
- 出现持续失眠、惊恐、情绪崩溃或自伤风险时，停止普通效率规划，转入安全优先响应。
- 不承诺押题、保证通过或精确记忆效果。

## 每轮结束

以一个清晰入口结束，例如：

- “把三门考试的日期和当前基础按这个格式发来：科目｜日期｜基础。”
- “完成后按日期｜考试｜任务 ID｜完成度｜掌握度｜实际耗时｜卡点回复；有卡点时再补一句你后来怎么想通的。”
- “如果这份安排不适合，告诉我最冲突的一项：时间、难度、资料还是节奏，我按新约束重排。”
- 已启用台账时，结束前按 `library-integration.md` 更新本轮涉及的记录；资料库不可用时明确告知“未写入资料库”并提供本地预览或摘要，不静默降级；未启用时附可复制状态摘要，不反复推销台账。
