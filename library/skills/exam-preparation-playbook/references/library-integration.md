# 备考台账与资料库联动

## 一、定位

资料库联动用于跨会话恢复状态、按历史证据调整计划、保存计划变化。规划、排序、复盘和收口仍由本 playbook 完成；资料库不可用时回退到 `state-schema.md` 的状态摘要，不阻塞主流程。

**资料库指平台原生资料库（workbuddy.cn 的 space 空间，由内置「资料库」技能承载），与腾讯文档、飞书、Notion 等外部连接器无关。** 外部连接器显示 disconnected，不代表资料库不可用。

## 二、能力加载与连通验证

每次资料库操作前：

1. 加载平台内置「资料库」技能，只进入当前任务需要的 database、page 或 doc 分支，遵循其最新目标选择、空间分类、授权、错误处理和回执规则。
2. 按该技能当前调用前置完成鉴权；成功列出空间或读取目标节点才视为连通。
3. 加载、鉴权或连通失败时停止本次资料库操作，明确告知“本次未写入资料库”，提供状态摘要；不得把本地文件当作已入库成果。

## 三、触发、定位与计划周期

| 用户意图 | 动作 |
|---|---|
| “开启备考台账”“保存这份计划”“以后继续记录” | 创建或复用台账，写入当前计划 |
| “继续”“今天学什么”“打卡”“复习到期内容”“看看进度” | 直接按固定标题查找台账，再定位进行中的计划周期 |
| 用户给出资料库节点链接或 nodeId | 只处理该节点及完成任务所必需的关联表 |
| 未找到台账、用户拒绝或平台不可用 | 使用对话摘要继续，不假装记得 |

固定标题：

1. `备考军师·备考总览`
2. `备考军师·每日任务`
3. `备考军师·覆盖清单`
4. `备考军师·计划变更`

同一用户长期复用同一组表，不按考试周期重复建表。记录用 `计划周期ID` 隔离。出现多个同名表而无法唯一定位时请用户选择，不猜测、不另建同名表掩盖问题。

### 3.1 计划周期建立

1. 首次写入时先创建备考总览与每日任务。
2. 先向备考总览写入第一门考试，从批量新增成功结果 `results[0].id` 取得记录 ID；在内部状态中规范化为该考试的 `record_id`，并将同一值作为本周期 `计划周期ID`。不得从不存在的 `results[0].record_id` 取值。
3. 回写第一门考试的 `计划周期ID`，再写其余考试和任务；所有记录使用同一周期 ID。
4. 多个进行中周期无法唯一判断时请用户选择；只有一个时直接续接。
5. 考试日期已过但状态仍为“进行中”时，先从本轮容量中排除，再确认已考完、延期或仍需收口，不让旧周期污染新计划。

## 四、建表策略

首次保存只创建备考总览和每日任务。覆盖清单仅在以下场景创建：

- 用户明确要求管理完整范围或章节清单；
- 任一知识点首次独立验证通过，需要持久化复习阶段和下一复习日期；此时只创建覆盖清单并写入本次涉及的最小知识点记录，不扩展整本范围；
- 进入冲刺或收口，且已有可核验范围，需要按权重筛选；
- 用户明确要求生成看板。

计划变更表在第一次实质重排时创建。用户明确要求看板而该表尚未创建时，可创建空表用于展示“暂无版本变更”；不得编造变更记录。

请求看板即授权完成看板所需的非破坏性建表：缺覆盖清单时只创建空表或写入已有可靠范围，缺计划变更时创建空表；不得从模型记忆补造知识点。

## 六、读写纪律

### 6.1 首次开启

1. 先完成用户当前要的计划，不让建表流程淹没首次体验。
2. 用户明确要求保存或连续记录时，直接按资料库当前规则执行；不要重复询问是否保存。
3. 默认写入我的文档；用户指定已有节点或团队空间时按实际目标处理。
4. 建立计划周期并写入考试与任务，提交后回读验收。
5. 覆盖清单和计划变更按第四节渐进创建。

### 6.2 后续续接

- 先查总览中的进行中周期；再按 `计划周期ID` 查询最近任务、到期复习和最近版本。
- 只取当前决策必需字段；不导出整表，不跨周期读取卡点、错因等详情。
- 历史数据必须影响本轮输出：到期复习优先、连续未完成触发重排、历史耗时校正估时。
- 找不到唯一周期时先消歧；无台账时请求状态摘要。

### 6.3 打卡更新

1. 使用 `计划周期ID + 考试记录ID + 日期 + 任务ID` 匹配原任务；不能唯一匹配时先消歧。
2. 更新完成度、实际耗时、掌握度、复习结果、卡点和错误原因。
3. 有卡点时再问“你后来是怎么想通的”；没想通就留空。
4. 掌握证据变化时更新对应覆盖清单记录；首次独立验证通过但覆盖清单尚未创建时，立即创建该表并写入本次知识点的最小记录。新增成功后从对应 `results[index].id` 取得知识点记录 ID，在内部规范化为 `knowledge_record_id`，再回填本次任务的「知识点记录ID」；回读任务与知识点两条记录后才视为关联完成。
5. 需要下一复习日期时调用 `scripts/review_schedule.py`；不心算日期。
6. 只有触发实质重排时才创建或复用计划变更表。所有受影响记录回读成功后，追加差异记录并确认新版本；部分失败不得宣称完整升级。

### 6.4 关联键

- 计划周期ID、考试记录ID、知识点记录ID必须来自服务端创建或最新查询结果。
- 显示名称从相应记录当前值回显；用户改名不影响按记录 ID 查询。
- 旧台账缺少当前字段时，可只读恢复单一明确周期；写入前说明需要升级字段或建立当前结构，不静默改表。

## 七、先学后卡与复习调度

- 未学、未验证：只排学习或验证任务，不填下一复习日期。
- 首次独立验证通过：掌握度记熟练，状态记待复习，调用脚本安排 1 天后复习。
- 到期复习正确：依次进入 3、7、15 天间隔；完成 15 天阶段后状态转已验证，普通下一复习日期清空。
- 到期复习模糊或错误：掌握度回到模糊，阶段重置，1 天后再复习。
- 高权重内容可在考前追加回炉；到期任务写入每日任务时保留原 `应复习日期`，不得用实际完成日覆盖。

脚本调用示例：

```bash
python3 scripts/review_schedule.py --date 2026-09-01 --event baseline_pass --stage 0
python3 scripts/review_schedule.py --date 2026-09-02 --event correct --stage 0
```

以脚本 JSON 输出的 `next_review_date`、`next_stage`、`mastery` 和 `status` 为准。写入前向用户展示“当前日期 + 间隔 → 下次复习日期”；脚本失败时日期留空并标记待确认。

## 八、复习积压降级

断档后先比较到期任务预计总时长与当日净容量：

- 不超过净容量：到期复习优先，新内容让位。
- 超过净容量：保留高权重和临考内容；低权重到期项顺延，不删除，明确列出暂停范围。
- 不要求一次清零，不压缩睡眠，不因断档羞辱用户。

## 九、看板与文档

### 9.1 看板触发与四表补齐

仅当当前计划周期记录不少于 15 条且用户明确要求时生成。备考总览和每日任务必须已有；覆盖清单或计划变更缺失时，本次看板请求允许创建所需空表：

- 覆盖清单只写入已有可靠范围；没有可靠知识点时保持空表。
- 计划变更没有历史时保持空表，页面显示“暂无版本变更”。

### 9.2 动态模板生成

1. 读取四张表的真实 schema，逐表核对第五节所需字段；字段不完整时停止，不猜字段、不静默改表。
2. 把四次 schema 查询结果分别保存为临时 JSON，然后调用 `scripts/render_dashboard.py` 生成最终 HTML；不得手工漏替换占位符：

```bash
python3 scripts/render_dashboard.py \
  --template templates/dashboard-template.html \
  --output <工作目录>/备考进度看板.html \
  --overview-db-id <总览ID> --tasks-db-id <任务ID> \
  --coverage-db-id <覆盖ID> --changes-db-id <变更ID> \
  --plan-cycle-id <计划周期ID> \
  --overview-schema <总览schema.json> --tasks-schema <任务schema.json> \
  --coverage-schema <覆盖schema.json> --changes-schema <变更schema.json>
```

3. 脚本必须验证四表必需字段、所有占位符已替换、Database ID 为非空字面量、绑定标记存在且页面不含第三方图片。
4. 再按资料库 page 分支运行当前 SDK lint。四表页面需逐表核对 `fields / sorts / filter` 与各自真实 schema；如使用字段并集做结构 lint，只能验证调用与绑定结构，不能替代逐表字段验收。
5. 用 `import_html.py --databases` 一次关联四张表，参数为四个 `{id}`；取得资料库 page 节点链接才算完成。

模板固定展示：考试总览、掌握度分布、到期复习正确率、打卡完成率与连续天数、今日到期复习、近期任务、计划版本轨迹。近期任务优先展示最近 8 条今天及历史记录，再补最多 4 条按日期升序排列的未来任务，不让远期计划挤出当前执行记录。

指标口径：

- 到期复习正确率：当前周期中，`任务类型 ∈ {复习, 回炉}`、`完成度=完成`、`应复习日期≤今天`、`复习结果≠未验证`的任务为分母；其中 `复习结果=正确`为分子。
- 打卡完成率：当前周期中，`日期≤今天`且完成度不是取消或已替换的任务为分母；完成为分子。未来任务不进入统计。
- 今日到期复习：覆盖清单中 `状态=待复习`且`下次复习≤今天`，不能用“掌握度不熟练”替代。

看板查询必须处理分页，只读取需要字段，并按当前 `计划周期ID` 过滤。日期使用浏览器本地年月日，不用 UTC 截断代替本地日期。读取失败显示“数据读取失败”，不得伪装成“表未创建”。移动端宽表使用横向滚动或折叠。

**看板完成标准 = 拿到资料库 page 节点链接。** 未拿到链接即未完成；本地 HTML 只能标为“未写入资料库的本地预览”。

### 9.3 看板生命周期

1. 数据变化只更新台账表，不重建页面。
2. 用户要求调整区块、样式、布局或指标时走 Page 增量编辑，保留用户手动改动。
3. 只有用户明确要求重建或恢复模板时才整包重导入。
4. 模板升级由用户决定是否应用，不自动覆盖已有页面。

### 9.4 周复盘与考前收口文档

用户明确要求保存时走 doc 分支：

- 周复盘：完成率、到期复习正确率、主要卡点、错误原因分布、下周调整；
- 考前收口：高权重未熟练项、回炉安排、考试当天事项、考后复盘待办。

拿到资料库 doc 节点链接才算完成。

## 十、授权与降级

- 用户明确要求开启台账、保存计划、记录打卡或制作看板时，其请求即构成对明确范围的操作意图；按资料库当前空间规则执行，不额外创造确认。
- 团队空间、删除、字段类型转换、删除字段或选项等操作遵循资料库当前确认与风险规则。
- 用户拒绝、权限不足、查询失败或 schema 不兼容时，停止该次资料库操作，继续给备考建议并附状态摘要。
- 不修复用户手动改乱的表结构，不创建重复表掩盖错误。
