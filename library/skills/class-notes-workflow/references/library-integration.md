# 课程知识库与复习联动

## 1. 定位

资料库与定时提醒属于平台原生能力。本文件只定义笔记课代表的课程知识库业务契约；实际创建、查询、写入、页面生成、文档保存和提醒操作，必须先加载平台原生 `资料库` Skill，再严格按其当前运行模式、鉴权、授权、检索范围、Database、Page 和验收规范执行。本包不复制平台脚本，也不把外部连接器的连接状态当作资料库可用性依据。

课堂材料整理不依赖资料库。只有平台原生资料库调用明确失败、用户未授权或当前能力不可用时，才降级为会话内笔记和候选卡；不得自动创建本地“课程知识库”目录、Markdown 卡片库或其它长期影子数据源。

## 2. 何时进入

只在以下情况读取并执行本文件：

- 用户说“继续整理这门课”“接着上次”“保存到课程知识库”；
- 用户说“今天该复习什么”“复习这门课”“查看掌握情况”；
- 本轮笔记已校订，用户希望保存笔记或概念卡；
- 用户明确要求生成学习看板或设置复习提醒。

只打招呼、询问能力、咨询笔记方法或做一次性快速整理时，不查资料库。

## 3. 授权与目标位置

### 3.1 首次建库

用户在本次输入中已明确要求保存（如“保存到课程知识库”“整理后存进知识库”“继续整理并保存”）时，该表达即视为内容写入授权，不再重复询问是否保存；但**不等于用户已经选择资料库空间**。

首次保存且用户没有给出空间、空间链接、目录、课程主页或当前会话已知位置时，先加载平台原生资料库的可见空间列表，只问一个位置问题：

> 这门课要放到哪里？推荐为《课程名》新建一个独立学习空间，课程笔记、概念卡和看板都集中在里面。也可以选已有空间，或建一个多课程共用学习空间。

专家不得自行决定放“我的文档”还是任一团队空间。用户可选择：

1. **当前课程独立空间（推荐）**：为一门课新建独立空间，建议名称为《课程名》学习空间；适合课程资料、卡片和看板长期独立维护。
2. **已有空间**：用户给出空间链接、空间名称或从可见空间列表中选择；只在该空间内处理。
3. **多课程共用空间**：为多个课程新建或选择一个学习空间；适合统一查看课程目录和跨课程材料。
4. **我的文档目录**：仅当用户明确选择时，在其下建立课程目录页。

用户已经明确给出空间、空间链接、目录页/课程主页链接，或当前会话已有成功位置时，不再询问位置，直接在该目标内执行。只说“整理笔记”而未提保存时，整理完成后只问一句是否保存；用户拒绝后本会话不再询问。

### 3.1.1 当前课程独立空间（推荐）

在当前课程独立空间中建立：

```text
高等数学学习空间
├─ 高等数学｜课程主页（doc）
├─ 课程概念卡片库（database，仅本课程）
├─ 第 1 课｜函数与极限（doc）
└─ 课程学习看板（page，条件触发）
```

每门课程使用独立卡片库和学习看板；跨课程对比只在用户明确选定多个课程空间后进行，不自动扩大检索范围。

### 3.1.2 多课程共用空间

在用户选定的多课程空间中建立：

```text
大学学习空间
├─ 高等数学｜课程主页（doc）
│  ├─ 第 1 课｜函数与极限
│  └─ 高等数学概念卡片库（database）
├─ 大学物理｜课程主页（doc）
│  ├─ 第 1 课｜质点运动
│  └─ 大学物理概念卡片库（database）
└─ 各课程学习看板（page，按各自课程卡片库生成）
```

课程主页记录课程名称、课程标识、当前章节目录、考试范围（用户提供时）和该课程卡片库入口。原始课件、录音转写或附件只有在用户明确要求归档时才保存到资料库网盘。

新建独立空间属于团队空间操作，按平台原生资料库规则展示最终名称与将创建的内容并等待确认；用户已给出的已有空间按其实际归属执行。只有取得平台原生资料库返回的空间或目录页、课程主页和卡片库成功回执及访问链接，才算建库完成。提示用户以后可直接提供课程空间、目录页或课程主页链接继续；不要声称专家在包内保存了节点 ID。

### 3.2 后续定位

按以下顺序定位，命中即停止：

1. 用户给出的课程空间、空间链接、课程主页、笔记或卡片库链接；
2. 当前会话已成功创建或读取的课程空间或节点；
3. 用户从可见空间列表中明确选定的空间。

以上均未提供时，不默认搜索“我的文档”、团队空间或全部资料库；先让用户选择课程空间。只有用户明确指定某个团队空间、空间链接或明确要求全库搜索时，才按平台原生资料库规则扩大范围。

多个同名位置时列出位置让用户选择，不猜。空间、目录被改名、移动或表结构不匹配时，不自动重建、删字段或改字段类型；说明问题并请用户决定使用哪个现有知识库或新建哪个课程空间。

写入目标不等于全库检索授权。用户只给单个课程主页或表格链接时，只处理该节点及完成当前任务所必需的直接下级节点，不扩展成全库搜索。

### 3.3 写入授权

- 用户明确要求保存只完成内容写入授权；首次没有空间位置时，必须先完成位置选择，不能直接默认落“我的文档”。
- 用户选择“我的文档”或已给出的个人节点后，写入前简短说明“保存笔记 1 篇 / 追加或更新卡片 N 张”，然后直接执行。
- 用户选择新独立空间或已有团队空间后，按平台原生资料库规则展示最终空间、名称和本批将创建的内容并等待确认；不得把内容保存意图替代团队空间确认。
- 用户当轮明确拒绝保存或不选择空间时，本会话不再追问，也不创建任何远端内容。
- 删除记录、删除节点、删除字段、改字段类型等可能清空数据的操作仍按平台原生资料库规则单独处理；用户未明确要求时不扩大范围。
- 写入结果不明确时先查询验收，不盲目重试；仍不能确认时保留会话内笔记和候选卡，并说明未完成资料库写入，不创建本地替代知识库。
- 批量写入按逐条结果验收；部分失败时只处理失败项，重试前先查重。

## 4. 单课程概念卡片库

| 字段 | 类型 | 规则 |
|---|---|---|
| 卡片标识 | text | 首次创建后保持稳定；推荐“课程标识｜章节｜概念”，后续更新按该值查重 |
| 课程标识 | text | 课程全称＋学期或用户给出的稳定标识；没有学期时只用课程全称 |
| 概念 | text | 卡片主题 |
| 课程 | text | 面向用户展示的课程名称 |
| 章节 | text | 章节或主题 |
| 卡面问题 | text | 一个可独立回答的问题 |
| 答案要点 | text | 一到三条要点，不复制大段原文 |
| 易混消歧 | text | 易混概念及最小区分条件；没有则留空 |
| 来源锚点 | text | 来源编号及页码、时间点或笔记段落 |
| 核验状态 | select | 已定位 / 部分支持 / 存在冲突 / 模糊 / 缺失 / 待确认 |
| 复习资格 | select | 候选 / 可复习 |
| 掌握状态 | select | 新卡片 / 复习中 / 已掌握；候选卡保持“新卡片”但不排期 |
| 复习阶段 | number | 0 / 1 / 2 / 3；含义见第 7 节 |
| 复习次数 | number | 初始 0 |
| 最近自评 | select | 未复习 / 轻松 / 回想 / 困难 / 空白；禁止写“通过”或过程备注 |
| 下次复习 | date | 仅可复习卡由脚本计算；候选卡和已掌握卡为空 |
| 更新时间 | date | 本次内容或状态实际更新日期 |

生成卡片后必须先运行 `scripts/card_policy.py` 判定复习资格。已定位、有可定位来源且答案不含待确认或模型补全内容时为“可复习”；待确认、部分支持、模糊、缺失、模型通用知识或无可靠来源的内容可以作为“候选”保存，但不初始化复习排期、不进入到期查询。存在冲突的内容只有在卡面明确要求复述“不同来源的说法及适用范围”、答案并列保留来源且不要求裁决时，才能判为“可复习”。

## 5. 整理前读取与增量对齐

### 5.1 最小读取范围

同一课程已有知识库且历史内容会改变本轮结果时，默认只读取：

1. 课程主页；
2. 卡片库中该课程相关记录；
3. 该课程最近一次笔记。

本次材料涉及更早章节时，再按章节定向补读；不先全量读取整门课或整个资料库。只有用户明确要求跨课程梳理时，才扩大到相关课程。

### 5.2 历史内容必须改变动作

- 新材料命中已有卡片标识：更新原卡片的答案要点、来源锚点、核验状态、复习资格与更新时间，不重复建卡。
- 新材料补充已有概念：保留原内容并追加补充与新来源；若补充仍未核验，卡片保持候选。
- 新旧内容冲突：按课次、日期或版本并列，进入待确认清单；只有符合冲突复述卡规则时才可复习。
- 新概念：按第 6 节制卡纪律生成卡片，再运行 `card_policy.py` 判定为候选或可复习。
- 历史记录不足：直说“现有记录不足以做跨课次判断”，按本轮材料继续。

资料库内容只代表历史记录，不自动代表正确。用户纠正来源、课程归属或卡片内容后，以当前确认的信息重新对齐。

## 6. 整理后写入

只保存能被后续检索、增量整理或复习使用的信息：

- 用户确认笔记结构后，将结构化笔记保存到对应课程主页下面；标题使用“课次或日期｜章节主题”。
- 每次整理最多写入 10 张概念卡，优先核心概念、公式条件和易混点，不把整篇笔记切成卡片。
- 一卡一知识点；使用问题式卡面；集合或枚举内容拆成单卡，只有顺序本身需要记忆时才保留完整序列。
- 相似概念除各自卡片外，必要时增加一张消歧卡，询问最小区分条件。
- 每张卡先生成课程标识和卡片标识，运行 `card_policy.py` 写入核验状态与复习资格；只有 `initialize_schedule=true` 时再运行 `review_schedule.py --action new` 初始化复习字段。
- 写入前按卡片标识查重；存在则增量更新必要字段并保留新增来源，不重复新增。
- 候选卡的下次复习必须为空，不进入到期队列；后续材料补齐后重新运行门禁，转为可复习时才初始化排期。
- 一页纸总结、对比表和自测题默认在对话交付；用户明确要求保存时才新建资料库文档。
- 只保存定位知识所需的最小文本，不把整份课件、整篇教材或整段版权材料复制进数据库。

## 7. 复习调度

使用包内 `scripts/review_schedule.py`，不由模型心算日期或星期。展示星期时只能使用脚本返回的 `next_review_weekday`，不得由模型补写。

### 7.1 卡片初始化

只有 `复习资格=可复习` 的卡片才初始化：阶段 0，状态“新卡片”，1 天后复习，最近自评“未复习”。候选卡保持无排期。

### 7.2 四档自评与状态机

用户先作答，专家依据卡片答案与来源反馈，再让用户选择：

- 轻松：视为通过；
- 回想：视为通过；
- 困难：视为未通过；
- 空白：视为未通过。

状态推进：

- 阶段 0 通过：阶段 1，3 天后复习；
- 阶段 1 通过：阶段 2，7 天后复习；
- 阶段 2 通过：阶段 3，15 天后复习；
- 阶段 3 通过：状态改为“已掌握”，下次复习为空；
- 任一阶段未通过：回到阶段 0，1 天后复习；
- 每次实际作答后复习次数加 1；只查看答案不计复习。
- “通过”不是合法自评值。用户只说“本轮已完成”但未给四档结果时，询问一次是统一按轻松、回想、困难还是空白记录，或逐卡重新作答；不得默认为通过。
- 用户明确给出“本批统一为某一档”时，可以对本批逐条调用脚本写入同一合法自评，但仍需逐条验收更新结果。

提前复习按实际复习日期重新排期。已掌握卡片只有用户明确要求复测时才运行 `--action reactivate`；复习次数保持原值，最近自评重置为“未复习”，不得写入“重新加入复习”等过程备注。

### 7.3 到期查询

用户发起复习时，查询 `复习资格 = 可复习` 且 `下次复习 <= 今天` 且 `掌握状态 != 已掌握` 的记录。用户指定课程时只查该课程；未指定时按课程分组列出到期数量，再由用户选择开始哪一组。候选卡不出现在到期队列。

### 7.4 定时提醒

只有用户明确要求提醒时才创建。一个复习批次只建一个提醒，不为每张卡各建一个；同日已有同类提醒时优先更新而不是重复创建。提醒内容只说明“复习课程知识库到期卡片”，不包含卡片正文或个人信息。

用户要求改期、暂停或取消时，按平台原生定时能力处理；卡片记录本身不因提醒取消而删除。

## 8. 学习看板

以下条件同时满足才生成：

1. 卡片库至少 10 条有效记录；
2. 用户明确要求查看掌握情况或制作看板；
3. 资料库页面能力可用。

首次生成流程按 `board-template.md` 执行：读取 `templates/learning-board.html` → 替换卡片库 ID → 使用服务端真实 schema 完成 SDK lint 与图片外链自检 → 上传为在线 Page 并关联卡片库 → 回传链接。看板实时读取卡片库，不做静态快照。

展示区块：全部卡片数、候选卡数、各课程可复习卡掌握度、掌握状态分布、章节分布、当前到期复习队列。候选卡不计入掌握度和到期队列。所有数字可回表复算，不写无依据的排名、预计提分或“超越多少同学”。

日常数据变化只更新 Database，Page 加载时自动读取，不重新上传。用户要求调整布局或区块时，先把结构改进同步回包内母本，再按平台原生资料库的 Page 增量编辑流程更新在线页面；只有用户明确要求重建页面时，才整包重新导入。看板是档案的呈现层，不是专家的稳定核心；条件不足时给文字摘要，不为展示效果强行生成，本地 HTML 不算交付。

## 9. 失败与降级

- 找不到知识库：只在当前允许范围内定位；询问用户提供目录页链接、确认首次建库形态或新建，不自动全库扫描。
- schema 不匹配：列出不匹配字段，不自行删改；继续用会话内笔记和候选卡。
- 查询失败：只按本轮材料整理，并说明本轮未使用历史记录。
- 写入失败：当前笔记照常在会话内交付；保留可复制的候选卡清单，不创建本地长期知识库。
- 部分成功：列出成功/失败数量，只处理失败项。
- 页面或提醒失败：不影响已成功写入的笔记和卡片库，不伪造页面或提醒已创建。
- 任何情况下，只有取得平台原生能力的成功回执和访问链接，才声称已创建课程知识库或学习看板。
