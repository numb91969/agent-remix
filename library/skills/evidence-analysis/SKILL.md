# 证据分析：框架选型、数据采集与综合提炼

给问题选对分析工具，把数据变成有证据支撑的发现，诚实标注每一条结论的可信程度——绝不允许把猜测包装成事实。

## 核心方法

### 1. 框架选型

**第一步永远是问「这是哪个行业 + 走哪个透镜」，而不是直接翻通用框架库。**

**① 行业路由（三级回退：精确命中 → 相似原型借用 → 通用框架）**

热门赛道有专属框架文件（`references/industries/`），它们比通用框架准得多，
因为写死了该行业的指标口径陷阱、专用分析动作、估值锚与命门假设。

**L1 精确命中**——命中即直接用，不必再看下面两级：

**L2 相似原型借用**——不在 L1 时**先走这一级，不许直接掉到通用框架**。
按「这门生意靠什么赚钱、什么决定它的利润」归到某个生意原型，借用同原型范本文件的方法。
完整原型表、判断四问、常见行业的原型归属参考见 `industries/README.md`：

| C 瓶颈租金 / 数据壁垒 | 利润归最紧的一环，且瓶颈会迁移 | `ai-compute.md`、`embodied-ai.md`（智能层） |

| E 支付方定价 | 价格由第三方支付者定 | `medtech.md` |
| F 网络密度 | 密度降低单位成本 | `logistics.md`、`internet-platform.md` |
| G 订阅留存 | 存量续费 + 净拓展 | `enterprise-software.md` |
| H 品牌心智零售 | 复购与溢价，单店可复制 | `consumer.md` |

| J 免费获客 + 第三方买单 | 用的人不付钱，第三方为其注意力/产出付钱 | `ai-application.md` |

> 🔴 **两条使用前置（先确认，否则框架可能整段不适用）**：
> **地域**——除 `ai-application.md` 外，本目录默认**中国市场口径**（集采、LPR、
> 产粮区底价、反内卷强标等）。分析海外标的时价值链与分析动作可迁移，
> **政策与支付方那一整块必须重建**。
> **粒度**——本目录是**行业级**。被问到具体某家公司时，§1.3 口径、§2.3 动作、
> §3.5 命门假设可直接用作尽调提纲；但**未上市标的的估值锚（P/E、P/B）失效**，
> 改用 ARR 倍数 / 轮次定价 / 单用户价值，做法见 `ai-application.md` §3.4
> （该节对所有一级市场标的通用）。详见 `industries/README.md` 顶部。

> 🔴 **L2 借用三条纪律**：
> ① **可借「方法」（周期定位、§2.3 分析动作、§3 估值锚与命门假设结构），
> 不可借「口径」——§1.3 的指标口径必须为目标行业重建。** 硬套过来的口径陷阱
> 比没有框架更危险，因为它看起来很专业。
> ② **必须在输出的方法说明处声明借用了哪份文件、因为同属哪个原型、哪些部分是重建的。**
> ③ 交付前补齐该行业特有的 2–3 条口径陷阱，补不出来说明研究还不够。

**L3 通用框架**——原型也归不了（判断四问答案发散）时才回退到下面的通用框架，
但仍应照搬行业文件的骨架顺序（先定价值链与指标口径 → 再选透镜 → 最后写命门假设），
并补齐该行业的口径陷阱与结论证伪条件。

**② 透镜选型**——同一个行业，问题类型不同用的是两套不同的东西：

| 用户问的疑问词 | 透镜 | 读哪一节 |
|---|---|---|
| 该不该做 / 怎么增长 / 选哪条路 / **格局如何** / 组织怎么改 | **咨询透镜（默认）** | 行业文件 §1 地基 + §2 |
| 值不值这个价 / 盈利拐点 / 给多少倍 / 哪个假设一翻转结论就翻 | **行研透镜（需明确触发）** | 行业文件 §1 地基 + §3 |

两个透镜**共用 §1 的价值链与指标口径**——口径只认一套，避免同一指标算出两个数。
判断不了就走咨询透镜。**问「格局」永远走咨询透镜**，不许因为涉及上市公司就答成配置建议。

> 🔴 **引用行业框架库里的任何数字前，必须重新取数。**
> `industries/` 下所有数字都是带 `as-of` 的**口径示例**——只说明这个指标长什么样、单位是什么，
> **不是当期值**。任何要写进交付物的规模/份额/增速/产能/估值倍数，
> 动笔前必须实际调用 `neodata-financial-search`（`data_type=doc`）/ `westock-data consensus`
> 或联网检索取当期值。**直接抄示例数字进交付物 = 交付事故**，等同于凭记忆编数字。
> 文件标注的「最后校订」超过 12 个月时，框架仍可用，数字口径需整体复核。

**③ 通用框架选型**——面对一个具体问题，从框架库里选 **2-4 个互补的框架**，不要罗列所有能想到的框架。选型三原则：
- 问题决定框架，不是框架决定问题
- 深度优于覆盖面（用好2个框架比蜻蜓点水用6个框架更有价值）
- 数据可行性优先（选的框架如果没有数据支撑就要降级或替换）

**问题域 → 推荐框架速查**：

| 问题域 | 主框架 | 辅助框架 |
|--------|--------|---------|
| 市场进入 | 五力模型 + TAM-SAM-SOM | 安索夫矩阵、竞争定位图 |
| 增长战略 | 安索夫矩阵 + 利润树 | 三层增长地平线、蓝海战略 |
| 定价策略 | 价值定价 + 利润树 | 竞对分析、支付意愿测算 |
| 成本削减 | 利润树 + 价值链分析 | 零基预算、二八原则 |
| 并购/尽调 | 商业尽调清单 | 五力模型、7S（整合阶段）、VRIO |
| 组织效能 | 7S框架 | 影响力模型、变革管理 |
| 决策机制 | RAPID决策角色 + 决策矩阵 | 事前验尸法、二阶思维 |
| 沟通表达 | 金字塔原理 + SCQA | 情境-矛盾-解决叙事结构 |
| 创新方向 | 蓝海战略 + JTBD | 韦德利地图、三层地平线 |
| 组合管理 | 波士顿矩阵/GE九宫格 | 收入结构、增长-盈利交叉分析 |
| 财务诊断 | 杜邦分析 | DCF、可比公司估值、EVA |
| 竞争格局 | 五力模型 + 战略群组图 | 标杆对比、价值链分析 |
| 行业研究 | 产业链上中下游拆解 | PESTEL、技术成熟度曲线 |
| 消费者洞察 | 消费者决策旅程 | RFM模型、马斯洛需求层次、JTBD |

**何时不该用某个框架**（比"怎么用"更重要）：
- 五力模型：只有当"行业结构本身"是问题核心时才用，不要当成默认起手式
- SWOT：几乎不该作主分析工具，它是头脑风暴格式不是分析方法，只适合分析完成后快速自检
- 利润树：只有因变量能量化为增长或利润时才用
- 7S框架：只用于组织根因诊断，不要用来分析市场或产品问题
- 波士顿矩阵：只适用于多产品组合决策
- 蓝海战略：只有"开辟新市场空间"是真实可行的选项时才用

完整14类框架的原理、适用场景与常见误用见 `references/framework-library.md`；
十三个赛道的行业专属框架与生意原型回退路由见 `references/industries/`（**优先于通用框架库**）。

### 2. 证据分级标注

给每一条陈述打标签：

| 标签 | 含义 | 要求 |
|------|------|------|
| `[F]` 事实 | 直接观察、有出处、可核实 | 必须带来源、时间范围、单位 |
| `[I]` 推断 | 从已知事实推导出的判断 | 说明推导逻辑，不能只给结论 |
| `[A]` 假设 | 因信息缺口而做出的判断性填补 | 必须给出置信度，说明假设不成立会怎样 |
| `[E]` 估算 | 基于假设和数据计算得出的数字 | 写明计算公式和输入假设来源 |

任何数字如果没有明确来源、单位和时间范围，默认视为不合格陈述，需要退回补充或明确标注为 [A]。详细的证据陷阱清单见 `references/evidence-grading.md`。

### 3. 真实数据采集

**主动去拉可核实的数据，而不是让用户自己粘贴文本。** 按数据类型选入口，不要因为"这两个源看着是证券工具"就跳过：

| 你要的数据 | 走哪个 |
|---|---|
| **市场规模 / 份额 / 渗透率 / 出口量 / 行业趋势** | `neodata-financial-search`，用 `data_type=doc` 召回券商研报与财经文章。**咨询最常要的就是这类，也最容易被误判为查不到——必须先试** |
| 宏观指标（GDP/CPI/汇率/大宗价格） | `neodata-financial-search`（`data_type=api`） |
| 某家上市公司的营收/毛利/资金流/机构评级 | `westock`：先 `westock-data search <公司名>` 拿代码，再 `quote`/`asfund`/`rating` |
| 行业增速的**卖方一致预期**（分年度营收/净利/增速） | `westock`：`westock-data consensus <代码>`。比自己拍增速有据，可标 `[F]` 并注明预期口径与日期 |
| **该行业市值/ROE 前 N 家是谁**（竞争格局标准动作） | `westock`：先 `westock-data search <关键词> --sector`（或 `sector --search`）拿板块代码，再 `westock-tool filter "<表达式>" --universe <板块代码>`。**板块/概念在 data 侧**；tool 侧是 `filter` / `strategy` / `label` |
| 具体公司的研报原文 | `westock`：`westock-data report <代码>` |

**`westock-data` / `westock-tool` 是简写**：两个子工具合并在一个 skill 包里，真实调用是
`node <westock-skill-path>/scripts/data-index.js <命令>` 与 `.../scripts/tool-index.js <命令>`。
包内没有 `bin/` 目录，短命令敲下去会 command not found，详见 `westock/SKILL.md`。

口径限制：`westock` 按证券代码取数，**只覆盖上市主体**——未上市公司与细分市场规模只能走
`neodata` 文章召回或联网搜索。沪深市值单位是元、港股美股是亿元，跨市场比较前先换算。

查不到的明确标注"数据不可得"**并写明试过哪些检索**，不得编造替代。

### 4. 资料综合提炼（Synthesis）

面对访谈记录、调研问卷、资料堆这类原始输入，提炼出**不超过3条**带证据、带"所以呢"的洞察，而不是罗列7、8条话题式发现。综合与摘要的区别：摘要压缩别人说了什么，综合指出这些话意味着什么、该怎么做。

**流程**：聚类（让主题从数据里自然浮现，不预设主题硬套）→ 按频率/严重度/意外程度强制排到3条 → 每条写成可证伪的主张句（不是话题词，如"客户在第3步流失是因为强制邀请团队成员"而不是"关于入职的反馈"） → 每条配2-3条具体证据（直接引用、精确数字、点名来源） → 每条写1句"所以呢"（读者应该做什么不同的事）。

## 完整工作流程

0. **先路由**：识别行业 → 按 **L1 精确命中 → L2 相似原型借用 → L3 通用框架** 三级依次找，
   命中即停，**不许跳过 L2**；走 L2 时在方法说明处声明借用了哪份文件与哪个原型。
   再识别透镜（咨询 / 行研），在输出开头一句话说明按哪个透镜作答
1. 识别问题域，选定2-4个框架（行业文件 §2.2 或 §3 的组合优先于通用框架库），说明每个框架具体验证什么（若已有假设树，明确对应关系）
2. 列出数据需求清单：指标名称、数据类型、建议来源、优先级（P0/P1/P2）、时间范围
3. 执行数据采集：**P0 数据必须实际发起过检索**（neodata/westock，按上表选入口）才能进入第 4 步——
   凭记忆填 P0 数字属于流程违规。P1 同样先查，查不到的明确标注"数据不可得 + 已试过的检索"
4. 应用框架分析，产出结构化分析，每条结论标注证据等级
5. （如涉及原始资料）执行3条洞察提炼

## 输出规范

```markdown
## 框架选型

| 分析维度 | 选定框架 | 验证什么 |
|---------|---------|---------|

## 数据需求与采集结果

| # | 指标 | 类型 | 来源 | 优先级 | 结果 | 证据等级 |
|---|------|------|------|--------|------|---------|

## 框架分析结论

### [框架1名称]
[按框架结构展开分析，每条结论标注 [F]/[I]/[A]/[E]]

## （如适用）资料综合：3条核心洞察

**洞察1**：[可证伪的主张句]
证据：[具体数据点]
所以呢：[这个发现应该改变读者的哪个决策]
```

## 注意事项

- 缺数据时诚实说"数据不可得"，绝不用"合理推测"掩盖编造
- 不要用五力模型分析每一个问题；SWOT不能替代真实分析
- 数字必须带单位、时间范围、来源
- **`references/industries/` 里的数字是口径示例不是当期值**，写进交付物前必须重新取数
- **行研透镜放开的是分析方法**（盈利拆解、供需平衡表、估值锚、敏感性），
  **不放开交易层**：评级、目标价、仓位、止损止盈一律禁止；格局题永远走咨询透镜
