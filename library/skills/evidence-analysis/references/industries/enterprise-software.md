> 文中所有基准值（NRR、Rule of 40、CAC 回收期、估值倍数等）仅作**口径示例**，

## 0. 速查

**一句话结构**：SaaS 的价值 = **留存 × 效率 × 增长** 的复利。
生意模型的本质是「先付获客成本、后收订阅现金流」，所以**回收期和留存质量比增速更根本**。

**当前的结构性变化（as-of 2026，本赛道最重要的一件事）**：
AI 正在同时改写 SaaS 的**收入模式**与**成本结构**——

| 维度 | 传统 SaaS | AI 时代的变化 |
|---|---|---|
| 定价 | 按席位订阅 | 席位计费占比下降，**混合定价（底座订阅 + 用量/成果计费）快速上升**（示例 as-of 2026：席位制收入占比约 21%→15%，混合定价约 27%→41%，Gartner 预测口径，须复核） |
| 毛利率 | 75-80%+ | AI-native 因推理成本被压到 **55-70%** |
| 估值锚 | EV/Revenue（ARR 倍数） | **EV/EBITDA 首次成为主要锚**（示例：公开市场 SaaS 中位约 26.6x，as-of 2026，须复核） |
| ARR 可见性 | 高（年度续约） | 下降——客户可因 Agent 提效而减少席位 |

**这意味着：用 2021 年的 SaaS 估值心法看 2026 年的公司，会系统性看错。**

**两个透镜的分界**：

| 你被问的是 | 走哪个透镜 |
|---|---|
| 定价模式怎么改 / 做水平还是垂直 / 中国市场怎么摆脱定制化 / GTM 怎么设计 / 要不要做 AI Agent | **§2 咨询透镜** |
| 增长质量如何 / 该给多少倍 / AI 是提升还是侵蚀这门生意 / 什么价位算合理 | **§3 行研透镜** |

## 1. 产业地基（两透镜共用）

### 1.1 价值链与利润分布

```
基础设施(云/算力) → 平台层(数据/中间件) → 应用层(水平 SaaS / 垂直 SaaS)
                                              ↓
                        交付与实施 → 客户成功 → 续约与增购
```

利润逻辑的三个判断点：

| 判断点 | 含义 |
|---|---|
| **系统记录地位（System of Record）** | 拥有企业关键数据底座的厂商议价权最强，**即使定价模式变了也能从 AI 时代受益而非被颠覆** |
| 垂直 vs 水平 | 垂直 SaaS 因行业 know-how 与嵌入式金融等增值收入，通常享有估值溢价（示例 as-of 2026：约 46% 溢价，须复核） |
| 交付重不重 | 实施与定制占比越高，越接近项目制生意，**毛利率与可复用性都会塌下来** |

### 1.2 核心驱动变量

| 侧 | 变量 | 追踪方式 |
|---|---|---|
| 需求 | 企业 IT 预算增速与结构 | 第三方 IT 支出预测、客户调研 |
| 需求 | AI 预算是新增还是挤占 | **关键问题**：若挤占存量软件预算，传统 SaaS 是受损方 |
| 留存 | NRR / GRR | 公司披露；**口径必须逐家核对** |
| 效率 | CAC 回收期、Magic Number、烧钱倍数 | 公司披露或测算 |
| 成本 | 推理成本占收入比 | AI 功能的毛利率影响 |
| 竞争 | 平台厂商是否把功能收编 | 单点工具最大风险是被平台吸收 |

### 1.3 关键指标与口径

| 指标 | 定义 | 口径陷阱 |
|---|---|---|
| **ARR** | 年度经常性收入 | **含不含用量计费、一次性实施费、硬件、定制开发？** AI 时代用量与成果计费上升后，「经常性」的定义变模糊，是本赛道当前最大的口径混乱 |
| **ARR Bridge** | 期初 ARR + 新签 + 增购 − 收缩 − 流失 = 期末 ARR | **尽调必备**。只给期末 ARR 与增速、不给 bridge 的公司要警惕——增长可能全靠新签堆、老客户在流失 |
| NRR | 同一批老客户的收入同比（含增购与流失，不含新客） | ① 年度还是季度年化 ② 分母客户群怎么定义 ③ 含不含降配。示例基准 as-of 2025-2026：私有 B2B SaaS 中位约 101-102%；ACV>10 万美元的企业级约 118% |
| GRR | 只扣流失与降配，不含增购 | **NRR 高但 GRR 低 = 靠少数大客户增购掩盖了大面积流失**，是最重要的交叉验证 |
| CAC 回收期 | 收回单客户获客成本所需月数（用毛利调整后收入） | 示例基准 as-of 2025-2026：中位约 16 个月（前一年 18），顶尖四分位 ≤6 个月，≥24 个月会被质疑可持续性 |
| LTV / CAC | — | **业界正在弃用**：LTV:CAC 要把三个估算值相乘，而回收期只用两个已知数。**优先用 CAC 回收期与烧钱倍数** |
| Rule of 40 | 增长率(%) + 利润率(%) ≥ 40 | 利润率用 EBITDA 还是 FCF 口径必须写明。示例基准 as-of 2025-2026：中位约 25%（前一年 15%），顶尖四分位约 43% |
| Magic Number | 新增 ARR / 上期销售市场费用 | 示例中位约 1.37；**拆开看更有信息量**：新客获取每 1 美元 ARR 约花 1.63 美元，增购只需约 0.80 美元 |
| 毛利率 | 软件毛利 | 示例：传统软件中位约 80%；**AI-native 因推理成本降至 55-70%**，跨代际公司不可直接比 |
| ARR per employee | 人效 | 示例中位约 19.3 万美元，顶尖约 27.9 万美元 |
| **Production ARR** | 已进入生产环境的 ARR | **必须与 POC/试点收入分开**——AI 时代大量收入停留在实验阶段，续约率完全不同 |
| 任务完成率 / 单次成功任务成本 | Agent 类产品的效果与成本指标 | 新兴口径，各家定义不一，引用时须写清定义 |

> **中国市场特殊口径**：国内企业软件普遍混有**定制开发收入、私有化部署、硬件**，
> 且回款周期长、应收账款占比高。
> **直接套用海外 SaaS 基准会严重高估国内公司的质量**——
> 分析国内标的时必须先做「收入质量拆解」：订阅 / 用量 / 实施 / 定制 / 硬件 分开列，
> 并同时看经营性现金流与应收账款周转。

| 你要什么 | 去哪 | 频率 |
|---|---|---|
| SaaS 基准值（NRR、CAC 回收期、Rule of 40 等） | 年度 SaaS Benchmarks 类报告（注意样本量与年份） | 年度；**必须写清样本来源与 n** |

| 一致预期与研报 | `westock-data consensus`、`neodata`（`data_type=doc`） | 随时 |

### 1.5 周期定位

SaaS 的「周期」主要是**估值范式周期 + 技术范式周期**：

| 层 | 驱动 | 观察指标 |
|---|---|---|
| 估值范式 | 市场在「增长优先」与「效率优先」之间摆动 | 板块倍数、Rule of 40 的溢价斜率 |
| 技术范式 | AI 对定价与成本结构的重写程度 | 混合定价占比、AI 收入占比、毛利率变化 |
| 企业 IT 支出 | 宏观与预算周期 | IT 支出增速、销售周期长度 |

**当前定位（as-of 2026，须复核）**：处在「效率优先」+「AI 重写定价与成本」的叠加期——
表现为 Rule of 40 中位数回升、CAC 回收期改善、但 NRR 压缩、毛利率因推理成本承压。

## 2. 咨询透镜（决策者 = 软件公司高管 / 董事会）

### 2.1 典型问题

定价模式怎么从席位制迁移到用量或成果计费 / 做水平还是垂直 /
中国市场怎么摆脱定制化陷阱 / GTM 走 PLG 还是销售驱动 /
要不要做 AI Agent、怎么定价 / 客户成功怎么组织 / 出海去哪。

### 2.2 框架组合

| 问题 | 框架组合 | 各自验证什么 |
|---|---|---|
| 定价模式迁移 | 价值度量选择 + 客户价值曲线 + 收入桥模拟 | **定价单位必须与客户感知的价值同向增长**；迁移会同时改变 ARR 可见性与毛利率，须模拟收入桥 |
| 水平 vs 垂直 | 市场规模 × 可防御性 + 行业 know-how 壁垒 | 垂直窄但深、有溢价；水平宽但易被平台收编 |
| 摆脱定制化 | 收入质量拆解 + 产品化率路径 + 客户分层 | 把定制需求归因到「行业共性」还是「单客特例」，前者产品化、后者拒绝或加价 |
| GTM 设计 | CAC 回收期分层测算 + 销售周期 + ACV 分布 | 不同 ACV 段对应完全不同的 GTM，**混着做必然低效** |
| AI Agent 决策 | 单位经济学（推理成本 / 任务）+ 数据资产盘点 + 竞争位势 | 有系统记录地位的厂商做 Agent 是加固护城河；没有的可能只是给模型厂打工 |

### 2.3 行业特有分析动作

**① ARR Bridge 诊断（本赛道的招牌动作，两透镜共用）**

```
期初 ARR + 新签 + 增购 − 收缩 − 流失 = 期末 ARR
```

把四个流量项分别拆到客户分层（按 ACV、行业、渠道），**立刻能看出增长是买来的还是长出来的**。
只看期末 ARR 与增速会漏掉「新签很猛、老客在跑」这个最致命的问题。

**② 收入质量拆解（中国市场必做）**——把收入拆成订阅 / 用量 / 实施 / 定制 / 硬件，
计算「真订阅收入占比」，并对照经营性现金流与应收账款。
**国内很多号称 SaaS 的公司，真订阅占比不到一半。**

**③ 单位经济学分层**——按 ACV 段分别算 CAC 回收期与毛利率。
**全公司平均的回收期会掩盖某个细分市场在持续烧钱。**
参照示例（as-of 2026）：新客获取的单位成本约是增购的两倍——
这直接推导出「增购比新签更值得投资源」的结论，但必须用自家数据验证。

**④ AI 单位经济学**——每个 AI 功能/Agent 的：单次调用推理成本 × 调用频次 vs 收费。
**这是判断「AI 功能是护城河还是毛利黑洞」的唯一硬指标。**

### 2.4 结论形态样例与高频误判

**合格结论**：
> 定价从纯席位迁移到「底座订阅 + 任务量计费」，先在 A 客户群试点 6 个月；
> 目标是 NRR 从 X% 提到 Y% 且 AI 功能毛利率不低于 Z%。
> 中国区停止承接单客特例定制（占比从 P% 压到 Q% 以内），
> 把三项行业共性需求产品化；若 12 个月内真订阅占比未过半，收缩该业务线。

**高频误判**：

| 误判 | 为什么错 |
|---|---|
| 只看 ARR 增速不看 bridge | 新签堆出来的增长会在续约期原形毕露 |
| NRR 高就以为健康 | 必须与 GRR 对照，否则是大客户增购在掩盖流失 |
| 用全公司平均单位经济学 | 会掩盖某个细分在烧钱 |
| 把定制收入算进 ARR | 不可续、不可复用 |
| 假设 AI 功能不影响毛利 | 推理成本是真实的边际成本 |
| 直接套用海外基准评价国内公司 | 收入结构与回款周期完全不同 |

## 3. 行研透镜（决策者 = 投资人）

### 3.1 典型问题

增长质量如何 / AI 对这家公司是增益还是侵蚀 / 该用什么锚、给多少倍 /
什么条件下估值溢价能维持。

### 3.2 盈利驱动拆解式

```
ARR = 客户数 × ACV
    其中 ACV 变化 = 增购 − 收缩

收入质量 = 订阅占比 × 留存质量(GRR/NRR)
效率     = 新增 ARR / 销售市场费用（Magic Number）
利润     = 毛利率(受推理成本影响) − 研发% − 销售%
Rule of 40 = 增长率 + 利润率
```

**AI 时代必须额外拆一层**：把收入分成「传统订阅」与「AI 相关（用量/成果）」，
两者的毛利率与可见性完全不同，混算会得出错误的利润率趋势。

### 3.3 增长质量的判定顺序

按重要性排序（as-of 2026 的业界共识，须复核）：

```
增长率 → NRR（并与 GRR 对照）→ CAC 回收期 → 烧钱倍数 → Rule of 40（作为估值筛选）
```

**注意范式变化**：投资人对资本效率的权重远高于 2021 年，
**烧钱倍数与 CAC 回收期在尽调中已在很大程度上取代 LTV:CAC**。

### 3.4 估值锚与可比口径

| 类型 | 主锚 | 示例区间（as-of 2026，须复核） | 说明 |
|---|---|---|---|
| 公开市场成熟 SaaS | **EV/EBITDA** | 中位约 26.6x | **首次取代 EV/Revenue 成为主锚**——AI 推理成本压缩毛利率，使收入倍数失去可比性 |
| 成长期（未盈利） | EV/Revenue，**须按 AI 推理成本后的毛利率调整** | AI 工作流自动化类核心区间约 8-10x，中位约 9x | 不做毛利率调整的收入倍数不可跨代际比较 |
| AI-native 智能体平台 | EV/Revenue | 约 14-22x；一级市场约 20-30x | 溢价需要生产环境 ROI 证明支撑 |
| 传统 RPA / 单点工具 | EV/Revenue 或 EV/EBITDA | 约 2.5-5x（EV/Rev）；成熟后台业务 10-20x（EV/EBITDA） | 被平台收编导致的深度折价 |
| 私有 SaaS | EV/ARR | 约 3.5-5x | 与公开市场差距大 |

**Rule of 40 与倍数的映射**（示例，须复核）：>50 分对应显著溢价，
40-50 分对应健康溢价，<30 分深度折价；**每提升 10 分大约值 1-2x 收入倍数**。

> 🔴 **本赛道估值第一提醒**：**跨代际比较必须先统一毛利率口径。**
> AI-native 公司毛利率 55-70% 与传统 SaaS 80% 不是同一门生意，
> 给它们同一个收入倍数是方法论错误。这也正是市场把主锚切向 EV/EBITDA 的原因。
> 引用任何基准值时**必须同时给出样本来源、样本量与年份**——
> SaaS 基准的口径分歧极大，不注明来源的基准值等于没有依据。

### 3.5 命门假设与敏感性

| 命门假设 | 翻转会怎样 | 观察哨 |
|---|---|---|
| AI 预算是新增还是挤占存量软件预算 | 挤占 → 传统 SaaS 是受损方而非受益方 | 客户 IT 预算结构调研、席位数变化 |
| 席位数会不会被 Agent 提效压缩 | 纯席位计费公司面临净收入萎缩 | 老客户席位续费数、定价模式迁移进度 |
| 推理成本下降速度 | 决定 AI 功能的毛利率能否修复 | 单位推理成本趋势、毛利率季度变化 |
| 平台厂商是否收编该功能 | 单点工具的生存问题 | 平台方产品路线图 |
| 留存质量 | 直接决定估值中枢 | GRR 与 NRR 的背离 |

敏感性至少做 **NRR × 增长率** 与 **毛利率 × 增长率（Rule of 40 平面）** 两组。

## 4. 两个透镜都会踩的坑

1. **ARR 定义不统一就横比。** 含不含用量、实施、定制、硬件，差别巨大。
2. **只看 NRR 不看 GRR。** 大客户增购能掩盖大面积流失。
3. **只给期末 ARR 不给 bridge。** 看不出增长来自哪里。
4. **用全公司平均掩盖分层差异。** 必须按 ACV 段拆。
5. **跨代际比收入倍数。** AI-native 与传统 SaaS 毛利率不同代。
6. **直接套用海外基准评价国内公司。** 国内收入结构与回款周期完全不同。
7. **引用基准值不写样本来源与年份。** SaaS 基准口径分歧极大且逐年变化。
8. **假设 AI 只带来收入不带来成本。** 推理是真实的边际成本。
