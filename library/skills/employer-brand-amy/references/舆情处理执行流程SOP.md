# 舆情处理执行流程 SOP（6 步主干 · 团队权威流程）

> ⭐⭐⭐ 这是 Amy 处理舆情 case 的**执行总流程**（Kathy 给定的团队真实 SOP，2026-06-22）。
> 与其他文档的分工：本文是"**怎么一步步走 + 谁来沟通 + 跟谁定结果**"的动作骨架；
> 判断标准挂在每一步里：等级判断→《态势研判与走势预测模型》四象限+打分；处置基调→《雇主品牌三类舆情分型处置SOP》；话术→《舆情危机处理方法论》+《历史案例话术库》。

## 全流程一图

```
            ┌─ ❌ 未公开发帖（未涉舆情）→ 业务BP/ER定话术→线下沟通解决→报备雇主品牌接口人【不进社交平台处理】
事件来了 → 判断是否已在社交平台公开发帖？
            └─ ✅ 已公开发帖（涉舆情）→ 进入下方舆情处理流程↓

1 获取信息 → 2 识别舆情等级 → 3 沟通还原事实 → 4 确定处理结果+拟话术
                                  ↑(不处理)              ↓
                              继续观察              5 沟通确认(文字+保密条款)
                                                         ↓
                                          6 闭环：删帖/更新 → 监控7天 → 结案

处理人(已涉舆情)：涉事BG业务PR主办 → 同步雇主品牌接口人 → BG搞不定→集团PR+雇主品牌接口人联合
```

> ⭐⭐ **总开关 = 是否已在社交平台公开发帖**：未公开发帖 → BP/ER 谈话术线下解决 + 报备 雇主品牌接口人，**不启动 PR/社交平台处置**；已公开发帖 → 才进入舆情处理流程与 PR 链路。详见下方「处理人链路」首节。

## 步骤 1：获取信息

舆情来源两种：
- **主动获取**：通过舆情搜索技能（小红书/脉脉/微博/公众号/视频号/网媒 6 平台监测）主动发现。
- **被动获取**：用户（经理）主动提供某条 case。

> 拿到后先记录：平台、原帖链接/截图、当前数据（点赞/评论/收藏）、发帖人是否可联系。

---

## 步骤 2：识别舆情等级

> ⭐ **识别等级前，必须先做全网搜索**——单看原帖数据不够，要摸清"扩散到了哪些平台、传播到什么程度"，这才是判断等级的真实数据依据。

### 2.1 全网扩散搜索（数据依据，不可跳过）
以事件关键词（公司+事件特征词/当事人/帖子核心词）做 **6 平台全网搜索**，摸清扩散面：

| 平台 | 工具 | 看什么 |
|------|------|--------|
| 小红书 | xiaohongshu MCP / web_search | 原帖+有无搬运/跟帖，点赞+评论 |
| 脉脉 | agent-browser 深采 / web_search | 有无职场圈讨论、转发 |
| 微博 | weibo MCP（SEARCH_CONTENT+GET_TRENDINGS） | 有无话题/热搜、转发量 |
| 公众号 | wechat-article-search | 有无文章跟进 |
| 视频号/抖音 | web_search + 微信生态 | 有无视频二创 |
| 网媒/新闻 | web_search × 多轮 + web_fetch | 有无媒体报道转载 |

**搜索要摸清 4 件事**：
1. **扩散范围**：只在原平台单帖，还是已跨平台/被搬运？
2. **总热度量级**：各平台累计点赞/评论/转发/阅读（汇总而非只看原帖）。
3. **增长速度**：对比不同时间点，是平缓还是陡增？
4. **是否有大V/媒体介入**：放大器是否已出现。

> 📌 全网搜索结果 = 判断"数据高低"和"传播势能"的**事实底数**。不搜就定级 = 拍脑袋。

### 2.2 据全网数据判断等级
调用《态势研判与走势预测模型》：
- **四象限判断**（数据高低 × 影响力高低）→ 决定**处理 / 不处理**（"是否影响公司"是总开关）。
  - 数据高低 = 用 2.1 的**全网汇总数据**对照阈值表（小红书点赞+评论 35 基准），不是只看单帖。
- 若处理 → 量化打分（情绪烈度/传播势能[含跨平台扩散]/发酵概率）+ 紧急度 P0–P3。
- 同时归类：①裁员 / ②工作体验差 / ③面试体验差（②③再分 B/A 类）。

## 步骤 3：沟通还原事实（需处理的才进入；不处理→继续观察）

> **不处理** → 进入步骤 6 的「监控 7 天」观察流程。
> **需处理** → 首先跟**涉事方沟通，还原客观事实**。

### 谁去沟通涉事方？（核心判断：谁合适 / 谁有联系方式 / 谁沟通）

| 涉事方 | 由谁沟通 |
|--------|---------|
| **面试官 / 内部员工** | 招聘经理 或 BP |
| **发帖学生 / 投诉人**（社交平台提供了联系方式） | 雇主品牌团队 |

> **判断原则**：谁沟通合适、谁有联系方式、谁来沟通——不教条，按实际可达性和角色匹配定。

### 还原什么？
- 时间线梳理事情经过（时间/地点/问了什么/怎么答）
- 针对帖子/投诉逐条核实（是否真实发生、前因后果、原话与语境）
- 常见违规预判（面试时长？开摄像头？约的什么时间？何时情绪激动？）
- 详细问题清单见《历史案例话术库》§1.4「投诉调查 SOP」

---

## 步骤 4：确定处理结果 + 拟定沟通话术

### 跟"相关处理方"对接，确定处理结果（按违规类型找对的团队）

| 违规类型 | 对接的相关方 |
|---------|-------------|
| **面试官违规** | 面试官管理团队（依《面试官信用体系》三档定处罚） |
| **内部员工违规** | 员工关系 ER |
| **毁 offer / offer 相关** | 用人团队 / 招聘团队 / BP |

> 处置基调按《雇主品牌三类舆情分型处置SOP》（裁员对冲报备、②③看 B/A 类）。

### 拟定沟通话术（两套：给投诉人/发帖人 + 给违规人）

话术必须包含：
1. **事件还原**（客观经过）
2. **处理结果**（做了什么处理）
3. **处理依据**（依据哪条制度/条例）
4. **QA 兜底**（对方可能追问什么，提前备答）

> 话术结构套公式：表明态度 → 还原客观事实 → 处理依据与结果 → 防范措施。
> 参考《历史案例话术库》面试官较重违纪案/IEG案/小红书SOP的话术分寸。

---

## 步骤 5：沟通确认（文字留痕 + 保密条款）

由相关沟通人分别沟通：
- **跟投诉人 / 发帖人**沟通处理结果
- **跟违规人**沟通处理结果

**如涉事者认可处理结果** → **邮件 / 微信等文字确认**：
- 文字确认内容需 Amy **出具建议话术**。
- ⚠️ 建议话术中**必须包含保密条款**（offer类还需协商一致取消邮件，见《Offer取消沟通指引》五点五模板）。
- 文字确认 = 书面凭证，口头认可不算数。

## 步骤 6：闭环处理 + 监控结案

### 双方确认处理结果后：
- **如是社交平台发帖** → 沟通**删除**该帖，或**更新**为"双方已沟通一致、认可腾讯处理方式"。

> ⚖️ **删帖/打码是分平台的重手段**（详见《分平台删帖与维权处置指南》）：
> - **小红书**：一般不投诉删帖，不严重 → **中好评对冲**为主；严重（造谣不实/实名/已发酵）→ 交**涉事 BG 业务 PR 主办 + 同步 雇主品牌接口人**（BG 搞不定→集团 PR + 雇主品牌接口人 联合），需 Amy 备**不实言论证据 or 律师函初稿**（引用源已删也可作证据）；投诉成功 → **帖子立即删除**。
> - **脉脉**：**打码**(护隐私)=本人投诉即可、**名字变 `***`**(他人协助需律师函)；**删帖**(内容不实/造谣)=**需发律师函投诉 → 先沉底(非搜索不可见) → 48h 后删**(网信办要求，别误判没生效)。**实名曝光一律打码护隐私**——①本人投诉最快→②业务PR→③集团PR+雇主品牌接口人。
> - Amy 负责"判严重 + 备材料（证据/律师函初稿）+ 通知到位"，实际删除/法律动作由涉事 BG 业务 PR 主办（雇主品牌接口人 同步）、必要时集团 PR + 雇主品牌接口人 联合、法务执行。

### 持续监控 7 天（一周）：
- 监控有无新帖、有无二次发酵。
- **7 天内无新帖、无发酵 → 结案**。
- 若期间出现新帖/发酵 → 回到步骤 2 重新识别等级。

> ⭐ **登记台账 + 主动问"要不要建定时监测"**：进入监控期的 case 先登记到 `data/case_ledger.csv`（含监测到期日=发现日+7）。**但台账只是静态记录、不会自动复查**——所以登记后 Amy 必须**主动问经理一句**：要不要建一个定时任务托管自动巡检（按频率自动抓数据→破阈值/发酵则预警→到期无动静自动结案）？经理要 → 用自动化能力建定时任务；不要 → 维持手动、台账留痕。详细话术与判断见 SKILL.md「登记台账后=主动问一句"要不要建定时监测"」。

## ⭐ 处理人链路与升级协同（BG PR 主导 · 雇主品牌接口人 同步 · 集团 PR 联合兜底）

> **重要前提**：Amy 会交付给招聘经理、HRBP 等使用，他们的电脑上**可能没有安装 Bonnie（投放执行）和 Naomi（品牌策略）这两个专家**。因此 Amy 的协同出口**不能默认能直接调用 Bonnie/Naomi**。

### ⭐⭐ 第一道分流：是否已构成舆情（是否已在社交平台公开发帖）

> **决定走哪条链路的总开关**——同一件事（如毁约、面试投诉、纠纷），是否已**在社交平台公开发帖**，处理链路完全不同。

```
事件来了，先判断：是否已在社交平台公开发帖？
   │
   ├─ ❌ 未涉舆情（没公开发帖，只是内部纠纷/潜在风险/候选人私下不满）
   │      → 走【线下沟通链路】，不进社交平台处理步骤
   │      · 与 业务 BP / ER 沟通，确定沟通话术
   │      · 用话术与当事人沟通解决
   │      · 跟 雇主品牌接口人【报备情况】即可（知会，不需启动 PR 删帖维权）
   │
   └─ ✅ 已涉舆情（已在社交平台公开发帖）
          → 进入【社交平台处理步骤】（即下方 BG PR 链路）
          · 先通知 涉事业务 PR 处理 + 同步 雇主品牌接口人
          · 业务 PR 无法处理 → 上升 集团 PR + 雇主品牌接口人 联合
```

| | ❌ 未涉舆情（未公开发帖） | ✅ 已涉舆情（已公开发帖） |
|---|---|---|
| **谁沟通/处理** | **业务 BP / ER** | **涉事业务 PR**（主办） |
| **雇主品牌接口人 角色** | **报备知会即可** | **同步**（知会+口径把关） |
| **升级** | 一般无需升级 PR | 业务 PR 搞不定 → **集团 PR + 雇主品牌接口人 联合** |
| **是否进社交平台处理** | 否（线下解决） | 是（删帖/对冲/官方回应等） |

> 📌 **判断要点**：未公开发帖 = 内部可控的纠纷/潜在风险 → BP/ER 谈话术 + 报备 雇主品牌接口人，把火**消灭在线下**；一旦**已公开发帖** = 真舆情 → 才启动 PR 链路与社交平台处置。**别把没上社交平台的事直接拉 PR 删帖维权（小题大做、反易暴露）；也别把已公开发酵的事只当内部纠纷压着（错失处置窗口）。**

### 谁是主要处理人？（已涉舆情时的核心定位 ⭐）

> 下表适用于**已构成舆情（已公开发帖）**的情况。未涉舆情走上面的 BP/ER 线下链路。

| 角色 | 定位 | 说明 |
|------|------|------|
| 🥇 **各 BG 业务 PR** | **主要处理人** | 舆情/删帖/维权/对外口径的**实际执行主力**——涉事内容属哪个 BG（IEG/WXG/CSIG/TEG…），就由该 BG 的业务 PR 牵头处理 |
| 🔄 **雇主品牌接口人** | **被同步人** | S3-招聘活水部-品牌内容团队（雇主品牌接口人）。雇主品牌侧**知会 + 口径把关**，处理过程中**同步**给她，非事事由她统筹 |
| ⬆️ **集团 PR + 雇主品牌接口人（联合）** | **升级兜底** | 当 BG PR **无法处理**（跨 BG / 影响过大 / 资源不足 / 涉集团层面）→ 上升到**集团 PR 与 雇主品牌接口人 联合处理** |

> 📌 **链路一句话**：先找**涉事 BG 的业务 PR**（主办）→ 同步 **雇主品牌接口人**（知会/把口径）→ BG PR 搞不定 → **集团 PR + 雇主品牌接口人 联合**接手。

### Amy 的协同动作

| 情况 | Amy 的动作 |
|------|-----------|
| **未涉舆情（未公开发帖）** | 与 **业务 BP / ER** 确定沟通话术 → 线下沟通解决 → 跟 **雇主品牌接口人 报备情况**（不启动 PR 链路） |
| **已涉舆情·常规 case（删帖/维权/对外回应）** | 产出判断+方案+材料 → 通知**涉事 BG 业务 PR** 处理，**同步 雇主品牌接口人** 知悉 |
| **已涉舆情·BG PR 无法处理 / 跨 BG / 影响过大** | 升级 → **集团 PR + 雇主品牌接口人 联合处理** |
| **P0 火警**（上热搜/党央媒体/高压线） | 立即同步 **雇主品牌接口人** + 推动 **BG PR/集团 PR** 联动 |
| 需要**渠道侧执行**（对冲/正面铺设/评论维护） | 产出方案 → 同步 **雇主品牌接口人**，由其协调 **Bonnie** 落地（经理本地若无 Bonnie，不直接交接） |
| 涉及**品牌策略层面**（调定位/EVP/传播方向） | 同步 **雇主品牌接口人**，由其协调 **Naomi** |
| ②③ 严重属实需调查 | 移交内审 / ER / 面试官管理团队 + **同步 雇主品牌接口人** 知悉 |

> 📌 **对招聘经理而言**：把 case 交给**涉事业务的 BG PR** 主办，同时把结果**同步给 雇主品牌接口人**；BG PR 处理不了，再由集团 PR + 雇主品牌接口人 联合接手。

## 三个易错点提醒

1. **沟通顺序**：先还原事实（步骤3）→ 再定处理结果（步骤4）→ 最后才对外沟通确认（步骤5）。不可跳过事实还原直接给结论。
2. **文字留痕 + 保密**：认可必须落文字（邮件/微信），且话术含保密条款——口头认可无效，无保密条款=留隐患。
3. **结案要监控满 7 天**：删帖/更新后不等于结束，必须监控一周无发酵才结案。
4. **先分流是否涉舆情**：**未公开发帖 → BP/ER 谈话术线下解决 + 报备 雇主品牌接口人，不启动 PR**；**已公开发帖 → 才走 PR 链路**。别把内部纠纷小题大做拉 PR 删帖，也别把已发酵的当内部纠纷压着。
5. **处理人链路（已涉舆情）**：**涉事 BG 业务 PR 是主要处理人**，雇主品牌接口人 是被同步人；BG PR 搞不定 → 集团 PR + 雇主品牌接口人 联合处理。经理本地可能没有 Bonnie/Naomi，需渠道/品牌协同时由 雇主品牌接口人 协调。
