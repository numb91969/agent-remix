# data/ — Amy 的配置与历史记录目录

> 存放"首次配置"和"跨会话留存的数据"，让 Amy 不必每次重问、且能支撑"监测7天/case入库"。

## 文件清单

| 文件 | 作用 | 谁维护 |
|------|------|--------|
| `config.json` | 首次配置：品牌词/竞品/监测阈值/处理人/审批人/反馈渠道 | 经理首次填一次，之后 Amy 复用 |
| `case_ledger.csv` | case 监测台账：每条进入处理/监测的舆情登记一行 | Amy 处理 case 时追加/更新 |

---

## case_ledger.csv 字段 schema

| 字段 | 含义 | 取值示例 |
|------|------|---------|
| `case_id` | 编号（年份-序号） | 2026-001 |
| `发现日期` | 首次发现 | 2026-06-23 |
| `平台` | 来源平台 | 小红书/脉脉/微博… |
| `事件一句话` | 简述 | 某员工称GM要求加班到3点 |
| `原帖链接` | URL或截图说明 | https://… |
| `舆情类型` | 三类分型 | ①裁员/②工作体验差/③面试体验差 |
| `二级分类` | ②③的B/A类 | 🟢B类一般 / 🔴A1职场PUA… |
| `P级` | 紧急度 | P0/P1/P2/P3 |
| `处理状态` | 当前状态 | 监测中/处理中/已结案/不处理 |
| `负责人` | 主办方 | 涉事BG业务PR/Amy/ER… |
| `首次数据` | 发现时互动量 | 赞30评12 |
| `最新数据` | 最近一次截图数据 | 赞35评15 |
| `监测到期日` | 发现日+7天 | 2026-06-30 |
| `结案日期` | 结案当天 | 留空=未结案 |
| `备注` | 处理动作/进展 | 已打码·监控中 |

## Amy 怎么用

1. **新 case 进来**（判定"处理"或走"监测7天"）→ 在 `case_ledger.csv` 追加一行，算好 `监测到期日`=发现日+`config.json` 里的观察天数（默认7）。
2. **⭐ 登记后主动问"要不要建定时监测"**：台账是静态记录，不会自动复查。凡进入监测/观察期的 case，登记后 Amy 必须主动问经理是否建定时任务托管自动巡检（话术与规则见 SKILL.md「登记台账后=主动问一句」）。要 → 建定时任务；不要 → 维持手动。
3. **每次更新数据**（监测7天期间）→ 更新该行 `最新数据`。
4. **结案** → 填 `结案日期`，`处理状态` 改 `已结案`。
5. **查历史**：经理问"上次那个GM的case后来怎样了" → Amy grep 本 CSV 回溯。
6. **配置复用**：监测/研判/取消offer 前先读 `config.json` 取品牌词、竞品、阈值、接口人，不重复问经理。

> ⚠️ 台账可能含敏感信息（真实姓名/链接），属内部数据，不对外。
