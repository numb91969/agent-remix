# 场景 G：输出列、推送与定时配置

本文档承接原 `offer-field-supplement` 的 `implementation_details.md` §6-§8、`notification_guide.md` 和 `automation_guide.md`，统一融合后的输出列定义、推送配置和错误码。

## 2. 确认页输出后的推送与定时配置

确认页 HTML 输出后，先检测推送与定时配置，再决定是否问询。

### 2.1 配置检测来源

1. webhook：环境变量 `WARMING_SUPPLEMENT_WEBHOOK`，或私有配置文件中的 `webhook`。
2. 私有配置文件路径：优先环境变量 `WARMING_SUPPLEMENT_CONFIG`，否则 `~/.config/warming-recruit-manager/supplement.local.json`。
3. Automation：私有配置文件中的 `automation.id`，且 `automation.enabled=true` 或 `automation.status=ACTIVE`。

### 2.2 分支规则

- webhook 和启用中的 Automation 都存在：不再询问，只提示已沿用现有定时任务和推送配置。
- 只有 webhook：只询问是否创建定时任务，以及执行频率/启停状态。
- 只有启用中的 Automation：只询问是否补充或更新 webhook。
- 两者都没有：展示完整问询文案。

### 2.3 完整问询文案

```text
确认页面已经输出，可进入页面确认细节并填充数据。

是否需要配置定时查询和推送服务？

【这个功能能做什么】
- 按您设置的频率（例如每天 9:30 / 每周一 9:00），由 CodeBuddy Automation 自动跑一次本 Skill 的场景 G；
- 自动按当前登录用户鉴权，查询您名下「待确认入职时间」环节且导师/直接上级/直接上级岗位/入职岗位任一为空的录用单据；
- 自动复查招聘系统详情、按您之前确认的策略生成建议值，并输出一份新的确认页 HTML；
- 跑完后通过您指定的企微群机器人，把待补充单数和确认页链接按固定模板推送到企微群；
- 您不用每天来催，只需要在收到推送后点链接进确认页审阅 → 一键回填。

【推送到企微群的固定文案】
【⏰ 校招录用导师信息收集提醒】

您名下还有 {N} 单待补充，请尽快确认：
• 导师为空：{a} 单
• 直接上级为空：{b} 单
• 直接上级岗位为空：{c} 单
• 入职岗位为空：{d} 单

👉 确认页面：{url}
（点击进入后审阅建议值，确认即自动回填业务系统）

执行时间：{YYYY-MM-DD HH:mm}

【如果需要开启，请提供以下信息】
1. 企微群机器人 webhook（key=xxx 的完整 URL，仅本机保存，不入仓库）
2. 执行频率（例如：工作日每天 09:30 / 每周一 09:00 / 自定义 cron）
3. 执行范围（默认：HR 定薪处理人=您 → 对接招聘经理=您 → 您权限内全部，三层兜底；如需改请说明）
4. 启停状态（立即启用 / 先创建但暂不启用）

如果暂时不需要，回复「不用」即可，本次流程到此结束。
```

### 2.4 企微推送模板

```text
【 ⏰校招录用导师信息收集提醒】

您名下还有 {N} 单待补充，请尽快确认：
• 导师为空：{a} 单
• 直接上级为空：{b} 单
• 直接上级岗位为空：{c} 单
• 入职岗位为空：{d} 单

👉 确认页面：{url}
（点击进入后审阅建议值，确认即自动回填业务系统）

执行时间：{YYYY-MM-DD HH:mm}
```

占位符说明：

- `{N}` = 确认页过滤后待补充单据数。
- `{a}` = 导师详情页原始值为空的单据数。
- `{b}` = 直接上级详情页原始值为空的单据数。
- `{c}` = 直接上级岗位详情页原始值为空的单据数。
- `{d}` = 入职岗位详情页原始值为空的单据数。
- `{url}` = 确认页可访问 URL 或本地 HTML 路径。

## 3. Automation 配置

### 3.1 何时进入

当用户在确认页输出后的问询中选择配置定时查询和推送，或用户主动说「每天」「每周」「定时」「频率我定」「调整定时任务」「改频率」「换 webhook」「暂停推送」「停掉推送」时，进入 Automation 创建或更新流程。

### 3.2 创建或更新规则

1. Automation prompt 只描述任务本身，不写频率信息；频率写入 automation schedule。
2. webhook 只写入私有配置文件或环境变量，不写入 Automation prompt。
3. 创建成功后，把 `automation.id`、`automation.schedule`、`automation.status`、`automation.enabled`、`updated_at` 写入 `supplement.local.json`，便于后续检测已配置并跳过重复问询。
4. 用户只要求暂停时，优先把 Automation 状态更新为 PAUSED，并同步 `supplement.local.json`，不要删除历史配置。

### 3.3 推荐 Automation prompt

```text
使用 warming-recruit-manager Skill 的场景 G 执行校招录用空字段补充流程：先获取当前登录用户并按用户态鉴权查询待确认入职时间环节且四字段任一为空的录用单据；默认范围为 HR 定薪处理人=登录用户、其次对接招聘经理=登录用户、最后当前用户权限内全部；复查招聘系统详情，按确认策略生成建议值，输出单文件确认页 HTML；若已配置企微机器人，则按固定模板推送确认页和待补充统计。
```

### 3.4 RRULE 格式说明

- 每周一 09:00：`FREQ=WEEKLY;BYDAY=MO;BYHOUR=9;BYMINUTE=0`
- 每天 09:30：`FREQ=DAILY;BYHOUR=9;BYMINUTE=30`
- 每小时：`FREQ=HOURLY;INTERVAL=1`
- 每 2 小时：`FREQ=HOURLY;INTERVAL=2`

## 4. 错误码

| 错误码 | 含义 | 处理方式 |
|---|---|---|
| `OFFER_NOT_FOUND` | 录用单不存在 | 标记人工复核 |
| `STEP_NOT_ALLOWED` | 非待确认入职时间环节 | 跳过写入 |
| `PERSON_FACTOR_MISMATCH` | 员工 ID 与英文名不匹配 | 标记人工复核 |
| `POST_ORG_MISMATCH` | 入职岗位不在录用组织树下 | 标记人工复核 |
| `LEADER_POST_MISMATCH` | 直接上级岗位不属于直接上级 | 标记人工复核 |
| `AUTH_DENIED` | 鉴权失败 | 停止批量写入并排查鉴权 |
| `CONFLICT` | 版本冲突/并发更新 | 提示用户重新生成确认页 |
| `UNKNOWN_ERROR` | 未知错误 | 保留 `request_id` 并排查 |
