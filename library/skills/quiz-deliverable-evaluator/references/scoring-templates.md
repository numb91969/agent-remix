# 重评维度模板（路线二 · 目标 B 用）

用户要「按自己的维度重新打分」时，先给下面预设让他**直接选 / 在模板上改 / 完全自定义**。权重总和建议为 1.0。

## 一、预设模板

### 1. 技术能力（技术岗主观题 / 代码题）

| 维度 | 权重 | 看什么 |
|---|---|---|
| 技术方案合理性 | 0.30 | 选型是否恰当、是否解决了真问题 |
| 代码 / 实现质量 | 0.25 | 结构、命名、异常处理、可维护性 |
| 问题分析深度 | 0.20 | 是否触及本质、有无边界与权衡讨论 |
| 表达逻辑性 | 0.15 | 论述是否有条理、结论是否可追溯 |
| 工程素养 | 0.10 | 测试、文档、可复现性、提交规范 |

### 2. 产品思维（产品 / 运营岗主观题）

| 维度 | 权重 | 看什么 |
|---|---|---|
| 需求理解 | 0.30 | 是否抓住真实诉求而非表面要求 |
| 方案完整度 | 0.25 | 关键环节是否闭环、有无明显缺口 |
| 用户视角 | 0.20 | 是否从使用者出发、有无场景意识 |
| 逻辑结构 | 0.15 | 拆解是否清晰、层次是否分明 |
| 创新性 | 0.10 | 有无超出常规的可行想法 |

### 3. AI 协作能力（`aiCoding` AI 实战题）

| 维度 | 权重 | 看什么 |
|---|---|---|
| 意图澄清 | 0.25 | 是否先澄清需求再动手，提问是否有效 |
| 任务拆解 | 0.25 | 是否把大任务拆成可验证的小步 |
| 审辩决策 | 0.25 | 对模型输出是否有判断，是否发现并纠正错误 |
| 交付质量 | 0.25 | 最终产物是否可用、是否达成目标 |

> 与平台内置的 `dimensionScore`（D1 意图澄清 / D2 任务拆解 / D3 审辩决策 / R1 交付质量）同构，便于对照。平台原分只作参照，不作结论。

### 4. 通用表达（开放主观题）

| 维度 | 权重 | 看什么 |
|---|---|---|
| 内容准确性 | 0.30 | 事实与概念是否正确 |
| 逻辑清晰度 | 0.25 | 结构是否顺、因果是否成立 |
| 论证深度 | 0.25 | 有无证据、有无追问一层 |
| 表达规范 | 0.20 | 用词、格式、可读性 |

## 二、评分表生成规则

1. 维度列表头写「维度名(权重)」，如 `技术方案合理性(0.30)`。
2. 维度格 / 本题得分 / 评语**一律留空**，交给用户填。
3. 可加数据校验：维度分限 1-5（或 0-100），本题得分限 0 到 `questionScore`。
4. 表尾留加权汇总公式（Excel 公式，改分自动重算），不要写死数值。
5. 平台原分单列，列名明确写「平台原评分（仅参照）」。

## 三、评分档位参考（可选，用户没要求就别强加）

| 等级 | 分数区间 | 含义 |
|---|---|---|
| A+ | ≥ 95 | 明显超出预期 |
| A | 85-94 | 达成度高，少量瑕疵 |
| B | 75-84 | 基本达成 |
| C | 60-74 | 部分达成，有明显缺口 |
| D | < 60 | 未达成 |

## 四、硬约束

- **客观题默认不重评**：只取平台 `trueAnswer` 呈现对错。用户明确要求才纳入自定义维度。
- **AI 默认只备料、不打分**。用户明确要建议分时才给，且必须标注「AI 建议分，仅供参考」，并说明依据的是哪些作答内容。
- **平台原有主观题 `score` / `remark` 不是结论**——它正是被替换的对象，只能作对照参考单列。
- **作答缺失时不硬凑分**：如实写「无有效作答，建议核实后再定分」，绝不凭题干脑补答案内容。
- 本 skill 全部接口只读，**任何分数都不会写回平台**，落库只能由阅卷官在系统手动完成。
