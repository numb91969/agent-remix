# 交付：麦肯锡风格 PPT 与 Excel

把分析变成**能直接进董事会的成品**——不是"标题 + 一列小字 + 大片留白"的骨架。

## 本 skill 与 tencent-pptx 的分工（先读懂这段，否则会走错路）

**PPT 的渲染不由本 skill 承担。** 2026-08 起废弃自建的 python 渲染栈
（`mck_ppt` / `mckinsey_pptx` / `charts_engine` / `mck_fusion.py` 全部删除），
改由**随包内置的 `tencent-pptx` skill**（`skills/tencent-pptx/`，腾讯文档出品，原样收录）生成。
原因是实测对比下自建引擎明显落后：
同一份新能源行业报告，自建引擎产出的 17 页里**零张图表、零张图形**（纯文本框，matplotlib
缺依赖时静默降级且无人发现），而 tencent-pptx 产出 14 页含 3 个原生 OOXML 图表 + 5 个矢量图形。

分工是这样的：

| 层 | 归谁 | 内容 |
|---|---|---|
| 渲染管线 | `tencent-pptx` | `.slide` 页面 → PPTX 编译、实时预览、语法+溢出校验、导出图片 |
| **设计宪法（命中分支）** | `tencent-pptx` | **`design-principle.mck-consulting.md`**（结构 + 麦肯锡常量已合并；**禁止**再命中通用 `design-principle.consulting.md`） |
| 交付后改稿 | `tencent-local-office-edit` | 已生成的 pptx 原地形状级编辑（纯本地），**交付后不要回头改页面源码**（见 S6） |
| **色板 / 解剖 / 片段核对** | **本 skill** | `mck-palette` / `exhibit-anatomy` / `cover-and-chapter` / `jsx/*`（与 mck-consulting 同口径，写页时对照） |
| **咨询图形** | **本 skill** | 结构图/图表成品片段（`references/jsx/`） |
| **咨询方法论** | **本 skill** | 行动标题、强制图表化、证据分级、署名规定、内容完整性门禁 |

**执行顺序**：调用 `tencent-pptx` 走 `create-from-scratch`；风格**只路由到「麦肯锡咨询」**
（`design-principle.mck-consulting.md`）。不要再「先命中通用 consulting、再用本 skill 覆盖」——
实测那条覆盖链压不住分支常量层（宠物空气净化器 deck：满铺深蓝封面 + 200px 反白章节号）。
缺了本 skill 的片段与门禁，图会空；缺了 tencent-pptx，什么都出不来。

## ⚙️ 动笔前先记住这 26 条机读阈值（S4 门禁逐条会查）

`scripts/gate_check.py` 的判定是**纯机读、逐字比对**的。这些数字必须在**写页面时**就满足，
不是等门禁报错再返工——返工的代价是整页重排。下表前 24 条是 `gate_check.py`（查 pptx）的全部判据，
最后两条由 `scripts/jsx_lint.py`（查 JSX 源码）负责，与代码逐条对齐。

**「标题折行」「口径副行」「零网格线零Y轴」「高亮唯一性」「卡片墙」「中文字体」六条是
"像不像麦肯锡"专项**。上一代门禁只查"有没有图、字够不够大、有没有压字"——色板对、版式对、
数据也对，产出的图仍然是 Office 长相。用户反馈"内容没问题但风格差很多"，差的就是这六条。

**「内容越线」「绘制顺序」「文字压色块」「空图形区」「静默失效属性」五条是复盘三份实测稿补的**，
共同点是**几何全部合法，所以整类漏检**：内容压进页脚但没越画布；色块盖住折线，错的是绘制顺序
不是坐标；文字压在无文字色块上，而「布局重叠」只比两个都带文字的形状；形状数够多但一个图元
都没画；`transform` 写了不报错却不执行，编译出的坐标合法、门禁全绿，图却整张废掉。
**门禁全 PASS 不等于图是对的——这五条就是为了缩小那个差距。**

| 形状越界 | 任何形状越出 1280×720 即 FAIL。**读 pptx 里渲染器写下的真实坐标**，不豁免任何形状 | 这是唯一的真值检查，`slidep-validate` 过了也可能在这里挂（它豁免带填充的形状）。报出来先看是不是 `bottom` 锚定失效 |
| 文字挤出容器 | 文字矩形捅出它所在色块**任一条边 >8px** 即 FAIL（四边都查，`alignItems:'center'` 的横条会上下同时溢出）。读 pptx 真实坐标——文字换行后的行数只有渲染器算得准 | **卡片高度按最长那条文案定，不是按最短那条**：正文 15px×1.5 行高 = 每行 23px，卡内正文预留 3 行 = 69px，加上编号与小标题，目录卡至少 150px 高。文案挤不进就精简或加高卡片，**绝不缩字号**（会撞字号下限） |
| 文字被压窄 | 单行文字的**自然宽度 > 框宽 ×1.06** 即 FAIL。字宽是在渲染器上实测标定的（166 个样本，估算误差 ±1.5%），阈值落在"正常最高 1.005 / 缺陷最低 1.156"的空隙里 | 横条 / 并排标签里 **`flexDirection:'row'` 的子元素默认会被压缩**，压完右缘与容器严丝合缝，几何看不出但行尾已被截掉。要么加宽容器，要么给文字 `flexShrink: 0`（拒绝收缩后会溢出成可见越界，反而查得出来） |
| **内容越线** | 任何形状底边压过 **y=646** 超过 8px 即 FAIL（起点已在 646 以下的页脚元素不计） | 图形区是 166–646，646 以下是 Footnote(662)/Source(682)/页码(682)。**这类缺陷不越画布**，所以「形状越界」和 `slidep-validate` 都放行——排版时按 480px 可用高度算，别靠"没报错"确认安全 |
| **绘制顺序** | 内容区里面积 >15000px² 的纯色块，若压在图片上达其自身面积的 80%，或罩住 ≥4 个更小的图元，即 FAIL | **预测段 `#EFEFF0` 底纹只能写在 `<svg>` 内最底层 `<rect>`**，禁止外层 absolute `<Box background:'#EFEFF0'>`（见已知坑 11、`charts.md` §1）。「写在折线之前」≠ 源码里 Box 排在 svg 前面——slidep 会把 absolute Box **重排到折线图之后**，门禁绘制顺序 FAIL，线被整段盖住 |
| **文字压色块** | 文字与**无文字**色块重叠达文字面积的 30%，且文字未被该色块横向装住，即 FAIL（图片不计——端点直标压在图上是麦式做法） | 横条的类目名放到条**外侧的标签列**，别压在条上。「布局重叠」只比两个都带文字的形状，色块没文字就不参与，所以这半边只有这条查得到 |
| **空图形区** | 被判"有图形"的页，内容区里无文字填充图元的面积占比 <4% 即 WARN（图元 ≥8 个且中位面积 <5000px² 视为手绘图，豁免；目录页豁免） | 揭穿"形状够多所以算有图"：三段式列表、编号清单靠形状数轻松过掉「强制图表化」，读者看到的仍然是文字。报出来就回查数据台账——这页有没有能画成横条/柱/热力矩阵的数据 |
| **下半留白** | 带图形内容页的墨水底边 < **y=560** 即 WARN（可用高 166–646 须撑满约 85%；目录/扉页豁免） | **行/条数少于片段默认时加高行高或条高填满**，禁止照抄矮几何让图贴顶。热力公式见 `charts.md` §3；横条见 §2。别用 `justifyContent:'center'` 把整块矮图垂直居中——麦式是顶对齐拉高图元 |
| **静默失效属性**（`jsx_lint.py`） | 出现 `transform` / `boxShadow` / `filter` / `clipPath` / `textShadow` / `float` / `display:'grid'` / `calc(` 即 FAIL | 这些写了**不报错也不执行**。实测：折线用 `<Box>` + `transform:'rotate()'` 拼斜线段，六段斜线全变成水平横条，整张图废掉而门禁全 PASS。斜线一律用 `<svg>` 的 `<line>`/`<polyline>` 画 |
| 布局坐标（`jsx_lint.py`，4 查） | ①`bottom`/`right` 锚定的**直接父元素在该轴上必须尺寸确定**；②子节点不得超出所在容器；③换算到整页不得越出 1280×720（**不豁免带填充形状**）；④≥50% 连线端点须落在节点框上（±8px） | 柱子用 `top: 容器高 - 柱高`，别用 `bottom:0`；连线用 1px `<Box>` 别用 `<svg><line>`。**这四项 `slidep-validate` 全查不到或会漏**（详见「已知坑」3、4、6） |

两个容易误判的定义，动笔时要知道：

- **"内容页"= 形状数 >10 的页**。封面、章节扉页、结束页形状少，自动豁免脚注与图形要求；
  但如果你把一个真正的内容页做得过于稀疏（≤10 个形状），它会被当成扉页而**逃过检查**——
  这不是好事，说明那页本来就太空了，该按「反骨架化」返工。
- **标题取的是 y=50–175 区间内字号最大且非纯数字的那个形状**。所以 KPI 页的巨型数字不会被误当标题，
  但前提是你把标题块放在规范位置（y=72 起）。标题块位置乱放，这项检查就会取错对象。

## 五阶段流程（S1→S5，禁止跳步）

**S1 需求 + 数据台账** — 给谁看（董事会 / 内部评审）、要几页、核心结论是什么。
然后**先做数据台账，再动骨架**——这一步是"字多图少"的唯一治法：

> 一页之所以退化成文字卡片，几乎从不是因为不想画图，而是**动笔时手上只有话没有数**。
> 到了 S3 才发现没数据，那时只能硬写成三个要点卡片。所以数据必须在骨架之前就清点完。

从备忘录 / 源材料里逐条抽出可视化素材，落成一张表（`DATA.md`，与 `STORY.md`、`DESIGN.md` 同级）：

| # | 支撑哪句行动标题 | 数据形态 | 具体数值 | 单位/口径 | 来源 + 等级 | 建议图型 |
|---|---|---|---|---|---|---|
| 1 | 出口已成第一增长极 | 时间序列 | 2022–2026 六年出口量 | 万辆，海关口径 | 海关总署 `[F]` | 折线 |
| 2 | 第一梯队已拉开身位 | 排名对比 | 前 8 家份额 | %，交强险口径 | 乘联会 `[F]` | 条形 |

**数据形态直接决定图型**，不要到 S3 再纠结选哪种图：

**台账的硬要求**：

- **行数 ≥ 计划的内容页数**。凑不满就说明数据不够撑这个页数，
  **正确反应是回去补数据或压缩页数，不是把缺数据的页写成文字卡片**。
  补数据的第一站是数据层，不是记忆：市场规模/份额/行业趋势走 `neodata-financial-search`
  的文章召回（`data_type=doc`），行业增速用 `westock-data consensus`，
  对手财务用 `westock-data quote/report`，行业前 N 家用 `westock-tool ... --universe`
  （后两个是简写，真实调用是 `node <westock-skill-path>/scripts/data-index.js` / `tool-index.js`）。
  完整入口见 agent 文档的「需求 → 数据源对照表」。
- 每行的"具体数值"必须是**真实数字**，写"待补""约若干"等于这行不存在。
- 最后一类（无量化数据）**可以用结构图充当可视锚点**，但**不许全篇都靠它**——
  结构图只表达逻辑不表达量级，一份全是结构图的 deck 在董事会上仍然是"没给数"。

**S2 骨架（故事线先行）** — 先定故事线再选版式：
- 用 SCQA/RSC 定整体叙事，总分总 + 分章（见 `memo-writing/references/storyline-scqa.md`）；
- 产出**标题故事板**：每页一句**行动标题**（结论式判断句）。抽出所有标题连读能理解完整论证
  （见 `memo-writing/references/action-titles.md`）。通不过"只读标题懂全文"测试就重写骨架，不许进 S3；
- **每一页都要在台账里指到至少一行**。指不到的页当场处理：补数据、并进相邻页、
  或降级成结构图页——**不许留着它到 S3 变成文字卡片**；
- 每页标注版式选型（按下方两张决策表），规划章节扉页与页眉进度标记；
- **编号体系一次定好，三处都要有**（漏编号是实测最常见的结构缺陷，读者会找不到自己在第几章）：
  - **目录页**：每条 = **大编号 + 章节名 + 一句摘要**（3–8 条）。禁圆球编号、禁只有章节名没有编号；
  - **章节扉页**：**白底** + **48–72px** 深蓝编号（`01`/`02`，Arial）+ 章节名 40–48px 楷体；
    **禁止**满铺 Navy / 160–320px 反白巨字（那是 `$TP` 咨询预设，已被覆盖）；
  - **正文页眉**：右上角 14–16px 灰色**章节进度**（如 `02 竞争格局`），让每一页都能自定位。
  
  编号用两位数字（`01`/`02`），全篇同一套，不要中英文混用或跳号。
  封面与章节页骨架见 `design-principle.mck-consulting.md` ①③（或对照 `references/cover-and-chapter.md`）；目录见同文件 ② 节。

**S3 逐页生成** — **三步顺序是硬约束，写第一页之前必须先完成前两步**：

1. `${NODE_BIN_DIR}/slidep-start --project "<项目目录>" --filename "<中文名>.pptx"` —— 建文件并启动实时编译，
   确认返回 `success:true`。若命令不存在（旧版无 hook），先
   `node <plugin-root>/scripts/install-slidep.mjs`（随包 `vendor/tencent-slidep-5.4.4.tar.gz`），再重跑。
2. `present_files("<项目目录>/<中文名>.pptx")` —— **打开侧边栏预览，让用户能边写边看**。
   这一步只写在 tencent-pptx 的 `create-from-scratch.md` Step 5；咨询流程常走 `create-from-material.md`，
   那条路径不提预览，**极易漏掉**。漏了页面照样生成，但用户全程只看到空白面板；
   写完再补调不算完成——实时进度已经没了。
3. 之后逐页写 `slides/NN.slide`（`01.slide`、`02.slide`……），按大纲顺序第 1 页写到第 N 页。
   每页动笔前确认：色值取自 `mck-palette.md`、图形能否直接复制片段库、行动标题是否结论句、
   **口径副行写了、且没写图号**（照 `references/exhibit-anatomy.md` 的 y 坐标表）。

   **第一次画某个图型时**：按 `exemplars/README.md` 打开 `charts.md` / `structures.md` 对应节，
   整段复制；**默认只改数据**。一页多图、条目数与片段默认差很多时，**允许按比例改绘图区宽高 /
   行高 / 间距**（见 `charts.md` 节首「几何怎么调」），改完须守 166–646 与色板，并跑两道校验。
   **不要凭印象从零手画**。**agent 默认不 Read PNG**（成本高且易与模板漂移）；
   PNG 仅人工校对可选。只翻横条/热力两节会把整份 deck 画成同一种图——按数据形态选节。
   **手写坐标的页（结构图 / 矩阵 / 气泡 / 瀑布）写完当页立刻验两道**，不要攒到最后：

   ```bash
   ${NODE_BIN_DIR}/slidep-validate slides/NN.slide --project .   # 语法 + 画布溢出
   python3 scripts/jsx_lint.py slides/NN.slide                   # 连线与节点是否同坐标空间
   python3 scripts/gate_check.py <deck>.pptx --geometry-only     # 真实坐标：越界/挤出卡片/压字
   ```

   第三道是**真值**：`slidep-start` 在跑，每次存盘 pptx 就重编译了，不必等整份写完。
   带底色卡片或横条的页（目录卡、要点卡、章节扉页、结论横条）**必须跑这道**——
   中文换行后占几行、flex 把子元素压窄了多少，只有渲染器算得准。
   前两道结构上都查不到"文案比卡片高度长一行"和"横条里的文字被压窄丢字"，
   而这两样正是目录页与结论横条最常见的翻车方式。
   前两道查的是**不同**的东西，缺一不可，而且**不能只信 validate**：它有两个实测确认的洞——
   带填充色的绝对定位形状被当装饰整体豁免（柱子、色块、卡片底色全中，飞出画布也不报），
   以及它的布局模型与真实渲染器不一致（实测它说无溢出，编译出的 pptx 里 y = −204px）。
   `jsx_lint.py` 补的正是这些：锚定失效、容器内溢出、带填充形状的画布溢出、连线脱节。
   报错会给出方向与 px 数，连线错位还会反推出被多算的偏移量（如 `两者整体相差 (56, 168)`）。
   当页验能立刻定位；攒到最后报出来是一串页号，你还得逐页回溯是哪个偏移写错了。

预览空白或改了不更新 → 先核对 `.pptx` 修改时间是否晚于 `.slide`；不是则实时编译服务已静默死亡，
重跑 `slidep-start`（见下方已知坑 2）。

**S4 三重校验（缺一不可，三道都是机读，不需要渲图看）** —
1. **语法 + 溢出校验**：`slidep-validate` 逐页跑通，`success:false` 必须修到通过。
   它默认带溢出检测（`--no-overflow-check` 才关，**不要关**），把每个形状的包围盒逐个比 1280×720 画布，
   报溢出方向、超出多少 px、以及出问题的源码行，例如
   `❌ 2 overflow(s) [bottom] (canvas height=720) … Bottom+220px`。
   内容撑爆页面底部这类缺陷它比人眼准，**看图反而看不出是 220px 还是 20px**。
   **它的盲区**：只跟画布比，不跟父容器比。文字挤出卡片、中文标签溢出 SVG 圆外，只要没跑出画布它一律放过
   （前者已由门禁的「文字挤出容器」接管，见下文）。
   **它的另两个盲区都是"元素还在画布内但彼此关系错了"**：形状互相压盖（两张卡片完全叠在一起
   它也报 `success:true`，实测），以及结构图连线与节点框整体错位（同样 `success:true`，实测）。
   前者由门禁的「布局重叠」接管，后者由 `jsx_lint.py` 接管（第 3 道）。
   **第三个盲区"文字挤出卡片但没跑出画布"已由门禁的「文字挤出容器」接管**：
   文字换行后的真实高度只有渲染器知道，所以只能在 pptx 层面查——导出的文本形状高度
   就是换行后的实际高度（实测同一段中文 2 行 = 54px、3 行 = 81px），拿它跟卡片矩形一比即可。
   目录卡、要点卡这类"文案比卡片高度长一行"的缺陷，就是靠这条抓住的。
   剩下只有 **SVG 圆内文字外溢**没有机读手段（文字与圆是两个坐标系，无法配对），
   靠 `references/jsx/charts.md` 的半径门槛规避，**手改片段尺寸时格外留神**。
2. **咨询门禁**：`python3 scripts/gate_check.py <deck.pptx> --source <源备忘录.md>`
   查内容完整性（源材料数据点有多少真落到了 deck 上）、色板合规、署名违禁词、证据标签缺失、
   布局重叠、**形状越界**、**文字挤出容器**、**文字被压窄**、**内容越线**、**绘制顺序**、
   **文字压色块**、**空图形区**，以及六条"像不像麦肯锡"专项
   （口径副行 / 零网格线零Y轴 / 高亮唯一性 / 标题折行 / 卡片墙 / 中文字体），共 24 项。
   几何七项读的是 pptx 里渲染器写下的真实坐标，
   **是整条流水线上唯一的真值检查**——`slidep-validate` 和 `jsx_lint.py` 都是模型推算，
   它是实际结果。三者都过才算干净；只有它挂说明前两道的模型漏了什么，值得回头看一眼。
   **几何项可以边写边查**：pptx 每次存盘就重编译，`--geometry-only` 只跑那七项、
   不会被「图形占比不足」这类整份级判据干扰，写完一页就能查一页，比写完十页再回头返工便宜得多。
   门禁脚本只用 Python 标准库，无需装任何依赖。**禁止口头声称"已通过校验"**，必须实际跑、贴结果。
3. **布局坐标校验**：`python3 scripts/jsx_lint.py slides/*.slide`
   直接读页面源码（会展开 `.map`，所以柱状图数组里的坐标也查），报五类：
   `bottom`/`right` 锚定失效、容器内溢出、画布溢出（**不豁免带填充形状**）、连线脱节、
   **静默失效属性**（`transform`/`boxShadow`/`display:'grid'`/`calc()` 等写了不报错也不执行的写法）。
   最后一类只能在 JSX 层拦：编译出来的坐标完全合法，pptx 层已经看不出你原本想画什么了。
   **它是前两道共同的盲区补位**，而且补的是 validate 自己会漏的部分：
   带 `background` 的形状飞出画布 validate 一律不报（实测 320×280px 溢出仍 `success:true`），
   容器内溢出它结构上不查，连线整体偏移时更是没有任何形状越界可查。
   报错会反推出被多算的偏移量（如 `两者整体相差 (56, 168)`），照着减掉即可。同样零依赖。
   已对 45 段官方示例 + 本片段库做误报测试：0 误报。

两道都过之后按下方「页面自检清单」过一遍——清单里的每一条都能从 JSX 源码和上面两份报告里判断，
**不需要导出图片、不需要 `read_image`**（成本高、且检不出比机读更多的东西）。

**S5 交付** — 字体在写页面时就定好了（`mck-palette.md` §4.1），**没有字体后处理这一步**。
给出产出文件路径 + 一句话说明页数与风格要点。落到 `deliverables/consulting/`。

**S6 交付后改稿** — 走 `$ED = ../tencent-local-office-edit`，**不要回头改 JSX**。
JSX 是整份重编译，会静默覆盖用户在编辑器里的手改；跨会话重启 `slidep-start` 还可能把 `.pptx` 重建成空文件。
选路：**改文字 / 数字 / 单个形状的颜色位置 / 关图表网格线 → 走 `$ED`**（形状级原地改，
一次 `slide_set_text` + `save_file` 就完事）；**调版式 / 挪结构 / 换图形类型 / 加减页 → 改 JSX**
（同样的事在形状级要几十次调用还得自己算 pt 坐标）。用 `$ED` 的三条硬规矩：
① 用任何工具前先 `python3 edsdk.py schema <工具名>`，不许凭摘要猜参数；
② deck 已被 `present_files` 打开时**不要再 `open_file`**，改用 `get_pool_status` 按路径匹配拿 `file_id`
（`present_files` 返回的是文件地址，不是 `file_id`）；
③ 保存用 `save_file`，**绝不主动 `close_file`**——会关掉用户正在看的视图。
改完**重跑 `gate_check.py`**：改文案极易把行动标题改到 12 字以下、或把带证据标签的数字改成裸数字。

## 麦肯锡硬纪律（已写入 mck-consulting，写页仍要自检）

风格命中分支是 `design-principle.mck-consulting.md`（**不是**通用 consulting）。下列四条已在分支常量层落地，
但写页/改稿时仍按本 skill 自检——片段库与门禁也按此执行：

1. **色板**。只用 `mck-palette.md` / mck-consulting §3 的 19 值白名单。
   禁止通用咨询的 `#061F32` / `#001965` / `#08A6F6`。

   ⚠️ **2026-08 起本条的内容整个换过，上一版是错的。** 上一版说"麦肯锡只有深蓝 + 主蓝两色，
   Cyan 在麦肯锡体系里不存在"——那是照搬 mckinsey.com 品牌网站色推导的，**与真实刊物不符**。
   对季刊 2021+ 语料 647 张图逐张抽色的结果是：亮青 `#00A9F4` 出现在 **174 张**图里，
   是仅次于深蓝的第二主色；而上一版那串主蓝淡色梯度（`#6485FF`/`#9CB1FF`/`#C8D4FF`/`#DEE5FF`）
   出现 **0 次**。改版依据与完整新色板见 `mck-palette.md` §0。

2. **图表配色必须显式传参**。原生 `<Chart>` 不传 `colors` 会掉回 Office 默认蓝橙（`#4472C4`/`#ED7D31`），
   一眼就不是麦肯锡。每个 `<Chart>` 都必须带 `colors` + `showDataLabels` + `axisColor`，
   写法见 `references/jsx/charts.md` §7。

3. **一页只高亮一个**。每张图只有一个系列用深蓝 `#051C2C` 或亮青 `#00A9F4`，
   其余弱化为浅青 `#AAE6F0` 或中灰 `#CED0D1`。彩虹配色是"AI 感"的第一破绽，
   而满页都是深色是第二破绽——**门禁的「高亮唯一性」两个都查**。

4. **零网格线、零 Y 轴、端点直标**。它的结构层管不到单张图表的内部长相，
   所以图表照样会带 Office 默认的网格线与坐标轴。这一层由 `references/exhibit-anatomy.md` 覆盖，
   门禁的「零网格线零Y轴」逐份扫 `ppt/charts/*.xml` 兜底。
   **这是"内容对、色板对，但看着仍不像麦肯锡"最直接的成因。**

## 强制图表化（针对"14 页仅 2 页有图"的历史事故，最高优先）

凡涉及**数值、占比、排名、趋势、时间序列、多维评估、两维定位、增减分解**的内容，
**必须**用图表或结构图承载，**禁止**退回纯文字卡片去讲本该图表化的数据。
一份数据型分析（竞争格局 / 市场研究 / 尽调）里，**带真实图形的页应占内容页一半以上**。

若你发现自己在用三栏卡片堆数字，停下，改成图表。
**数字少的观点页也要视觉化**——按下方「逻辑结构 → 版式」表找图形，不是纯 bullet。

**红线**：找不到真实数据支撑的图表，宁可换对比表格或文字，**绝不编造数据凑图**。

## 反"AI 感"具体特征（可数的破绽，逐条排查）

## tencent-pptx 的已知坑（实测踩过，务必预防）

0. **`slidep-start` / `slidep-validate` 命令不存在（旧版环境）**。
   新版 WorkBuddy 会用内置 `tencent-pptx` 的 hook 把引擎装进 `${NODE_BIN_DIR}`；
   旧版没有该 hook、或托管 Node 里没有 slidep 时，会报 `command not found`。
   **不要改 `skills/tencent-pptx/` 原文**——本 expert 已在插件根随包钉死同版本 tarball：
   `vendor/tencent-slidep-5.4.4.tar.gz`（说明见 `vendor/README.md`）。
   失败时先装再跑：

   ```bash
   node <plugin-root>/scripts/install-slidep.mjs
   # 或手动：
   npm install -g --prefix="$(dirname "$NODE_BIN_DIR")" --no-audit --no-fund \
     <plugin-root>/vendor/tencent-slidep-5.4.4.tar.gz
   ```

   装好后仍用 `${NODE_BIN_DIR}/slidep-start` / `slidep-validate`。
   这只补齐本机 CLI；远端编译后端不可用时仍出不了 PPT（见下一条）。

1. **`openFile network error: TypeError: fetch failed` —— 先探端口，别急着判死刑**。
   编译后端**在本机**：WorkBuddy 自带的 `editor_sdk`（`@tencent/tencent-docs-ai-engine`），
   走 `http://127.0.0.1:<port>/mcp`，**不走公网**。地址只由一个环境变量决定，
   读不到就退回写死的 `39099`：

   ```js
   // @tencent/slidep/dist
   e7 = () => (cI ? cI.split("/mcp")[0] : "http://localhost:39099")   // cI = process.env.TENCENT_DOCS_LOCAL_MCP
   ```

   新版 WorkBuddy 会把真实端口注入这个变量，所以正常无感。**旧版不注入**，
   而端口是动态分配的（2026-08 实测本机是 **39100**），于是退回 39099 → 没人监听 → fetch failed。

   **旧版兜底：探到端口，导出变量，重跑。**

   ```bash
   PORT=$(LC_ALL=C lsof -nP -iTCP -sTCP:LISTEN 2>/dev/null \
     | LC_ALL=C awk '/^editor_sd/{n=split($9,a,":");print a[n]}' | sort -u | head -1)
   export TENCENT_DOCS_LOCAL_MCP="http://127.0.0.1:${PORT}/mcp"
   ${NODE_BIN_DIR}/slidep-start --project "$(pwd)" --filename "<中文名>.pptx"   # → success:true
   ```

   `lsof` 把命令名截断成 **`editor_sd`**（9 字符），按 `editor_sdk` 匹配一个都匹配不到。

   **`PORT` 探空 = 本机没有这个引擎**（更旧的 WorkBuddy 不带 docs 引擎）：**降级用 `python-pptx`
   直接出 pptx**，仍守本包风格——白底、左对齐、
   `mck-palette.md` 色板、行动标题写结论、每页带口径副行与资料来源、署名只写丁笃行；
   **这条路的门禁按 WARN 看即可**（手绘图元画不出来，形状数与图表化比例达不到属正常），
   别为了过门禁放弃交付，更别去手补 OOXML。
2. **守护进程会静默死亡**。它死后你改 JSX 不再重新编译，而预览面板与导图仍照旧成功——
   于是你在看一份**旧稿**却以为改好了。**交付前先核对 pptx 的修改时间是否晚于 JSX**，
   不一致就重启 `slidep-start`。
3. **`slidep-validate` 的溢出检查有两个实测确认的大洞，"它过了"不等于没溢出**。

   **洞一：带填充的绝对定位形状被当作装饰整体豁免。** 源码 `isDecorative()` 对
   `position:'absolute'` 且有 `background` 的形状直接返回 true，该形状不参与画布比对。
   实测：400×400 的填充色块跑出画布 320×280px，返回 `success:true`；
   同样几何把 `background` 换成 `border` 就正常报错。
   **手绘柱状图的柱子、色块、卡片底色全都符合豁免特征**——它们飞出画布不会有任何提示。

   **洞二：它的布局模型与真实渲染器不一致。** 实测同一份 JSX，validate 说无溢出，
   编译出的 pptx 里形状 y 坐标是 **−204px**。

   加上它**结构上不查容器内溢出**（只跟 1280×720 画布比），手绘图表/结构图的错位
   基本全靠 `scripts/jsx_lint.py` 兜。**这两个脚本都必须跑，不能只跑 validate。**

4. **绝对定位的基准是「直接父元素」，不是 CSS 的"最近已定位祖先"**（Yoga 语义，实测四组用例确认）。
   父元素有没有 `position` 完全无关：静态父级被 `marginTop:100` 推下去，
   它里面 `top:0` 的绝对定位子节点也落在 100px 处。

   **由此引出最致命的一个坑：`bottom`/`right` 会静默失效，锚到起始边而不是末端。**

   规则很简单：**`bottom`/`right` 要求直接父元素在该轴上尺寸确定**；不确定时该轴按 0 算，
   元素被锚到容器的**起始边**并朝画布外生长，而且**不报任何错**。实测九组：

   | 直接父元素 | `bottom:0` 的结果 |
   |---|---|
   | `height: 400` 显式数值 | ✅ 正常锚在底部 |
   | `height: '100%'` 百分比 | ✅ 正常 |
   | 静态（未定位）但有 `height: 200` | ✅ 正常 |
   | Slide 本身 | ✅ 正常 |
   | **只有 `width`、没写 `height`** | ❌ 锚到顶部，元素朝上长 |
   | **`.map` 里的无样式 `<Box key={i}>`** | ❌ 锚到顶部（实测柱状图上翻 204px） |

   **为什么只有纵向翻、横向没事**：默认 `flexDirection:'column'` + `alignItems:'stretch'`，
   无样式包装层**横向被拉满到父宽**（所以 `right` 侥幸正常，实测确认），
   纵向却因为唯一子元素是绝对定位的而撑不出高度。于是同一批元素里 `top` 定位的正常、
   `bottom` 定位的飞出去，错位看起来毫无规律、极难定位。

   **默认就别用 `bottom`/`right`**：一律写 `top: 容器高 - 元素高`、`left: 容器宽 - 元素宽` 正向定位。
   要用的话先确认直接父元素在该轴上有确定尺寸——`key` 不要多包一层，容器该写的 `height` 别省。
   `jsx_lint.py` 会逐条查这个条件（与上表九组实测逐一对齐）。

5. **横条里的并排文字会被 flex 静默压窄，行尾直接丢字**（实测，`gate_check` 已接管）。

   `flexDirection:'row'` 的子元素**默认允许收缩**（`flexShrink` 隐含为 1）。一行里放
   「粗体标签 + 说明文字」，两段加起来超过容器内容宽时，渲染器不会溢出、不会换行，
   而是**把两段按比例一起压窄到刚好塞进容器**。实测 460px 宽的横条里，
   自然宽 110px 与 381px 的两段被压成 94px 与 338px（94+338+8 = 432 = 容器内容宽，严丝合缝）。

   **为什么三道校验全看不出来**：压完右缘正好贴着容器边，没有任何越界；
   导出的 pptx 里 `wrap="none"`（本该按内容自适应宽度），于是 PowerPoint 直接把行尾画到框外或截掉——
   实测丢掉了行尾的 `[A]`。JSX 静态分析也无从判断，因为 JSX 里根本没写宽度。

   **横向排不下有四种表现，只有第三种要靠比字宽**（四种都实测编译验证过）：
   ① 文字是色块的**兄弟**、不写 width → 文本形状右缘直接越出色块（「文字挤出容器」抓，实测超 43px）；
   ② 写了 width 排不下 → 换行变高、下缘捅出色块（同上，实测超 10px）；
   ③ 文字是色块的**子元素**且同排有**多个**子元素 → 被一起压窄，几何全正常
      （「文字被压窄」抓，判据是标定过的字宽 vs 框宽）；
   ④ 文字是色块的**唯一**子元素 → 渲染器改为换行并把文本形状**撑高**，
      配上 `alignItems:'center'` 就变成**上下同时**捅出横条（实测 44px 高的横条里文字长到 87px，
      上下各露 21px）。所以「文字挤出容器」四条边都要查，且配对容器要按**中心点**而不是左上角——
      按左上角配对时文字左上角已跑到容器上方，一个容器都找不到，直接漏检。

   **写横条时的规矩**：并排文字一律加 `flexShrink: 0`。加了之后排不下会变成**可见的越界**，
   反而被前两道抓住；不加就是静默丢字。横条宽度按最长那句估——实测字宽：
   中文与全角标点 1.0em、`→ ① — …` 也是 1.0em、大写字母 0.70em、数字 0.558em、
   小写字母 0.442em、`%` 0.896em、空格 0.29em。18px 字号下 24 个中文就要 432px。

6. **手画结构图的两种坐标翻法，第二种机读全盲**。

   **翻法 A（元素掉出画布）**：子节点坐标被容器偏移二次叠加。
   **翻法 B（元素留在画布内但整体错位）**：把外层容器改成 `top:0,left:0` 来"修好" A，
   于是节点框按整页坐标落对了位置，但**内嵌 `<svg>` 也跟着回到页面原点**，
   连线整体往左上移了一个原容器偏移量——连线接不上任何节点，图明显歪掉。
   `gate_check` 的重叠项也管不到（它只比带文字的形状，连线没有文字）。
   **必须跑 `scripts/jsx_lint.py`**，它会报「连线脱节」并反推出被多算的偏移量。
   修 B 的正确做法不是把容器挪到原点，而是**保留容器 + 把节点框改成局部坐标**（下面这条）。

   `position:'absolute'` 的 `left/top` 相对**直接父元素**而非整页，所以带偏移的容器里
   **必须用局部坐标**（`0…width`/`0…height`）。写成 `top: 196 + p.y` 而容器 `top` 已是 188，
   就是把偏移加了两遍，底部节点掉出画布（实测 `Bottom+32px`）。
   同一容器里混用 `<svg>` 和 `<Box>` 时尤其危险：SVG 的 `x1/y1/cx/cy` 由 `viewBox` 决定，
   **永远是局部坐标**，`<Box>` 若写整页坐标，连线端点与节点框会整整错开一个容器偏移量。
   照抄 `references/jsx/*.md` 的骨架就不会错；完整正误对照见 `structures.md` 开头的「坐标系铁律」。
   **能避开整类问题的写法**：连线优先用 1–2px 的 `<Box>` 细条（片段库就是这么画的），
   它和节点框同处一个坐标空间，**根本不可能失步**；只有需要斜线时才用 `<svg>`，
   此时务必让 svg 与容器**等尺寸、零偏移**。
   **这类页写完当页跑两道校验**（`slidep-validate` + `scripts/jsx_lint.py`），见 S3。
7. **原生 `<Chart>` 关不掉网格线和 y 轴**，属性表里只有 `axisColor`。
   交付前用 `$ED` 的 `slide_update_chart_gridlines`（`visible=false`）关掉 Y 轴主网格线、
   `slide_update_chart_axis` 调坐标轴。柱/条/折线/面积/散点适用，
   **饼图和环图不支持**（会报错让你先转图表类型）。

   **但 2026-08 起这条不再是"用原生也没关系"的理由**：占语料一半的折线与占 6% 的横条，
   麦式做法要求无轴、无网格、端点直标、灰 track——前三条要靠交付前那一步补救、
   灰 track 原生根本做不出。所以**折线与横条一律走 `charts.md` §1/§2 的手绘片段**，
   只有堆叠柱和环图还值得走原生。门禁的「零网格线零Y轴」会扫 `ppt/charts/*.xml`，
   忘了关就是 FAIL——这一步以前全靠自觉，实测就是最常漏的一环。
8. **交付后改稿链路割裂**。它规定成稿后的修改必须走 `tencent-local-office-edit`（已随包内置，见 S6 选路），
   禁止回到 JSX 改。所以**版式类决定第一版就要定对**——版式返工只能在 JSX 侧做，而那条路交付后已关闭。
   注意这条坑与坑 1 的关系：`$ED` 是**纯本地**服务，所以腾讯后端故障时新 deck 出不来，
   但**已生成的 deck 仍然改得动**。
9. **JSX 不是 React**。禁 `import`/`export`/hooks/函数组件定义，禁 `display: grid`，
   禁 CSS `calc()`，换行只能用 `<br />`，文件最后一个表达式必须是 `<Slide>`。
10. **`present_files` 极易漏调，导致用户看不到实时预览**。它只写在 `create-from-scratch.md` 的 Step 5，
   而咨询流程常从 `create-from-material.md` 进入，那条路径不提这一步。必须在写第一页**之前**调用（见 S3）。
11. **折线「预测区间」底纹用外层 `<Box>` 会被盖住整条线**（2026-08 OpenEvidence 第 8/11 页实测）。

   错法（源码看起来「底纹在折线前」，编译后反过来）：

   ```jsx
   <Box style={{ position: 'absolute', left: 424, top: 0, width: 336, height: 340, background: '#EFEFF0' }} />
   <svg>…<polyline/>…</svg>
   ```

   slidep 把 absolute 填充 Box 画成独立形状，**z-order 排在 `<svg>` 转成的 `<p:pic>` 之后**，
   预测段折线/圆点整段被 `#EFEFF0` 盖住，只剩线端悬空标签；`gate_check`「绘制顺序」FAIL。

   正解（底纹与折线同一张图，SVG 文档序即绘制序）：

   ```jsx
   <svg width={760} height={376} viewBox='0 0 760 376'>
       <rect x='424' y='0' width='336' height='340' fill='#EFEFF0' />  {/* 必须最先 */}
       <polyline … /><circle … />
   </svg>
   {/* 「预测区间」标签放基线上方空隙，约 top:318，勿压折线 */}
   ```

   `jsx_lint.py` 会对「同页有 `<svg>` + absolute `#EFEFF0` 大色块」直接 FAIL。照抄 `charts.md` §1。
12. **矮图贴顶、下半空白过大**（热力/横条行数少于片段默认时最常见）。

   片段按 8 行/8 条写死行高 42/34。N=4 仍照抄 → 图只占内容区上半，y=450 以下全白。
   **正解**：按 `charts.md` §2/§3 公式加高 `rowH`（热力 42–72，横条条高 26–48），
   使墨水底边 ≥ y=560。禁止用 `justifyContent:'center'` 把矮块垂直居中。
   `gate_check`「下半留白」WARN。
