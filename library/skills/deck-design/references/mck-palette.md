# 麦肯锡色板与字号：唯一真相源

本文件是本 skill 全部视觉常量的**唯一真相源**。任何页面（JSX、图表、SVG）取色只许从这里取，
不许自创色相，不许从别处复制 hex。

## 0. 这张表是怎么来的（2026-08 改版，与上一版不兼容）

上一版用的是 **mckinsey.com 品牌网站色**（深蓝 `#051C2C` + 主蓝 `#2251FF` + 一串推导出来的
主蓝淡色梯度 `#6485FF`/`#9CB1FF`/`#C8D4FF`/`#DEE5FF`）。问题是：**品牌网站色 ≠ 图表色**。
麦肯锡的 exhibit 用的是另一套青蓝体系，那串淡蓝梯度在真实刊物里**一次都没有出现过**。

本版改为实测色。做法是对《麦肯锡中国季刊 / CEO 特刊》2021 年后 12 本刊、**647 张图表**
逐张抽取矩形填充色并按"出现在多少张图"排序（语料与抽取脚本见 `mck-reference/`）。
下表每一色都标了它的实测出现频次——**没有出处的颜色不进这张表**。

三条被实测推翻的旧结论，记下来别再犯：

1. **"Cyan 在麦肯锡体系里不存在"是错的。** 亮青 `#00A9F4` 出现在 **174 张**图里，
   是仅次于深蓝的第二主色。GenAI 特刊的条形图与热力矩阵通篇都是深蓝配亮青。
2. **主蓝淡色梯度是虚构的。** `#6485FF`/`#9CB1FF`/`#C8D4FF`/`#DEE5FF`/`#F2F5FF` 五色
   在 647 张图里出现 0 次。真实的弱化色是浅青 `#AAE6F0`（53 张）。
3. **现代刊没有暖色。** 按色相统计，2021+ 语料里红/橙出现 **0 次**，
   唯一的非蓝色是只出现在 3–4 张图里的薄荷青 `#75EFE7`（未收录）。
   方法论文档里提到的"偶用橙 `#E36C0A`"来自 2015–2020 旧刊，**已不适用**。

## 2. 一页只高亮一个（麦肯锡图表的核心手法）

这条比色值本身更重要。每张图**只有一个**系列/一根柱/一个气泡用深蓝或亮青，
其余一律弱化为 `#AAE6F0` 或中性灰。做不到"一眼看出该看哪"的图就是失败的图。

- 强调 = `#051C2C`（深蓝，最重）或 `#00A9F4`（亮青，需要跳出来时）
- 弱化 = `#AAE6F0`（浅青，主力）或 `#CED0D1`（中灰）
- **负向/减项没有专用色**：用深色档（`#061F79`）配位置与标注表达，见 §2.1

### 2.1 没有暖色了，负向怎么表达

旧版靠 `#D46A00` 标减项、风险、里程碑。实测语料里没有这个用法，改用麦肯锡自己的三种手法：

| 场景 | 旧做法 | 新做法 |
|---|---|---|
| 瀑布减项 | 橙色柱 | 深靛 `#061F79` 柱 + 柱顶 `−18` 负号 + 柱在基线上方浮空的位置本身已表意 |
| 热力/风险强度 | 红橙色阶 | 单色阶浅→深表强弱（`#99E6FF` → `#AAE6F0` → `#00A9F4` → `#027AB1` → `#051C2C`），配右上角"低—高"图例 |
| 里程碑/卡点 | 橙色菱形 | 深蓝 `#051C2C` 菱形 + 文字标注；卡点环节用白底 + 主蓝边反色突出 |

**色阶方向是有约定的：深 = 强/多/差，浅 = 弱/少/好。** 全篇必须一致，不能这页深表示好、那页深表示坏。

## 3. 条形图的灰 track（麦肯锡辨识度最高的单一特征）

原刊的横条图，**每根蓝条底下都压着一根满宽的 `#E6E6E6` 灰条**，表示 100% 基准。
读者一眼能看出"这一项占了整体的多少"，而不需要去看坐标轴——这也正是它敢完全去掉 X 轴的前提。

```jsx
{/* 一行 = 灰 track 打底 + 蓝条叠在上面 + 条端直标数值 */}
<Box style={{ position: 'relative', width: 520, height: 26 }}>
    <Box style={{ position: 'absolute', left: 0, top: 0, width: 520, height: 26, background: '#E6E6E6' }} />
    <Box style={{ position: 'absolute', left: 0, top: 0, width: 291, height: 26, background: '#051C2C' }} />
    <Box style={{ position: 'absolute', left: 299, top: 3 }}>
        <Text style={{ fontSize: 18, color: '#191919' }}>56</Text>
    </Box>
</Box>
```

条宽换算：`蓝条 width = 数值 / 满刻度 × track 宽`。满刻度取"比最大值略大的整数"，
全组共用同一个满刻度，否则条长之间不可比。完整片段见 `jsx/charts.md` §2。

## 4. 字号阶梯

沿用 `design-principle.mck-consulting.md` 的阶梯，**正文硬下限 22px 不得突破**。
唯一例外：结构图与图表内部的节点说明、数据标签允许 15–18px（它的 ⑨ 节自己给了这个豁免）。

| 层级 | px | 字重 | 用途 |
|---|---|---|---|
| 章节编号 | 48–72 | Bold | 仅章节扉页；Arial；**白底深蓝字**，不是 160–320 反白巨字 |
| 封面主标 | 60–72 | Bold | 封面；楷体；**白底深蓝字** |
| KPI 大数 | 60–120 | Bold | 数据页锚点数字 |
| Action Title | 32–40 | Bold | 每页标题块，固定 36 |
| **口径副行** | **18–20** | **Regular** | **紧随标题下一行，灰色。见 `exhibit-anatomy.md`** |
| 副标 / 卡片小标 | 24–30 | Bold | 次级标题、结论句 |
| 正文 | 22–28 | Regular | 段落，**硬下限 22** |
| 结构图节点标题 | 21–24 | Bold | 仅结构图内 |
| 结构图说明 / 数据标签 | 15–18 | Regular | 仅结构图内、图表标签 |
| Source / Footnote / 页码 | 14 | Regular | 页脚 |

单页字号种类 ≤5；相邻层级差 ≥6px。

## 4.1 字体：中文楷体 + 西文 Arial，按 `<Text>` 分配

**写页面时逐个 `<Text>` 指定 `fontFamily`，不做任何后处理**：

| 这个 `<Text>` 装的是 | `fontFamily` |
|---|---|
| 含中文（标题、口径副行、行标签、说明句、Source/Footnote） | `'楷体'` |
| 纯西文或纯数字（数据标签、KPI 巨字、年份轴、页码 `03 / 07`、英文术语块） | `'Arial'` |

字体名用中文「楷体」而不是 `KaiTi`：Windows 上解析到 SimKai、macOS 上解析到 STKaiti，两边都认。

### 语料实测（4 份近刊、约 10 万字符）

| | 承担者 | 占比 |
|---|---|---|
| **中文** | STKaitiSC-Regular（正文 12pt）、KaiTi（图表标签与脚注 7–9pt）、STKaitiSC-Black（标题） | **99.9%** |
| **西文与数字** | McKinsey Sans（品牌字体）、Arial | **99.8%** |

黑体 / 雅黑 / McKinsey Sans 承担的中文是 **0 字**；楷体承担的西文只有 45 字（0.2%）。
**图表标签、热力矩阵格内小字同样是楷体**，全刊统一，没有例外。

### 为什么是按 `<Text>` 分，而不是靠字体栈回退

渲染器的 run 属性生成器只做一件事：取 `fontFamily` 的**第一个值**，同时写进
`<a:latin>` 和 `<a:ea>`。所以**一个 `<Text>` 只可能有一种字体**，字体栈的后续项在导出时被丢弃：

- `fontFamily: 'Arial, 楷体'` → 两者都是 Arial。浏览器预览里中文会回退到楷体、导出却不会，
  **预览与产物不一致**，正是这个不一致让人觉得割裂；
- `fontFamily: '楷体, Arial'` → 两者都是楷体，**西文不回退**（楷体自带完整
  A–Z / a–z / 0–9 / % / $ 字形），满页数字变书法体，正好和麦肯锡相反。

把语言拆到不同 `<Text>` 就绕开了这个限制：每个 `<Text>` 自己就是一种语言，
一种字体够用。**预览用的就是同一个 `fontFamily`，所见即所得**。

顺带修掉一个隐患：早先的做法是先按无衬线写完、过完几何门禁，交付前再换字体——
换字体会改变中文的换行位置，等于门禁验的是换字体**之前**的排版。现在字体在写的时候就定了，
`文字挤出容器`、`文字被压窄` 这些量出来的就是最终结果。

### 同一行里中英混排怎么办

一个 `<Text>` 里写 `GenAI 应用`，整块会走该 `<Text>` 的字体，做不到原刊那样逐字符切换。
多数情况不用管：麦式 exhibit 的数字本来就是独立元素（数据标签、轴标签、KPI 巨字），
天然可以单独给 `'Arial'`；正文句子里嵌的三两个英文词走楷体，视觉上无损。

只有**单行标题**里必须中西分体时，才拆成相邻的两个 `<Text>` 放进
`flexDirection: 'row'` 的容器——代价是这一行失去自动换行，所以别用在会折行的段落上。

### 两条使用限制

- **深底反白的中文照样用楷体，但必须 `fontWeight: 'bold'`**。楷体笔画细，白字压在
  `#051C2C` 上不加粗会发虚。原刊的解法不是换字体而是换字重——标题用的是
  STKaitiSC-Black 这一档，语料里 99.9% 的中文（含所有反白文字）都还是楷体。
  别为了反白再引入第三个字体家族，全篇只有楷体 + Arial 两套。
- 禁书法体西文、艺术字、emoji。楷体只给中文，西文永远是 Arial。

## 6. 改色规则

要调色只改本文件，然后全库 grep 替换。**片段库里的 hex 必须与本表逐字一致**——
出现本表以外的 hex 即为缺陷，`../scripts/gate_check.py` 会扫出来。
新增颜色前先回到 `mck-reference/mckinsey-charts-restoration/data/*.json` 确认它在语料里真实出现过，
**不要凭配色直觉推导中间色**——上一版那五个淡蓝就是这么来的。
