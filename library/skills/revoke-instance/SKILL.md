# revoke-instance

## 这个技能做什么

将一个进行中的流程单撤回。这是**写操作**，执行后流程单状态变为"已撤回"，不可恢复。

## 唯一可用工具

`RevokeWorkflowInstance`

## 约束

- **InstanceId 是必填参数**（T 开头）。如果用户没给，请求用户提供。
- **执行前必须向用户确认**。
- **只调用 1 次**。成功即完成，失败按下面两种场景分别处理。
- 只有流程单的发起人才能撤回自己的单据。
- 只有状态为 Running（进行中）的流程单才能撤回。

## 执行流程

1. 确认 InstanceId（T 开头）
2. **向用户确认**：撤回后不可恢复，确认要撤回吗？
3. 用户确认后，调用 RevokeWorkflowInstance → `{ Id: "{InstanceId}" }`
4. 根据返回结果判断场景 → 展示对应结果

## 两种撤单结果

### 场景 A：直接撤单成功

返回成功，没有生成审批单时：

```markdown
✅ 流程单 {InstanceId} 已成功撤回。

> 撤回后流程单状态变为"已撤回"，不可恢复。
```

### 场景 B：撤单需要审批（生成撤单审批单）

调用后返回了新的审批单 ID（如 `RevokeApprovalInstanceId` 或响应中包含另一个 T 开头 ID），说明该流程配置了撤单审批机制，不是直接撤回，而是生成了一条撤单审批流程单：

```markdown
⚠️ 这个流程与上一个不同 — 撤单需要审批：

| 项目 | 内容 |
|------|------|
| 流程单 {原InstanceId} | 状态仍为 🔄 进行中 |
| 撤单审批单 | {审批单InstanceId} 已生成 |

该流程配置了撤单审批机制，不是直接撤回，而是生成了一条撤单审批流程单。需要等待审批人批准后，原流程单才会被撤回。

你可以在这里查看撤单审批进度：https://huijin.woa.com/flow/apply/detail/{审批单InstanceId}
```

### 调用失败

```markdown
❌ 撤回失败：{错误原因}

可能的原因：
- 您不是该流程单的发起人
- 流程单状态不是"进行中"（已结束/已驳回/已撤回的不能再撤）
- 流程单 ID 不正确
```

## 输出末尾

```markdown
> 以上操作均通过流程平台（https://huijin.woa.com/flow/apply/detail/{InstanceId}）
```
