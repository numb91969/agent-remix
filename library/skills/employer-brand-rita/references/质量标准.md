# 质量标准

## P0 铁律：数据-问题匹配性校验（分析前必做，无例外）

> **任何分析输出前，必须先完成以下校验。未通过校验的分析不允许呈现给用户。**
> 
> 这是调研专家的基本专业素养。面对招聘经理/HRBP 等专业用户，数据逻辑不自洽会严重损害专业可信度。

### 强制校验清单

1. **构念匹配（Construct Validity）**：当前使用的数据指标，是否真正测量了用户提问的构念？
   - "投递意向" ≠ "技术影响力"（前者是综合吸引力，后者特指技术维度认知）
   - "全体学生BG偏好" ≠ "技术人才对BG的技术认可度"
   - 如果手上数据只能作为间接代理指标（proxy），必须**主动声明**"这不是直接测量，只是参考指标"，并说明差距在哪里

2. **人群匹配（Sample Validity）**：分析的人群是否与问题指向的人群一致？
   - 分析"技术影响力" → 必须先筛选技术背景/技术岗位意向人群
   - 分析"校招候选人感知" → 必须排除已入职员工样本
   - 若筛选后样本量过小（<50），必须声明"样本量不足，结论仅供参考"

3. **口径一致性（Metric Consistency）**：跨年/跨BG对比时，数据口径是否一致？
   - 各年问卷的选项措辞、题目位置、样本构成是否可比
   - 若口径有差异，必须在结论中声明局限性

4. **因果归因谨慎性**：相关性 ≠ 因果关系
   - "宣讲后意向下降" ≠ "宣讲效果差"（可能是信息更新后的理性决策）
   - 所有归因表述必须用"可能""或许""一种解释是"等限定词

### 校验不通过时的处理

- 不能用错误数据硬做分析后再加一句"不完全准确"
- 正确做法：**先向用户说明当前数据的局限，给出最接近的替代分析方案**，并建议需要补充什么数据才能精准回答
- 示例："您问的是CDG的'技术影响力'，但现有数据只有'各BG投递意向'（综合吸引力），不等于技术维度认知。我可以筛选技术人群后做近似分析，但建议后续通过专项问卷直接测量。"

## 问卷设计 Checklist

- [ ] 每道题只问一件事（无双桶问题）
- [ ] 选项MECE（互斥穷尽）
- [ ] 总题量≤20题（招聘团队用户注意力有限）
- [ ] 5分钟内可完成（高频问卷）或12分钟内（深度问卷）
- [ ] 分析框架→题目映射完整
- [ ] 有注意力检测设计
- [ ] **开放题具体化原则**：所有开放性问题必须足够具体，让回答可直接编码分析。禁止"你还有什么想说的"类笼统提问。正确做法：限定格式（给3个关键词）、限定维度（印象最深的一件事）、限定场景（一句话描述你的感受）。
  - "你对XX还有什么想说的？" → "说起XX，请给出你第一时间想到的3个关键词"
  - "如果用一句话向朋友推荐/吐槽XX，你会说什么？"
  - "今天让你印象最深的1个信息点/环节是什么？"
- [ ] **题间逻辑一致性**：前后题之间的选项必须逻辑自洽，不允许出现矛盾组合。设计时必须：
  - 逐题检查：当前题的每个选项是否与前置题/后续题的选项存在矛盾
  - 设置跳转逻辑：前置题答案决定后续题的可见/不可见
  - 选项动态适配：根据前置回答自动过滤不合理选项
  - 输出时标注逻辑关系表
  - 常见矛盾对举例：
    - 身份=在职 vs 求职状态=准备明年校招
    - 身份=在校本科生 vs 经验=5年以上
    - 已入职=是 vs 求职意愿=正在积极找工作
    - 渠道=实习亲身体验 vs 身份=从未在该公司实习过

## 报告输出 Checklist

- [ ] 核心数据准确（可回溯原始数据）
- [ ] 图表降序排列
- [ ] 样本量标注统一（"样本量=N"）
- [ ] 每条洞察有数据支撑
- [ ] 行动建议具体可执行（指向具体负责人/动作）
- [ ] Word报告字体统一微软雅黑
- [ ] **数据来源标注规范（必须遵循）**：每份报告必须按以下三段式结构标注数据方法与来源：
  1. **前置「数据来源与方法论说明」**（报告正文前、目录后）：4-6 个 bullet，简要说明本报告使用了哪些数据平台/工具、分析方法、数据时间范围、以及局限性声明
  2. **正文**：纯数据表格 + 结论分析，不在每段/每表旁逐条标注来源
  3. **附录「数据来源清单」**（报告末尾）：编号列表，汇总所有数据源名称、关键字段映射、数据采集时间
