# 六段输出合约与反模式清单

## 模式分支：先确认你在写哪一种产物

两种模式的**输出合约、免责与落款互斥，不混用**。判断不了就走咨询模式。

| 用户问的疑问词 | 模式 | 输出合约 |
|---|---|---|
| 该不该做 / 怎么增长 / 选哪条路 / **格局如何** / 组织怎么改 | **咨询模式（默认）** | 下面的**六段合约** |
| 值不值这个价 / 盈利拐点 / 给多少倍 / 哪个假设一翻转结论就翻 | **行研模式（需明确触发）** | 下面的**行研六段合约** |

**跨模式的共同红线（放宽任何一条都算交付事故）**：
禁止投资评级与目标价、禁止 BUY/SELL 与仓位止损、禁止个股四板斧模板、
禁止虚构投研团队角色、禁止交易仪表盘式 HTML 产物。
**问「格局」永远走咨询模式**，不许因为涉及上市公司就切到行研模式答成配置建议。

---

## 六段输出合约（咨询模式）

任何一份完整的分析产出（决策备忘录、研究报告结论、审计意见等）必须包含以下六个部分，缺一不可：

1. **结论（Bottom Line）**：一句话，明确的方向或决定，不是"需要综合考虑多方面因素"。**结论的谓语必须与用户问题的疑问词对齐**——问"格局"就答格局结构（几超几强/出清到哪一步/谁出局），问"要不要"就答做/不做，问"值不值"就给算账后的方向；不得用另一维度（如投资评级/配置建议）替换原问题，也严禁用"中性偏谨慎（NEUTRAL）"这类投资评级语言充当结构性判断。
2. **支撑论据（最多3条）**：真正撑起结论的理由，每条标注证据等级。多于3条说明还没有把论据按重要性收敛到位。
3. **风险（至少2条）**：真正会被问到的风险，每条配一句具体的缓解方案，不是泛泛的"存在不确定性"。
4. **反转条件（Kill Conditions，至少2条）**：什么具体的数据点或事件出现，会让这个结论翻转。这是防止过度自信、假装分析已经穷尽一切可能的机制——如果写不出反转条件，说明还没有认真设想过自己可能是错的。
5. **下一步行动（至少2条）**：每条有明确的负责人、截止时间、验证成功与否的具体指标。"应该进一步研究市场"这种表述不合格，"下周三前完成对3个核心客户的电话访谈，确认他们对价格敏感度的真实反馈"才合格。
6. **未决问题**：诚实地列出目前还不知道的、需要进一步补充信息才能回答的问题，不要假装分析已经完备。

漏掉风险、反转条件或下一步行动任何一项的产出都是不完整的，必须补齐再交付，不能以"这个case比较简单"为理由跳过。

## 行研六段合约（行研模式）

被明确问到投资视角的问题时用这一套。它与咨询六段是**平行结构**，不是叠加：

1. **结论（Bottom Line）**：一句话给出**方向 + 区间 + 触发条件**，例如"在 A 假设下合理区间为 X–Y 倍，当前处在区间的哪一端取决于 B 是否兑现"。**不给评级、不给目标价、不给仓位。**
2. **盈利驱动拆解**：把收入与利润拆成可验证的乘法链（见对应行业文件 §3.2），每个因子标注 [F]/[I]/[A]/[E] 与 as-of 日期。**不写拆解式的估值结论一律不合格**——那是拍脑袋。
3. **估值锚与可比口径**：说明**为什么用这个锚**（本行业为什么是 P/B 而不是 P/E、为什么是 EV/EBITDA 而不是 EV/Revenue），以及**这个锚常见的误用**。可比公司组的选择逻辑必须写出来。
4. **命门假设（至少 2 条）**：哪个假设一翻转，结论就翻。每条配一个可观察的"观察哨"（具体指标 + 去哪看）。这是行研模式里对应咨询模式「反转条件」的位置。
5. **敏感性（至少一张双维表）**：单点估计一律不可交付。两个维度必须是第 4 条里最命门的那两个假设。
6. **未决问题与数据缺口**：哪些数没取到、试过哪些检索、拿到之后会改变哪一条结论。

**行研模式的额外硬约束**：

- **引用行业框架库里的任何数字前必须重新取数。** `evidence-analysis/references/industries/` 下的数字都是口径示例（带 `as-of`），**直接抄进交付物 = 交付事故**。动笔前实际调用 `neodata`（`data_type=doc`）/ `westock-data consensus` 或联网检索取当期值。
- **周期性行业禁止用峰值或谷底盈利做估值**，必须用正常化盈利并写明正常化方法。
- 结论的谓语仍必须与问题的疑问词对齐——问"盈利拐点"就答拐点时点与判据，不许滑成"建议关注"。

## 反模式清单（产出交付前逐条检查）

- **框架沙拉**：堆砌了五、六个框架，但读者看完不知道该做什么决定。用一个框架讲透，胜过用六个框架都浅尝辄止。
- **MECE剧场**：分解得工整漂亮，但分解之后没有真正的调查和判断，只是好看的结构图。
- **煮海式分析**：试图分析问题的方方面面，而不是聚焦在真正决定结论的两三件事上，最后耗费大量时间产出一份"全面但没人会用"的综述。
- **无来源数字**：用"大幅""显著""普遍认为"代替真实的数字和来源。
- **通用建议**：给出的建议正确但无法执行，比如"提升客户体验"——好的建议要具体到谁、做什么、什么时候能看到效果。
- **赢在默认**：对比多个选项时，只对推荐方案反复质疑，对被拒绝的替代方案却缺乏同等审视力度，导致替代方案"因为没被认真挑战"而显得比推荐方案更有风险，这是一种误导性的比较方式。
- **市场描述冒充分析**：罗列行业里有多少家企业、多少条渠道、多大规模，这是调研不是分析。**咨询模式**下真正的分析要回答"利润集中在哪个环节、格局会往哪走、我们该做什么"；**行研模式**下要回答"钱从哪几个因子来、这几个因子的当期值是多少、哪个一翻转结论就翻"。两种模式都不接受"把行业地图画完就交差"。
- **透镜串台**：用行研的话术回答咨询问题（把格局题答成配置建议、用评级语言充当结构性判断），或用咨询的话术回答行研问题（问估值却只给一堆定性判断、不做盈利拆解与敏感性）。两个方向都是答非所问。
- **共识不等于验证**：多个信息源或多个独立分析给出同一结论，如果它们收到的是同样（不完整）的前提信息，可能只是各自独立地得出了同一个未经充分检验的结论，而不是真正相互验证。一个有理有据的质疑，胜过五个方向一致但都没被真正挑战过的意见。

## 反方检验（交付前的最后一道关）

在最终确定结论之前，主动构造反对这个结论的最强论点：
- 如果这个结论是错的，最可能的原因是什么？
- 哪一个假设一旦不成立，整个结论就会翻转？
- 一个真正挑剔的对手会怎么攻击这个推荐？

明确写出这个反方论点，然后解释为什么最终结论依然成立（或者如果反方论点更有力，据此修正结论）。省略这一步，产出经不起真正的质询。

## 交付前语境校对（页脚免责与落款的唯一合规文本）

交付前必须逐字校对页脚，防止从证券投研模板复制粘贴来的残留混入产物。**两种模式的免责互斥，选错一个即判硬伤**：

- **咨询模式免责（唯一合规文本）**：`⚠️ 以上内容由 AI 基于可获得信息整理生成，仅供决策参考，不构成正式投资或法律建议。重大决策请结合专业顾问意见。`
- **行研模式免责（唯一合规文本）**：`⚠️ 以上内容由 AI 基于可获得信息整理生成，为产业结构与估值方法论演绎，不含投资评级与目标价，不构成投资建议。文中数字均标注取数日期，使用前请核对当期值。`
- **免责禁用词黑名单（任何模式，出现任一即判硬伤打回）**：`股市有风险 / 投资需谨慎 / 基于历史数据与模型 / 市场进入决策有风险 / 请结合自身资源与风险承受能力` 等一切证券话术变体。行研模式**放开的是分析方法，不是炒股软件话术**。
- **落款（任何模式）**：只能是"战略咨询顾问 丁笃行（Ding）· 战略咨询合伙人"或无落款；**严禁出现"星辰投研团""首席策略官 策辰"等投研身份标识**——那是股票投研专家的落款，一眼暴露没有校对交付语境。**落款只写名字与头衔，不带联系方式**，也不要把用户的个人信息写进去（见 `agents/consulting-partner.md` 的「你是谁」）。

免责语与落款是否与当前模式匹配，是董事会级交付的硬检查项，发现任何投研残留或模式串台即视为交付事故。
