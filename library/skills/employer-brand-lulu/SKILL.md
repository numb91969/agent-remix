## 触发词

审核、帮我审一下、review、检查合规、审核JD、审核PPT、审核海报、审核文案、审核课题、招聘文案审核

## 概述

对腾讯招聘相关物料进行标准化审核，覆盖五大场景，输出分级审核报告 + 修改建议。

这是**总入口 skill**：
- 默认先跑：通用合规层 + 对应场景专项层
- 若识别为：推文、公众号文章、转发语、长文案
- 则追加：`copy-review` 的三视角深审模块（PR合规 / 品牌调性 / 目标候选人）

`copy-review` **保留独立 skill**，适合只做文案深审时单独调用；本 skill 则负责统一入口与全场景审核。

## Layer 0：首次使用说明

**仅在用户首次触发时输出**（同一会话中不重复）：

```markdown
## 招聘文案审核

你可以把要审核的内容直接发给我，我会先判断它属于哪一类，再按对应规则给出审核结论。

### 我能审核什么？

| 场景 | 你可以怎么给我 | 我会重点看什么 |
|------|---------------|----------------|
| JD | 文本、表格、截图、文件 | 合规风险、错别字、语句是否清楚 |
| PPT / HTML 宣讲材料 | 文件、截图、提取文本 | 六不要红线、对外口径、基础文字问题 |
| 青云课题 | 文本、表格、截图 | 课题名称、描述、招聘要求是否符合标准 |
| 海报 | 截图、图片、文案 | 文案合规、基础视觉问题、信息是否完整 |
| 招聘运营文案 | 短信、邮件、系统通知、转发语、公众号文章 | 基础文字、信息准确性、必要时追加文案深审 |

### 我怎么工作？

- 你**直接发内容**：我自动识别场景并开始审核
- 你**只说“帮我审一下”**：我会先让你选场景
- 你**已经说明场景**（如“帮我审这个JD”）：我就按该场景直接审核

### 我会怎么输出？

我会统一按三类反馈：
- 🔴 必须修改：合规红线或明显错误
- 🟡 建议修改：表述、结构或质量问题
- 💡 信息提示：需要你再确认的数据、时间、部门名称等

### 补充说明

如果内容属于**推文、公众号文章、转发语、长文案**，我会在基础审核之外，再补一层“文案深审”，从：
- PR合规
- 品牌调性
- 目标候选人感受

三个角度再看一遍。
```

## Layer 1：入口识别（方案C）

### 交互模式

| 情况 | 行为 |
|------|------|
| 用户直接给了内容（文本/文件/截图） | 自动识别场景，直接审核 |
| 用户说"审核"但没给内容 | 弹出场景选择选项 |
| 用户明确说了场景（如"审这个JD"） | 跳过识别，直接按指定场景审核 |

### 场景识别规则

| 线索 | 判断为 |
|------|--------|
| .pptx文件 / PPT截图 / 宣讲材料 / HTML页面 | PPT/HTML审核 |
| 岗位描述/职责/任职要求/JD | JD审核 |
| 课题名称+描述+招聘要求三段式 | 青云课题审核 |
| 海报截图 / 明显的视觉物料 | 海报审核 |
| 短信/邮件/通知/系统消息/邀请面试 | 招聘运营文案审核 |
| 推文 / 公众号文章 / 转发语 / 长文案 | 招聘运营文案审核（追加文案深审模块） |
| 在线文档链接（`docs.qq.com` / `doc.weixin.qq.com`） | 先读取正文再审核：`docs.qq.com` 优先用 tencent-docs；`doc.weixin.qq.com` 优先用 wecom-doc（Cookie 失效时引导用户刷新后重试） |

#### 🎮 IEG 特化审核（叠加层，非独立场景）

内容命中以下任一 → 在上表判定的场景基础上**追加** IEG 特化审核模块，读取 `references/ieg-review-rules.md` 执行：

- 内容含 **IEG / 游鹅选鹅 / 腾讯游戏 / 游戏工作室**
- 用户明确说 **"IEG" / "进校" / "空宣" / "直播"**
- 场景为**宣讲会 PPT / 直播口播稿**

IEG 红线（叠加在通用红线之上，完整版见该 reference）：

| # | 规则 |
|---|---|
| IR1 | 保密产品必须逐一确认对外授权 |
| IR2 | 竞品公司名零容忍 |
| IR3 | 不对竞品直接评价或对比 |
| IR4 | 不针对具体竞品游戏做玩法/运营拆解 |

> 进校宣讲额外加审：产品名/截图/Logo 逐项确认授权、嘉宾不含未公开项目、互动 QA 不含薪酬/加班/竞品。
> 空宣直播额外加审：主播口播稿逐句过审、弹幕管理预案、屏幕共享不含保密、直播背景不含未公开海报。

### 场景类型确认

审核报告开头标注识别结果：`审核场景：XX | 适用范围：校招/社招/青云`

如果识别不确定，优先审核，在报告开头注明"识别为XX场景，如有误请指正"。

## Layer 2：通用审核层（所有场景必跑）

### 🔴 必须修改（红线）

| # | 维度 | 规则 | 说明 |
|---|------|------|------|
| R1 | 友商提及 | 零容忍（但区分场景） | 线下闭门交流：仅提示；对外公开材料：必须修改 |
| R2 | 涉政话题 | 不讨论政治敏感话题 | 不提及政务人员/岗位 |
| R3 | 领土表述 | 地点以城市为单位 | 必须"中国香港/澳门/台湾"；不说"国内外" |
| R4 | 公司敏感信息 | 不暴露保密项目、面试录取评价、薪酬/年终/职级 | 即使闭门场景，薪酬信息也建议删除（截图传播风险） |
| R5 | 承诺性表述 | 不私自承诺留用/录取/薪酬/资源 | "有竞争力薪酬""保证转正"等均不可 |
| R6 | 负面网络梗 | 不用"资本家""网络必胜客"等 | 不提友商负面事件、不拉踩 |
| R7 | 院校歧视 | 禁止985/211/双一流/C9等限制词 | 仅保留专业和能力要求 |
| R8 | 军事化词汇 | 严禁战友/部队/战场/战位/打仗/硝烟/特种部队 | 替换为：同学/同行者/主场/领域/精锐团队 |
| R9 | 组织阵型暴露 | 不暴露具体团队人数/汇报关系/组织层级 | "200人团队""3个中心12个组"不可出现 |

### 🟡 建议修改

| # | 维度 | 规则 |
|---|------|------|
| S1 | 绝对化用语 | "最""第一""唯一""领先""SOTA"等需数据支撑；闭门场景仅提示 |
| S2 | 自贬表述 | "追赶""落后""二线"不可出现 |
| S3 | 宏大叙事/套话/过度网感 | "赋能""打造""生态""双向赋能""指数级跃升"及"BUFF""外挂""最IN""赛博管家""次元壁"等对外易显轻佻或歧义的表达，建议换成具体、稳健、可理解的描述 |
| S4 | 错别字/漏字/语句错误 | 基础文字质量 |
| S5 | 标点/格式不规范 | 中英文标点混用、编号格式不统一 |
| S6 | 术语拼写 | 参考 @references/terminology.yaml |

### 💡 信息提示

| # | 维度 | 规则 |
|---|------|------|
| I1 | 数据无来源 | 所有数字标【待确认数据来源】，把关权交给人 |
| I2 | 部门名称 | 提示核对join.qq.com官网对外部门名称 |
| I3 | 时间信息 | 提示核对当前招聘节点 |
| I4 | 岗位名称 | 提示核对官网岗位名是否一致 |

### 场景合规尺度

**重要**：不同活动类型的合规尺度不同。

| 场景 | 友商模型名 | 绝对化表述 | 薪酬信息 |
|------|-----------|-----------|---------|
| 线下闭门技术交流（青云沙龙等） | 💡 仅提示 | 💡 仅提示 | 🔴 仍需删除 |
| 对外公开宣讲（进校/线上） | 🔴 必须修改 | 🟡 建议修改 | 🔴 必须修改 |
| 对外推文/招聘物料 | 🔴 必须修改 | 🔴 必须修改 | 🔴 必须修改 |

## Layer 3：专项审核层

### PPT/HTML审核

**额外检查项**：

| 维度 | 规则 |
|------|------|
| 嘉宾称呼 | 保留英文名/中文名/昵称即可，不用企微全名（含工号/部门前缀） |
| 嘉宾title | 确认使用的是对外部门名称，非内部组织架构名 |
| 个人邮箱 | 确认嘉宾本人同意公开；有外传风险建议改为团队公邮/二维码 |
| 资源规模 | "万卡算力"等信息确认是否可对外披露 |
| 信息完整性 | 检查是否有投递方式(join.qq.com)、BG归属、嘉宾介绍 |
| AI生成痕迹 | 如发现大量套话/排比/军事化修辞模式，提醒可能为AI生成，建议精简 |
| 标准页 | 校招组维护的标准页（BG介绍/热招岗位）跳过不审 |
| 模板结构 | 不审模板结构（每场学校情况不同） |

**高频问题模式（实战积累）**：
1. 招聘页（最后一页）是问题集中区：薪酬承诺、内部部门名、个人邮箱、资源规模
2. 技术嘉宾容易把内部实验benchmark数据直接放进材料
3. AI生成内容导致军事化修辞+套话堆砌
4. 缺少基础信息（投递方式/BG归属/嘉宾介绍）

### JD审核

**额外检查项**：

| 维度 | 级别 | 规则 |
|------|------|------|
| 门槛歧视 | 🔴 必须修改 | 985/211/双一流/年龄/性别限制 |
| 不合理高门槛 | 🔴 必须修改 | 实习生要求≥3篇顶会一作/≥2年工作经验 |
| 实习时间要求 | 🔴 必须修改 | "实习≥X月""每周≥X天"不宜出现 |
| 业务合法性/知识产权边界 | 🔴 必须修改/升级确认 | 如职责涉及破解、解密、绕过保护、提取第三方闭源资产、逆向商业游戏资源等高风险描述，需法务/安全确认；JD不应直接写成可能被解读为规避技术保护或侵权的表述 |
| 职责清晰度 | 🟡 建议修改 | 空泛描述读完不知道具体做什么 |
| 格式规范 | 🟡 建议修改 | 编号一致性、条目数量合理（3-5条） |

**校招 vs 社招区分**：
- 实习时间要求、高门槛规则仅适用于校招/实习JD
- 社招JD的经验年限要求合理

### 青云课题审核

**复用现有qingyun-review的11维度标准**，详见 @references/qingyun_rules.md

### 海报审核

**额外检查项**：

| 维度 | 规则 |
|------|------|
| 文案合规 | 通用层规则全部适用 |
| 基础视觉 | 文字对齐、颜色主题一致性（仅基础层，不涉及品牌感/审美） |
| 信息时效 | 日期/时间/链接是否过期 |

### 招聘运营文案审核

**额外检查项**：

| 维度 | 级别 | 规则 |
|------|------|------|
| 错别字/漏字 | 🔴 必须修改 | 短信发几千人，错一个字影响面大 |
| 链接正确性 | 🔴 必须修改 | join.qq.com等链接需完整正确 |
| 岗位名称一致性 | 🟡 建议修改 | 与官网一致 |
| 拼写（AI/Al混淆） | 🔴 必须修改 | 大写I和小写L的混淆是高频问题 |
| 承诺性表述 | 🟡 建议修改 | 运营文案中合规敏感度略低于PPT |

**追加规则**：
- 如识别为推文、公众号文章、转发语、长文案，不止做基础审核，还要追加“文案深审模块”。
- 文案深审模块沿用 `copy-review` 的三视角方法：PR合规、品牌调性、目标候选人。
- 输出时保留统一分级结构，同时可补一段“三视角补充判断”。

### 文案深审模块（融入 copy-review 方法）

**适用对象**：推文、公众号文章、转发语、长文案、需要考虑传播表达的招聘内容

| 视角 | 关注什么 | 处理方式 |
|------|---------|---------|
| PR合规 | 绝对化用语、未发布宣称、友商提及、组织阵型暴露、数据准确性 | 发现硬伤即标红或待确认 |
| 品牌调性 | 套话官话、宏大叙事、风格偏移、拼接感、句式质感 | 输出建议修改 |
| 目标候选人 | 成长机会、真实影响力、人才密度、日常体验、为什么值得投 | 判断吸引力是否成立 |

**模块边界**：
- 本 skill 中，这一模块作为“追加深审”出现，不替代通用审核。
- `copy-review` 仍保留独立 skill，适合只做内容深审时单独使用。

## Layer 4：输出格式

### 报告结构

审核完成后输出可视化看板（show_widget）+ 文字详情：

**看板信息卡**：
- 必须修改 X处（红色）
- 建议修改 X处（黄色）
- 信息提示 X处（蓝色）

**详情按级别分组输出**：

每条问题包含：**位置 + 问题 + 修改建议**

如无任何问题：输出"✅ 审核通过，未发现合规风险或质量问题。"

### 整体评价（可选）

在报告末尾，如有值得肯定的地方或整体性建议，简要附上。

## 行为准则

1. **不编造信息**：无法判断的标"信息不足，无法判断"
2. **不猜测**：不确定的事实标【待确认】
3. **区分场景尺度**：闭门 vs 对外，合规标准不同
4. **数据把关权交给人**：只提示"需确认来源"，不替人判断真假
5. **修改建议忠于原意**：不优化原文、不加戏、不改技术含义
6. **先结论后展开**：报告开头给汇总数字，详情在后面
7. **高频问题主动预警**：看到典型模式（如AI生成痕迹、招聘页集中问题）主动提醒

## Pitfalls

- 当 JD 涉及逆向、解密、抓包、提取第三方资产、破解商业软件/游戏资源时，不能只做普通招聘文案审核，必须额外判断**业务合法性、知识产权边界、是否可能被理解为规避技术保护措施**。
- 如确属合法授权、兼容性研究、安全研究或内部资产治理场景，JD 也应补足授权/合规前提，避免直接出现“key 提取”“包体解密”“资产提取”这类高风险表述。
